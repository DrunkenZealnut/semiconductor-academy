## 1. 제어 시스템의 뼈대 — PC와 PLC가 나눠 맡는 일

반도체 장비의 제어 시스템은 상위의 중앙 공급 제어기에서 모듈별 제어기(PMC·TMC)로 내려가는 분산 제어 구조로 설계돼요. 앞 단원에서 본 CTC·TMC·PMC 구조가 여기서 통신 영역별로 다시 나타나요.

| 영역 | 중심 | 통신 방식 | 역할 |
|---|---|---|---|
| CTC 영역 | 상위 허브 | TCP/IP | PMC·TMC를 통합 연결, 상위 호스트와 SECS/GEM 통신 인터페이스 담당 |
| TMC 영역 | 이송 모듈 PLC | TCP/IP + RS-232/485(N-포트) + EtherCAT | 이송 관련 장치 제어 |
| PMC 영역 | 공정 모듈 PLC | RS-232/485(N-포트) + 디바이스넷/이더캣 | 공정 관련 장치 제어 |

CTC가 허브 역할을 하며 전체를 통합 감시하고, TMC·PMC는 각자 자기 구역의 장치를 실시간 네트워크로 붙들고 있는 구조예요.

## 2. PLC 하드웨어 설계 스펙 — 무엇으로 고를까

분산 제어를 어디서 할지에 따라 독립형 PLC를 쓸지 확장형 PLC를 쓸지 정해요. PLC는 디지털 입출력 모듈, 아날로그 입출력 모듈, 통신 모듈(RS-232·RS-485·이더캣·디바이스넷 등), 열전대 모듈 같은 기능 모듈을 조합해 구성돼요.

PLC를 고르는 기준은 네 가지예요 — 처리 능력(CPU 연산 속도·메모리 용량), I/O 확장성, 통신 인터페이스, 환경 사양. 복잡한 제어 알고리즘과 실시간 처리가 필요한 반도체 장비일수록 고성능 CPU가 필요해요.

| 통신 방식 | 특징 | 주로 쓰는 곳 |
|---|---|---|
| RS-232 | 단일 장비 간 근거리 직렬 통신 | 진공 게이지, 온도 컨트롤러 |
| RS-485 | 다중 장치 연결, 최대 1.2km 장거리 전송 | MFC(질량유량제어기) 등 |
| 이더캣(EtherCAT) | 이더넷 기반, 마이크로초(μs) 단위 초고속 실시간 | 정밀 모션·서보 제어, 로봇 구동 |
| 프로피버스(PROFIBUS) | 지멘스가 개발한 산업용 필드버스 | 센서·밸브·인버터와 PLC 간 실시간 통신 |

## 3. I/O 설계 — 현장의 아날로그를 디지털로

I/O(입력/출력)는 세 갈래로 나뉘어요.

- <strong>디지털 입출력</strong>: 입력은 센서 신호·스위치 상태·밸브 위치 피드백(24VDC 신호가 기본), 출력은 솔레노이드 밸브·릴레이·표시등 제어예요.
- <strong>아날로그 입출력</strong>: 입력은 온도·압력·유량·농도 센서 신호(4~20mA, 0~10V 표준), 출력은 밸브 개도·모터 속도·히터 출력 제어예요.
- <strong>특수 기능 모듈</strong>: 온도 제어, 모션 제어, 통신, 카운터 모듈이 있어요.

현장의 물리량은 전부 이 세 갈래를 거쳐야 비로소 제어 시스템이 읽고 쓸 수 있는 신호가 돼요.

## 4. HMI 설계 스펙 — 화면에 무엇을 담을까

<Callout type="info" title="조작법이 아니라 설계 스펙">
  아래 내용은 "버튼을 이렇게 누르세요"가 아니라, 설계자가 "화면 크기를 몇 인치로 하고, 비상 정지 버튼을 얼마나 크고 눈에 띄게 만들지"를 정하는 설계 기준이에요. 장비마다 실제 화면 구성은 제조사·모델에 따라 달라요.
</Callout>

터치 패널을 고를 때는 화면 크기·해상도·밝기·내환경성을 함께 따져요. 반도체 장비는 대체로 15~21인치 화면을 쓰고, 표시 정보의 선명도를 위해 풀 고화질(Full HD) 이상 해상도를 권장해요.

화면 밖의 물리적 조작 요소도 설계 대상이에요.

| 요소 | 설계 기준 |
|---|---|
| 비상 정지 버튼 | 크고 붉은색으로 제작 — 긴급 상황에서 누구나 즉시 찾아 누를 수 있도록 |
| 키 스위치 | 아무나 조작하지 못하도록 권한을 나누는 용도 |
| 표시등 | 녹색=정상 운전, 황색=경고, 적색=알람, 청색=수동 모드로 색상을 고정 |
| 경보 표시 장치(시각) | 타워 라이트, 3단 또는 5단 구조 |
| 경보 표시 장치(청각) | 버저·혼, 경보 수준별로 음색과 패턴을 다르게 |

색상과 크기, 위치를 이렇게 미리 정해 두는 이유는 하나예요 — 작업자가 생각하지 않고도 즉시 알아볼 수 있게 만들기 위해서예요.

## 5. 통신 네트워크와 SECS/GEM — 장비 안팎을 잇는 표준

장비 내부 제어 장치들과 외부 시스템을 잇는 통신은 여러 산업용 표준 프로토콜을 함께 써요.

| 네트워크 | 특징 |
|---|---|
| 이더넷(EtherNet) | TCP/IP 기반, 100Mbps~1Gbps |
| 이더캣(EtherCAT) | 고성능 실시간, 모션 제어·고속 I/O·정밀 동기화 |
| 디바이스넷(DeviceNet) | 필드버스, 트렁크-드롭 구조로 센서·액추에이터를 저비용 분산 제어 |
| 프로피버스(PROFIBUS) | 유럽 표준 필드버스, RS-485 기반 또는 광케이블 기반 |

장비와 상위 호스트 시스템(MES 등) 사이의 통신은 이 네트워크들과는 결이 다른 표준인 <strong>SECS/GEM</strong>이 맡아요. 반도체 장비와 상위 시스템 간 통신을 표준화해서 장비 자동화와 스마트 제조 환경을 만드는 핵심 기반 기술이에요.

| 표준 | 정의하는 것 |
|---|---|
| SEMI E4(SECS-I) | 장비-호스트 간 물리적 통신 방식 (RS-232C 기반 직렬 통신) |
| SEMI E5(SECS-II) | 메시지의 구조와 데이터 형식, 장비 상태 보고·공정 데이터 전송·명령 전달 규칙 |
| SEMI E37(HSMS) | TCP/IP 기반 이더넷으로 SECS-II 메시지를 고속 전송하는 방식 |

이 세 표준이 합쳐져 장비 상태·공정 데이터·알람을 실시간으로 상위 시스템에 전달하는 통신 체계를 이뤄요. 이런 통신·진단 소프트웨어를 실제로 개발하는 직무는 <SourceRef source="ncs-semi" section="equipment-utility-software" label="NCS · 반도체 장비 유틸리티 소프트웨어 개발" />에서 볼 수 있어요.

## 6. 소프트웨어 아키텍처 — 클라이언트-서버로 설계하기

<SourceRef source="ncs-semi" section="equipment-system-software" label="NCS · 반도체 장비 시스템 소프트웨어 개발" />가 실제로 만드는 결과물이 바로 이 구조예요. CTC는 전체 시스템의 그래픽 사용자 인터페이스(GUI)를 담당하는 클라이언트이고, 여기에는 I/O 매니저·원격 인터페이스 엔진·인터로크·알람 관리·시퀀스 관리가 들어가요. 실제 하드웨어를 구동하는 쪽은 모듈 컨트롤러(서버)로, 원격 인터페이스 엔진과 모듈 엔진으로 구성돼요.

TMC·PMC 각 모듈도 이 구조를 그대로 축소해서 가져요 — 로컬 GUI(원격 인터페이스·I/O 매니저·인터로크·알람 관리·시퀀스 관리)가 개별 모듈을 제어하고, 그 아래 다양한 드라이버가 실제 하드웨어와 이어져요. 전체 시스템 하나가 똑같은 설계 원리를 층층이 반복하는 셈이에요.

## 7. 스케줄러와 레시피 관리 — 언제, 무엇을, 어떤 조건으로

### 스케줄링과 디스패칭

스케줄링(scheduling)은 어떤 제품을 어떤 장비에 배치할지 미리 계획해서 생산 시간을 줄이고 자원 낭비를 막는 과정이고, 디스패칭(dispatching)은 그 계획에 따라 장비 앞에 도착한 웨이퍼의 처리 순서를 실시간으로 정해 "지금 이 작업을 하라"고 지시하는 과정이에요.

반도체 장비의 스케줄러는 정해진 시간 안에 반드시 작업을 처리해야 하는 실시간 운영체제(RTOS) 위에서 동작해요. 플라스마·진공·가스·온도처럼 여러 장치를 동시에 제어해야 하니, 우선순위 기반의 선점형 스케줄링으로 정밀한 타이밍을 지켜요.

스케줄러는 세 가지 기능을 해요 — 장비 상태·주문 우선순위·자원 배치를 반영한 <strong>자동 일정 생성</strong>, 장비 고장·긴급 오더·웨이퍼 불량에 대응하는 <strong>동적 갱신</strong>, 유지 보수 시간·소모품 교체 주기·물리적 제약 조건·공정 시퀀스까지 모두 따지는 <strong>일정 검증</strong>이에요.

### 레시피 계층

레시피는 장비가 공정을 자동으로 수행하도록 미리 정해 둔 조건값의 집합이에요 — 온도·압력·가스 유량·전력·시간 같은 설정값을 담은 "공정 실행 프로그램"이죠. 관리 수준에 따라 세 층으로 나뉘어요.

| 레시피 | 범위 | 담는 내용 |
|---|---|---|
| 로트 레시피 | 최상위 | 로트(웨이퍼 묶음) 전체의 공정 흐름과 장비 운용 계획, 클러스터·프로세스 레시피의 조합 지정 |
| 클러스터 레시피 | 장비 단위 | 이송 로봇 경로, 로드 로크 동작, 공정 모듈(PM) 처리 순서 |
| 프로세스 레시피 | 공정 모듈 단위 | 가스 종류·유량, 챔버 압력, 온도, RF 전력, 공정 시간 |

이 레시피들을 등록·검증·변경·배포하고 실행 이력까지 관리하는 게 RMS(Recipe Management System)예요. RMS는 EAP(장비 자동화 프로그램)를 통해 실제 공정 실행과 연동되고, SECS/GEM 표준 메시지로 장비 간 레시피를 전달해서 모든 장비가 똑같은 조건으로 공정을 수행하도록 보장해요. 파라미터(설정값)는 RMS(레시피 관리) → EAP(장비로 전달) → EDA(공정 데이터 수집) → MES(생산·품질 관리) 순서로 흘러가며, 이 과정에서 실시간 데이터 수집과 이상 감지가 이뤄져요.

## 8. 화면 설계와 알람·이벤트 관리

### 장비 UI 레이아웃

장비 화면은 자리마다 역할이 정해져 있어요.

| 영역 | 표시·기능 |
|---|---|
| 상단 바(top bar) | 회사 로고·로그인, 장비 상태, 호스트 통신 상태, 신호등, 알람 표시 |
| 하단 바(bottom bar) | 메인 내비게이션 + 보조 기능의 세컨드 내비게이션 |
| 우측 바(right bar) | 실시간 공정 제어와 긴급 대응을 위한 조작 기능 |

이 세 영역과 내비게이션이 유기적으로 연결돼야 작업자가 원하는 기능으로 빠르게 이동할 수 있어요 — 이 역시 "어디를 누르면 뭐가 나온다"가 아니라 "어떤 정보를 어디에 배치할까"를 미리 정하는 설계의 문제예요.

### 알람은 경고가 아니라 상태 관리

알람은 단순한 경고음이 아니라 장비의 상태 전이(정상 → 이상 → 정상 복귀)를 관리하는 운영 시스템이에요. 센서·인터로크·기능 모듈이 이상을 감지하면 알람 처리 엔진이 이를 메시지로 바꿔 시각·청각으로 알리고, 심각도에 따라 치명적 알람·경고 알람·정보 알람으로 나눠요. 사용자가 복구 조치를 마치면 시스템이 자동으로 알람을 해제하고 정상 상태로 복귀해요.

알람은 다섯 단계로 관리돼요.

1. <strong>알람 발생</strong> — 센서·제어 모듈이 이상 상태를 감지해요.
2. <strong>메시지 표시</strong> — HMI에 시각적으로 표시해요.
3. <strong>복구 조치</strong> — 작업자 또는 프로그램이 복구 절차를 수행해요.
4. <strong>알람 해제</strong> — 이상 조건이 해소되면 자동 또는 수동으로 해제해요.
5. <strong>정상 상태 복귀</strong> — 장비가 정상 운전 모드로 돌아와요.

### 이벤트는 기록이다

이벤트는 공정 시작·종료, 로트 투입·교체, 레시피 변경, 알람 발생·해제 같은 주요 상태 변화를 시간 순서대로 남기는 기록이에요. 이 로그는 MES·EAP 같은 상위 시스템과 연동되어 공정 분석, 문제 추적, 품질 이력 관리에 쓰여요 — 알람이 "지금 무슨 일이 있었는지"를 알린다면, 이벤트는 "그동안 무슨 일이 있었는지"를 기억하는 역할이에요.
