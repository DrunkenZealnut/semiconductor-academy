## 1. 사람의 말과 기계의 신호 사이 — 프로그래밍 언어

컴퓨터가 곧바로 알아듣는 언어는 <strong>기계어</strong>, 즉 0과 1로만 이루어진 신호예요. 사람이 이 신호를 직접 다루기는 너무 불편하기 때문에, 사람의 사고방식과 기계의 신호 사이를 이어주는 도구로 <strong>프로그래밍 언어</strong>가 만들어졌어요.

좁은 뜻으로 프로그래밍은 컴퓨터가 할 일을 순서대로 설계하고 작성하고 시험해 보는 작업이고, 넓은 뜻으로는 오류를 찾아 고치고(디버깅) 프로그램을 다듬는 작업까지 포함해요.

하드웨어를 얼마나 직접 다루느냐에 따라 언어는 둘로 나뉘어요.

| 구분 | 특징 | 예 |
|---|---|---|
| 저급언어 | 하드웨어를 직접 제어, 사람이 읽기 어려움 | 기계어, 어셈블리어 |
| 고급언어 | 하드웨어 지식 없이도 작성 가능, 사람이 읽기 쉬움 | C, C++, Java, Python 등 |

어셈블리어는 기계어의 0·1 신호를 사람이 익힐 만한 1∼6글자 기호로 바꿔 표현한 것이고, 고급언어는 한 걸음 더 나아가 사람의 사고 흐름에 가까운 문장으로 프로그램을 작성하게 해줘요. 다만 C 언어로 작성한 소스 코드는 그 자체로 실행되지 않고, <strong>컴파일러</strong>라는 번역 프로그램을 거쳐야 비로소 기계어가 돼요(고급언어 중에는 Python처럼 인터프리터가 한 줄씩 바로 해석·실행하는 방식도 있어요).

## 2. C 언어는 어떻게 태어났을까

C 언어는 1972년 미국 벨 연구소에서 <strong>데니스 리치(Dennis Ritchie)</strong>와 <strong>켄 톰프슨(Ken Thompson)</strong>이 만들었어요. 켄 톰프슨이 먼저 설계한 B라는 언어가 있었는데, 두 사람이 <strong>UNIX 운영체제</strong>를 개발하는 과정에서 이를 다듬어 C로 발전시켰죠. 처음부터 DEC사의 컴퓨터 PDP-11에서 돌아가는 UNIX를 만들려고 설계된 언어라서, 지금까지도 유닉스 계열 운영체제와 유난히 궁합이 좋아요.

## 3. C를 C답게 만드는 특징

반세기 가까이 지난 지금도 C가 널리 쓰이는 이유는 다음 특징들 때문이에요.

- <strong>범용 프로그래밍 언어</strong>: 문서 작성 프로그램부터 운영체제·게임·로봇 제어까지 만들 수 있는 프로그램의 종류에 제한이 없어요. 다른 언어의 컴파일러를 C로 만들기도 해요.
- <strong>이식성이 높다</strong>: 같은 C 코드는 CPU 종류가 달라져도 거의 고치지 않고 실행할 수 있어요. 문자를 숫자로 표현하는 ASCII 코드 표준이 자리 잡으면서 이식성이 한층 더 좋아졌어요.
- <strong>형식이 자유롭다</strong>: 적은 수의 <strong>예약어(키워드)</strong>만으로 프로그램의 뼈대를 구성해요.
- <strong>함수(모듈)를 제공한다</strong>: 복잡한 문제를 작은 함수 단위로 쪼개 해결하고, 한 번 만든 함수는 다른 곳에서도 재사용할 수 있어요.
- <strong>하드웨어를 직접 건드릴 수 있다</strong>: 어셈블리어를 몰라도 메모리 같은 하드웨어 자원을 비교적 쉽게 다룰 수 있어, 운영체제 같은 시스템 프로그램을 만드는 데 유리해요.
- <strong>절차 지향적이다</strong>: 코드를 위에서 아래로 순서대로 실행해 사람이 흐름을 따라가기 편해요.

## 4. 소스 코드가 실행 파일이 되기까지

에디터로 작성한 C 코드는 그 자체로는 실행되지 않아요. 확장자 .c 파일로 저장하는 이 코드를 <strong>소스 코드</strong>라 부르고, 다음 3단계를 거쳐야 실행 파일이 돼요.

1. <strong>컴파일(Compile)</strong>: 컴파일러가 소스 코드에 문법 오류가 있는지 검사해요. 오류가 있으면 에러 메시지를 띄우고, 없으면 기계어로 번역해 확장자 .obj인 <strong>목적 파일(object file)</strong>을 만들어요.
2. <strong>링크(Link)</strong>: <strong>링커</strong>가 목적 파일을 표준 라이브러리 등 다른 코드와 연결해, 확장자 .exe(또는 .com)인 실행 파일을 완성해요.
3. <strong>실행(Run)</strong>: 완성된 실행 파일을 <strong>로더</strong>가 메모리에 올리면 비로소 프로그램이 동작해요.

이 과정에서 프로그래머가 직접 쓴 원본 코드를 <strong>원시 프로그램</strong>, 컴파일러가 만들어낸 기계어 코드를 <strong>목적 프로그램</strong>이라고 불러요.

번역 방식에 따라 언어 번역 프로그램은 이렇게 나뉘어요.

| 종류 | 번역 방식 | 특징 |
|---|---|---|
| 어셈블러 | 어셈블리어를 기계어로 | 명령 하나하나를 거의 그대로 대응시켜 번역 |
| 컴파일러 | 고급언어 전체를 한꺼번에 번역 | 목적 프로그램을 만들어 두므로 실행 속도가 빠름(C, C++, FORTRAN 등) |
| 인터프리터 | 고급언어를 한 줄씩 번역하며 즉시 실행 | 목적 프로그램을 만들지 않아 실행할 때마다 다시 번역해 상대적으로 느림(BASIC 등) |

C는 대표적인 <strong>컴파일러 언어</strong>예요. 그래서 실행 전에 반드시 컴파일과 링크 과정을 거쳐요.

## 5. C 프로그램의 최소 단위: 함수

C로 프로그램을 작성한다는 건, 결국 여러 개의 <strong>함수</strong>를 만들고 그 함수들이 실행되는 순서를 정하는 일이에요. 함수는 특정 작업 하나를 담당하는 독립된 코드 단위로, 입력을 받아 처리한 뒤 결과를 내놓는다는 점에서 수학의 함수와 닮았어요.

모든 C 프로그램은 함수 하나 이상으로 이루어지고, 그중 반드시 <strong>main</strong>이라는 이름의 함수가 있어야 해요. 프로그램이 시작되면 가장 먼저 자동으로 호출되는 함수가 바로 main이에요. 함수는 이름·입력값 종류·반환값 종류를 적어두는 <strong>헤더</strong>와, 실제 작업 내용을 담는 <strong>본체</strong> 두 부분으로 이루어져요.

함수는 두 종류로 나뉘어요. 컴파일러가 미리 만들어 둔 <strong>라이브러리 함수</strong>는 누구나 바로 가져다 쓸 수 있고, 프로그래머가 필요에 따라 직접 만드는 <strong>사용자 정의 함수</strong>는 원하는 대로 설계할 수 있어요. 다음 단원에서는 이 함수들을 실제로 호출하고, 값을 계산하고, 화면에 출력하는 코드를 직접 다뤄볼게요.
