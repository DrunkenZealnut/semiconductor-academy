## 한 줄 요약

아키텍처 설계 = 무엇을 만들지 정하고(설계 사양), 어떻게 구성할지 그리고(전체 블록도), 언제 누가
만들지 계획하고(개발 절차), 제대로 만들어졌는지 어떻게 확인할지(검증 계획)까지 — 진짜 회로를
그리기 전에 큰 그림을 미리 다 그려 두는 일이에요. 「반도체 산업의 유해인자」<ChapterRef order={2} />가
"반도체 칩이 무엇인가"를 설명한다면, 이 모듈은 **"그 칩을 어떤 순서로, 어떤 모양으로
설계하나"**를 다뤄요.

## 1. 설계 사양 정하기 — 무엇을 만들 것인가

반도체 칩을 설계하기 전, 가장 먼저 정해야 하는 건 "이 칩이 정확히 무엇을 하는 물건인가"예요.
이 내용을 문서로 정리한 게 **데이터시트(Datasheet)** 이고, 여기에는 세 종류의 규격이 담겨요.

### 가. 데이터시트에 담기는 세 가지 규격

첫째는 **기능 규격**이에요. 전체 블록도, 내장 프로세서·메모리 사양, 각 기능 블록의 역할, 외부
부품과 주고받는 신호의 규격까지 "무슨 일을 하는 칩인가"를 정리해요. 둘째는 **전기적 규격**인데,
넘으면 칩이 망가지는 한계선인 최대 허용 범위(Absolute Maximum Ratings)와, 정상적으로 동작하는
범위인 추천 동작 조건 두 가지로 나뉘어요. 셋째는 **물리적 규격** — 패키지의 모양, 크기, 핀
개수처럼 완성됐을 때의 실제 겉모습이에요.

### 나. 경쟁 제품과 비교해서 사양을 확정한다

설계자는 이 제품이 실제로 쓰일 응용처(스마트폰, 자동차 등)마다 어떤 기능이 필요하고 불필요한지
먼저 정리하고, 이미 나와 있는 경쟁 제품의 데이터시트를 구해 비교표를 만들어요. 다음은 그렇게
정리한 비교표의 예시예요.

| 비교 항목 | 설계할 제품 | 경쟁제품 A | 경쟁제품 B |
|---|---|---|---|
| 최대 주파수 | 96MHz | 48MHz | 100MHz |
| 반도체 공정 | 65nm | 65nm | 90nm |
| 패키지 종류 | BGA-120 | QFP-64/100, BGA-120 | QFP64, BGA216 |

### 다. 반도체 공정을 고른다 — 직접 만들까, 맡길까

사양이 정해지면 이걸 실제로 <Term id="wafer">웨이퍼</Term> 위에 찍어낼 **반도체 공정**을 골라야
해요. 공정은 회로의 최소 선폭(nm, 나노미터)이 가늘수록 집적도가 높아지는데, 요즘은 90/80nm부터
16/14nm까지 다양한 공정이 쓰이고 있어요.

<Callout type="info" title="IDM과 파운드리 — 반도체 회사의 두 얼굴">
  <strong>IDM(종합 반도체 회사)</strong>은 설계부터 제조·테스트까지 한 회사가 다 맡는 곳(삼성전자,
  SK하이닉스, Intel 등)이고, <strong>파운드리</strong>는 설계도만 받아 생산만 전담하는 회사(TSMC,
  UMC 등)예요. 설계만 하고 자체 공정은 없는 회사는 <strong>팹리스(Fabless)</strong>라 불러요.
</Callout>

공정을 고를 때는 회로 크기, 아날로그 IP 지원 여부, 제조 비용과 일정까지 함께 따져요. 특히 웨이퍼
한 장에서 칩이 몇 개나 나오는지도 중요한 기준이에요 — 웨이퍼 면적을 칩 한 개의 면적으로 나누면
대략적인 생산 개수를 예측할 수 있어요(웨이퍼는 지름 8인치(200mm), 12인치(300mm)로 구분돼요).

## 2. 아키텍처 그리기 — 어떻게 구성할 것인가

사양과 공정이 정해지면, 이제 그 사양을 실제 회로 블록들로 어떻게 나누고 연결할지 그리는
단계예요. 좁은 의미의 "아키텍처 설계"가 바로 이 단계이고, 그 중심에는 **전체 블록도**가 있어요.

### 가. 전체 블록도, 칩의 설계도

전체 블록도에는 각 기능 블록의 역할, 데이터가 처리되는 흐름, 내부 메모리 구성, CPU가 있다면 그
정보, 각 블록의 동작 주파수까지 담겨요. 이 블록도가 상세할수록 나중에 회로를 짜는 설계자들이
헤매지 않아요. 아날로그 회로는 전기적 노이즈에 약해서, 빠르게 동작하는 디지털 블록과는 일부러
떨어뜨려 배치해요.

### 나. IP를 살까, 만들까

블록마다 처음부터 새로 설계할지, 이미 검증된 **IP(Intellectual Property, 반도체설계자산)**를
사올지도 결정해야 해요. 기존에 개발한 블록이 있으면 그대로 쓰거나 일부만 고쳐 쓰고, 없으면 자체
개발과 외부 라이선스 도입 중 하나를 고르는데, 개발 일정이 빠듯할수록 라이선스 도입이 유리해요.

<SourceQuote section="NCS 학습모듈 — 반도체 아키텍처 설계: 3-1. 아키텍처 결정 (다양한 구조의 아키텍처 설계)">
  <p>
    반도체 아키텍처 설계는 한 가지 형태로 구현을 할 수도 있지만, 구현 방법 및 기능 블록의 분배에
    따라서 여러 가지 형태로 설계가 가능하다. 그러므로 아키텍처 설계 담당은 각 기능 블록의 연결
    상태와 사용하는 CPU, 메모리의 형태에 따라서 가능한 아키텍처의 구조를 설계해서 각각의
    아키텍처에 대한 비교를 하여 최적의 아키텍처를 선정한다.
  </p>
</SourceQuote>

### 다. 완성된 아키텍처의 모습

아키텍처가 결정되면 각 기능 블록의 이름, 연결 형태, 동작 주파수까지 구체적인 숫자로
표현돼요. 다음은 그렇게 정리된 사양 예시의 일부예요.

| 항목 | 주요 사양 |
|---|---|
| CPU 동작 속도 | 10MHz ~ 200MHz |
| CPU core | 32bit operation |
| 내부 동작 전압 / 전류 | 1.2V / 300mA |
| 외부 인터페이스 전압 | 3.3V 또는 1.8V |

  관점의 그림을 같이 그려요.

## 3. 개발 계획과 검증 — 언제 만들고, 제대로 됐는지 어떻게 확인할까

아키텍처가 완성됐다고 바로 공정에 들어가지는 않아요. 어떤 순서로 누가 만들지 계획을 짜고, 실제
칩을 찍기 전에 "이대로 만들면 진짜 작동하는가"를 미리 확인하는 과정이 남아 있어요.

### 가. 개발 단계와 위험 요소

개발은 설계 사양서 작성 → 전체 블록도 → 블록별 상세 설계(RTL) → FPGA 검증 → 합성·배치·연결 →
웨이퍼·패키지 제작 → 기능·신뢰성 검증 → 양산 준비 순으로 진행돼요. 각 단계마다 설계 오류, 기능에
대한 오해, 검증 미흡, 반도체 공정 특성 변동, 패키지 설계 오류 같은 위험 요소가 숨어 있어서, 미리
예측하고 대응 방안을 세워 둬야 나중에 당황하지 않아요.

### 나. 진짜 칩을 만들기 전 리허설 — 검증 시스템과 동작 시나리오

반도체 공정은 한 번 시작하면 되돌리기 어렵고 비용과 기간도 많이 들어요. 그래서 공정에 들어가기
전에 **FPGA(Field Programmable Gate Array)** 라는 프로그래밍 가능한 부품에 설계한 회로를 미리
심어서 실시간으로 동작을 확인해요 — 진짜 칩을 만들기 전 리허설인 셈이에요.

<Callout type="warning" title="한 번 tape out하면 되돌릴 수 없어요">
  Tape out(공정 전달)은 인쇄소에 최종 원고를 넘기는 것과 비슷해요. 넘긴 뒤에 오류가 발견되면
  처음부터 다시 웨이퍼를 만들어야 하므로 비용·기간 손실이 커요. 그래서 공정에 들어가기 전 검증은
  절대 건너뛰면 안 되는 단계예요.
</Callout>

<SourceQuote section="NCS 학습모듈 — 반도체 아키텍처 설계: 4-2. 검증 시스템 결정 (설계 검증 시스템)">
  <p>
    반도체 제조 공정은 그 비용이 많이 들고, 제조 일정이 길기 때문에 반도체 공정에 들어가기 전에
    최대한 많은 기능들이 정상적으로 동작하는지 검증하여 기능 불량이 날 확률을 최소화해야 제품을
    성공적으로 완성 할 수 있다.
  </p>
</SourceQuote>

실제 확인은 **동작 시나리오**로 이뤄져요. 블록 하나씩만 확인하는 게 아니라, 여러 블록이 데이터
흐름을 따라 함께 움직이는 상황을 시나리오로 만들어 검증 시스템에 돌려 보고, 예상했던 결과와 실제
결과가 같은지 비교해요. 다르면 원인을 찾아 수정하고, 다시 처음부터 검증을 반복해요.

## 이 일을 하는 사람은

설계 사양과 개발 계획은 **아키텍처 설계자**가, 각 기능 블록의 회로를 실제로 짜는 일은 **RTL
설계 엔지니어**가, 검증 시스템을 만들고 동작을 확인하는 일은 **검증(Verification) 엔지니어**가
맡아요. 여기에 하드웨어와 맞물려 동작하는 소프트웨어를 준비하는 담당자까지 함께 움직여야, 사양서
한 장이 진짜 동작하는 칩이 될 수 있어요.
