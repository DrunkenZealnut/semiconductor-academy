## 2. PDCA 사이클 요약

### 2.1 Plan 단계 (2026-08-09)

**사이트 첫 자체 도해 도입**이라는 명확한 배경이 있었다. 원문 도판 336개를 저작권상 전면 미사용하기로 한 선행 사이클 이후, 그 공백을 채울 수 있는 유일한 방법이 자체 제작이었다.

**주요 결정**

| # | 결정 | 사용자 선택 | 비고 |
|:--:|---|---|---|
| 1 | 도해 개수 | **97모듈 전부** (최소 시각 요소가 아니라 "시각 리듬"을 목표) | 이로 인해 Design §5.2 판정 규칙 재정의가 필수가 됨 |
| 2 | 구현 방식 | **재사용 컴포넌트 세트** (8→12종) | 97개 전용 SVG는 유지보수 불가능 |
| 3 | 기술 기반 | **서버 컴포넌트 정적 SVG** | 상호작용 0 · JS 번들 증가 0 · 접근성 한 곳에서 통제 |
| 4 | 실행 순서 | **파일럿 게이트 후 확대** (1차 → 2차) | 시각 언어를 뒤늦게 바꾸면 모든 그림을 다시 그려야 함 |

**FR 9개 · NFR 7개** 확정. 특히 NFR-1(First Load JS 증가 0)이 기술 기반을 정했다 — 직전 사이클이 102kB를 성과로 기록했기 때문이다.

**Design 정정 V-1 반영**: Step 0 전수 배치에서 8종으로 커버 안 되는 22모듈이 드러났다(분류 트리·특성 곡선·기능 블록도·원자 격자·연표 5개 패턴). 계획 수립 후 즉시 설계 단계에서 12종으로 확대 결정.

### 2.2 Design 단계 (2026-08-09)

**Step 0 — 97모듈 배치 전수 매핑**이 최대 난관이었다. 모듈마다 ⓐ어떤 컴포넌트를 ⓑ어떤 데이터로 ⓒ왜 넣는지 배정해야 했고, 배정 기준은 "**이 그림이 없으면 무엇을 못 읽는가**" 한 줄이었다.

**12종 컴포넌트 스펙 확정**

```
1차 5종 (Step 1에서 검증):
  LayerStack — 소자·막 단면 적층
  FlowSteps — 공정·동작 순서
  CompareCards — 2열/3열 대조
  TruthTable — 진리표
  NodeGraph — 회로도·블록도 (V-2: 1차 승격, 2차에서 아님)

2차 7종 (Step 2~3에서 적용):
  ValueBars — 자릿수 차 큰 수치
  TreeBranch — 계층 분류
  LatticeDiagram — 원자 결정 격자
  CurvePlot — 곡선 (항상 보조, 주 도해 아님)
  ScaleRuler — 크기 감각
  Timeline — 연표
  LabeledFigure — 범용 라벨 래퍼
```

## 4. 이 사이클의 서사

### 4.1 사이트 최초의 자체 도해

13개 자료원 425개 이미지가 전부 원문 스캔이었다. 자체 제작 SVG는 `og-default.svg` 1개뿐이었다. 이 사이클은 단순한 "확대"가 아니라 **첫 번째 시각 어휘를 세우는 일**이었다.

### 4.2 8종 → 12종 확대 (V-1의 의미)

Plan에서 8종으로 계획했으나 Step 0 배치 중에 **22모듈이 8종으로 커버되지 않음**이 드러났다.

- 분류 트리(7모듈) — 2축/3축 계층
- 특성 곡선(5모듈) — I-V 형상, 대역폭
- 기능 블록도(5모듈) — MCU·DSP·MCM 구성
- 원자 결정 격자(4모듈) — 실리콘·인·붕소
- 연표(4모듈) — 기술 역사

→ `TreeBranch`, `CurvePlot`(기존), `NodeGraph`(1차 승격), `LatticeDiagram`, `Timeline` 5종 추가. 계획 대비 설계 단계에서의 **동적 확대**는 이 프로젝트의 특징이다.

### 4.3 design-validator가 잡은 4건 (V-2~V-5)

- **V-2**: 파일럿이 미존재 컴포넌트 요구 (`NodeGraph` 1차 승격)
- **V-3**: `idPrefix` 규약 재검토 (구현 후 2종만 필수였음)
- **V-4**: col-8 욕조 곡선은 원서에 없음 (자동 다시쓰기 방지)
- **V-5**: 자수 측정 로직의 결함 — 정규식이 도해 JSX를 불규칙하게 삼킴

### 4.4 원문 근거 규약이 9건을 되돌림

흥미로운 발견: 도해를 그으려는 과정에서 **"원문에 이 값이 있나?"**를 계속 묻게 되었다.

- 001: 절연체 상한 없음, `1e14`는 창작 ❌
- 087: High-k 유전율 수치 미제시, 088에서 끌어온 값 ❌
- col-3·col-2·col-7·078·047·050: 원문 형상·데이터 재확인 결과 **아래 주석 표기** 필요

이는 **도해 작업 특유의 함정**이다: 표는 "데이터를 요약"하기만 하면 되지만, 도해는 "**무엇을 그릴 것인가?**"라는 질문이 바로 설계 검증이 된다.

### 4.5 자수 측정 로직 결함 (V-5)

정규식 `<[^>]+>`가 도해 JSX 블록을 불규칙하게 삼킨다는 발견.

```
011 (단일 컴포넌트): <LayerStack ... /> → 통째 제거 → ±0
018 (다중 태그): <strong>text</strong> → </strong> 뒤의 텍스트 남음 → +141
```

→ 줄 단위 제거로 교정 + 선행 사이클 `first-semiconductor-primer.design.md` §5.1에 예외 문안 역반영. **측정 재현성을 높이는 부수 효과**도 있었다.

### 4.6 선행 사이클 문서 2건 갱신

1. **Design §5.2 재정의** — "텍스트로 구조 불성립할 때만"에서 **"T1 정밀 / T2 패턴 / T3 강화 3단 판정"**으로 확대.
2. **Design §5.1 자수 기준 현행화** — 항목 1,200~2,000 → **1,200~2,300** · COLUMN 600~1,200 → **600~1,600** (실측 분포 반영).

## 6. 교훈

### 6.1 설계-구현의 동적 상호작용

Plan(8종) → Design(12종)의 확대는 **설계 단계에서 배치 검증이 필수**임을 보여줬다. 상세 설계 없이 구현에 들어갔다면 22개 모듈이 떠돈 채로 후반에 터졌을 것이다.

### 6.2 원문 근거 규약의 실제 작동

도해를 만들다 보면 자동으로 "원문에 이 데이터가 있나?"를 묻게 된다. 이를 문서화한 §5.2 규약("원문 형상이 없으면 `CurvePlot` 배정 금지")이 **087·col-3처럼 실제 오류를 방지**했다. 창작의 방지책이 되었다.

### 6.3 서버 컴포넌트의 번들 이득

12종 × 140 인스턴스를 넣고도 **First Load JS 102kB 무증가**. 이는 상호작용을 포기하고 정적 SVG로 가기로 한 Design D-4 결정의 타당성을 증명했다.

### 6.4 보조 도해의 가치

1차에서 Gap-1(보조 26건 미적용)으로 78.1%였으나, 이를 채우자 93.6%로 뛰었다. 보조는 "있으면 좋은 것"이 아니라 **주 도해의 설명을 완성하는 필수 요소**였다.
