### 4.2 종결된 게이트 — 판권 확인 (Design §7 D-1)

원문 스캔본에 판권 페이지가 없어 역자·출판사·발행연도는 끝까지 미확인이었고, Plan §4.4가 이를 **공개 배포 게이트**로 걸어 뒀다.

**2026-08-09 사용자 결정으로 종결** — 이 사이트는 middleware 로그인 게이트 뒤에서만 열람되는 **비공개 개인 학습용**이라 공개 배포가 성립하지 않는다.

**조치**: 미확인 정보를 표기하지 않도록 `publisher` 필드 제거. 이때 `disclosureFor`의 no-publisher 분기가 13개 자료원 중 **처음** 실행되며 바이라인이 `(菊地正典(기쿠치 마사노리))`로 괄호 중첩돼, `attribution`을 괄호 없는 `'기쿠치 마사노리 菊地正典'`으로, 분기를 `(attribution 지음)`으로 함께 정리했다.

## 7. 긍정점 & 개선 사항

### 7.1 잘 된 점 (Keep)

- **입도 결정을 사용자에게 넘긴 것** — 오케스트레이터는 20그룹을 권했으나 사용자가 88항목을 택했다. "빼먹지 말라"는 요구를 **입도 자체로 보장**하는 선택이었고, 결과적으로 누락 0을 구조적으로 달성했다.
- **오프셋 −4의 일정성 검증** — OCR 손상 목차를 6개 지점 교차 검증으로 기계적 복원. 추측이 아니라 측정으로 97항목을 확정했다.
- **4중 정합성 검증** — `043-dram` sections 소실(이슈 3)은 이 검증이 없었으면 빌드도 통과하고 조용히 누락됐을 결함이다.
- **Design/Do 정정 5건의 역방향 기록** — V-1~V-5를 Plan·Design에 이력으로 남겨 후속 사이클이 같은 오판을 반복하지 않게 했다.
- **원서 시점차 처리 패턴** — 2010년경 원서의 '미래 기술' 서술을 그대로 옮기고 이후 실제 전개를 별도 절로 병기. 이 패턴이 CodeRabbit 리뷰 반영에도 그대로 적용됐다.

### 7.2 개선 사항 (Improvement)

- **자기 검증이 4번 틀렸다.** 서브에이전트 없이 오케스트레이터가 직접 측정하면서 판정 스크립트 자체의 결함(하드코딩·정규식·줄바꿈)과 **Match Rate 산출 오류**까지 나왔다. 측정 결과가 기대와 어긋날 때 **먼저 측정 코드를 의심**하는 절차가 필요하다.
- **일괄 치환 전 영향 범위 미확인** — 이슈 4는 정규식을 22파일에 적용하기 전에 1파일 dry-run만 했어도 막을 수 있었다.
- **Design 수치 기준이 실측과 어긋났다** — 항목 1,200~2,000자 기준은 3단 레이어 + 표를 포함하는 실제 콘텐츠에 좁았다.

### 7.3 다음에 적용할 것 (Try)

- 대량 파일 일괄 변경은 **1파일 dry-run → diff 확인 → 전체 적용** 순서를 고정한다.
- Gap 판정 스크립트는 **양성 대조군**(의도적으로 틀린 입력)을 함께 돌려 스크립트 자체를 검증한다.
- Match Rate는 **그룹 소계 합과 총계를 교차 검증**한다 (이번 오류 ④의 직접 재발 방지).
- 신설 통제 어휘는 Design 단계에서 **역방향 연결 시뮬레이션**을 먼저 돌린다 (V-2 재발 방지).
