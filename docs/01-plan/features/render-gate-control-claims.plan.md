# 렌더 관문 대조군의 주장 — Plan

> **선행**: `render-gate-scope-floor`(94%, 2026-08-28 아카이브) 잔존 **B-1** · **B-5**
> **한 줄**: 대조군 29건이 있는데 **호출부 배선 11자리 중 5자리는 망가뜨려도 아무도 안 운다.**

---

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 판정을 순수 함수(`scopeStatic`·`scopeViolations`)로 뽑아 대조군을 싸게 얻었는데, **그 함수를 부르는 자리**는 아무도 안 본다. 실측: 인자 11자리 중 **5자리를 망가뜨려도 자체검사가 종료 0**이다. 특히 `scopeStatic` 전체(브라우저 앞 판정 γ·ε·α₀·σ)가 사실상 무대조군이다. |
| **Solution** | 자식 대조군의 임시 cwd에 **가짜 도해 트리**(컴포넌트 파일 + 배럴 + MDX)를 직접 심는다. 그러면 γ·ε·α₀·σ·β를 자식으로 **직접 유발**할 수 있어 배선 5자리가 한꺼번에 덮인다. 동시에 자식이 **저장소 상태와 무관**해져 B-5(정적 위반이 자식 대조군 앞을 막아 사유가 어긋나는 것)도 풀린다. |
| **Function · UX Effect** | **독자에게 보이는 변화는 없다.** 검사기가 자기 배선을 증명하는 사이클이다. |
| **Core Value** | *"대조군이 있다"* 와 *"그 판정이 본 검사에서 살아 있다"* 는 다른 주장이다. 지금은 앞의 것만 참이다. |

## 1. 문제 — 실측이 B-1을 5배로 키웠다

선행 Check가 남긴 것:

> **B-1** β의 배선에 대조군이 없다. **B-5** 정적 판정이 자식 대조군의 앞을 막아 ⑲⑳㉑㉒가 *"사유 불일치"* 로 실패한다 — 관문은 빨개지지만 **메시지가 원인을 안 가리킨다.**

착수 전에 **호출부 인자를 하나씩 훼손**해 자체검사가 잡는지 전수로 봤다.

| 호출부 | 인자 | 무엇의 배선 | 잡히나 | 깨진 대조군 |
|---|---|---|:--:|---|
| `scopeStatic` | `svg` → `[]` | α₀ | ❌ | (없음) |
| `scopeStatic` | `dir` → `barrel` | γ | ❌ | (없음) |
| `scopeStatic` | `barrel` → `dir` | γ 반대쪽 | ❌ | (없음) |
| `scopeStatic` | `skipped` → `[]` | σ | ❌ | (없음) |
| `scopeStatic` | `pagesByKind` → 빈 Map | — | ✅ | ⑲⑳㉑㉒㉓ |
| `scopeViolations` | `svg` → `[]` | α | ✅ | ⑳ |
| `scopeViolations` | `dir` → `barrel` | **β** ← B-1 | ❌ | (없음) |
| `scopeViolations` | `observed` → 빈 Set | 관측 | ✅ | ㉑ |
| `scopeViolations` | `observedSvg` → 빈 Set | δ | ✅ | ㉒㉓ |
| `scopeViolations` | `pagesByKind` → 빈 Map | δ | ✅ | ㉒㉓ |
| `scopeViolations` | `urls` → 전부 | δ | ✅ | ㉒㉓ |

**덮인 배선 6/11.** `scopeStatic`에서 유일하게 덮인 `pagesByKind`도 **우연**이다 — 관측 쪽 대조군들이 같은 Map을 쓰기 때문이지 정적 판정을 증명해서가 아니다.

### 1.1 ★선행 Check가 이 자리를 **틀리게** 적었다

선행 분석 §2 B-1은 이렇게 적었다.

> ㉒가 δ를, ⑳이 α를, **배럴 조작 실측이 γ·ε를 덮는다**(자식이 정적 판정에 걸려 죽는 것으로).

**틀렸다.** 배럴 **파일**을 조작하면 잡히지만, 배선을 조작하면 안 잡힌다. 둘은 다른 주장인데 같은 것으로 셌다. *"자식이 정적 판정에 걸려 죽는다"* 는 관찰은 맞지만, 그것은 **저장소가 망가졌을 때**의 이야기이지 **검사기가 망가졌을 때**의 이야기가 아니다.

### 1.2 B-1과 B-5는 **같은 구조**에서 나온다

```text
   본 검사:   collectUrls → scopeStatic(정적) → 브라우저 → 관측 → scopeViolations
                              │
   자식 대조군:                └── 여기를 **통과한 뒤에야** 자식이 돌 자리에 닿는다
```

정적 판정이 앞에 있으므로,

- **B-1** 정적 배선을 무력화하면 자식은 그냥 지나간다 → 아무도 안 운다
- **B-5** 정적 판정이 **울면** 자식이 그 메시지로 죽는다 → 노린 사유와 어긋난다

**원인이 하나다** — 자식이 **실제 저장소 상태를 공유**한다(임시 cwd가 `src/components`를 심링크로 잇는다).

## 2. 해법 — 자식을 저장소에서 떼어 낸다

임시 cwd에 심링크 대신 **가짜 도해 트리**를 직접 만든다.

```text
임시 cwd/
  node_modules -> 심링크        (playwright-core만 있으면 된다)
  src/data     -> 심링크        (chapters.json)
  src/components/diagram/       ← 직접 만든다
      Alpha.tsx   ( <svg 포함 )
      Beta.tsx    ( <svg 없음 )
      index.ts    ( export { Alpha } from './Alpha' … )
  src/content/probe/*.mdx       ← 직접 만든다
```

이러면 자식 안에서 **상태를 마음대로 만들 수 있다**.

| 만들 상태 | 유발되는 판정 | 덮이는 배선 |
|---|---|---|
| 배럴에 `Ghost`를 넣고 파일은 안 만든다 | **γ** | `scopeStatic.dir`·`barrel` |
| `Extra.tsx`를 만들고 배럴에 안 넣는다 | **ε** | `scopeStatic.dir`·`barrel` |
| `Alpha`를 어느 MDX도 안 쓰게 한다 | **α₀** | `scopeStatic.svg` |
| `topics/x.mdx`처럼 URL 규칙 밖에 둔다 | **σ** | `scopeStatic.skipped` |
| 스텁이 `data-diagram="Nope"`를 낸다 | **β** | `scopeViolations.dir` ← **B-1** |

> ★**Check 정정**: 위 표는 *"실제 트리를 쓰는 ⑳이 유도 규칙을 지킨다"* 를 전제했는데 틀렸다(분석 B-8). 실제 트리의 값은 **α 배선 + 저장소 정적 건강검진**이고, 유도 규칙을 지키는 것은 **가짜 트리 자식 ㉒·㉓**다.

**다섯 자리가 한 기계로 덮인다.** 그리고 자식이 저장소를 안 보므로 **B-5도 사라진다** — 저장소를 조작해도 자식은 노린 사유를 그대로 낸다.

## 3. 열린 문제 — Design이 정한다

| # | 문제 |
|:--:|---|
| **A** | **가짜 트리가 실제와 멀어진다.** 지금 자식은 진짜 컴포넌트를 읽어 `SVG_COMPONENTS`를 유도한다. 가짜로 바꾸면 *"유도 규칙이 실제 컴포넌트에서 도는가"* 를 아무도 안 보게 된다 — **새 무대조군 지대**다(선행 사이클이 순수 함수를 뽑으며 겪은 것과 같은 모양). 실제 트리를 쓰는 자식을 **하나는 남길 것인가.** |
| **B** | **`node_modules`·`src/data` 심링크는 남는다.** 완전 격리가 아니다. 어디까지가 "저장소와 무관"인지 선을 그어야 한다. |
| **C** | **자식 수와 값.** 배선 5자리를 덮으려면 자식이 4~5개 는다. 지금 자체검사 약 11초 — 얼마가 되나. 한 자식에 여러 상태를 겹쳐 실을 수 있나(예: γ와 ε를 한 번에)? 겹치면 값은 싸지지만 **어느 판정이 울었는지** 사유로 갈라야 한다. |
| **D** | **B-5의 처방을 따로 둘 것인가.** 자식을 격리하면 B-5가 자연히 풀리지만, *"정적 위반이 있으면 처분 대조군을 건너뛰고 말한다"* 는 방어를 **추가로** 둘 수도 있다. 이중이 필요한가. |

## 4. 기능 요구

| # | 내용 |

| FR-1 | 자식 대조군이 임시 cwd에 **가짜 도해 트리**(컴포넌트 · 배럴 · MDX)를 만든다 |
| FR-2 | γ 배선 — 배럴에 있고 파일이 없는 상태를 자식으로 유발해 `exit 2`와 사유 확인 |

| FR-5 | σ 배선 — URL 규칙 밖 MDX |
| FR-6 | **β 배선**(B-1) — 관측에 없는 종이 그려지는 상태 |

## 6. 착수 순서

```text
① FR-9 배선 감사 스크립트부터 — 지금 6/11을 기록으로 고정한다
② 가짜 도해 트리 기계 (열린 문제 A·B의 선을 Design이 그은 뒤)
③ γ·ε 자식 대조군 → 감사 재실행
④ α₀·σ 자식 대조군 → 감사 재실행
⑤ β 자식 대조군(B-1) → 감사 재실행
⑥ G-6 — 저장소를 망가뜨리고 사유가 어긋나지 않는지
⑦ 되돌려 확인(FR-8) + 문서 · Check
```

**①이 먼저인 이유**: 이 사이클의 게이트가 *"6/11 → 11/11"* 이다. **재는 자를 먼저 만들지 않으면 나중에 무엇이 늘었는지 말할 수 없다.** 그리고 ③④⑤ 사이에 감사를 반복 실행해 **한 걸음마다 몇이 늘었는지** 본다.
