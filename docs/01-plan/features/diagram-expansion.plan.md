| 관점 | 내용 |
|---|---|
| **Problem** | 도해 12종은 공용 자산으로 만들었으나 적용은 `first-semiconductor` 97모듈뿐이다. 그런데 **백로그의 "213모듈 + 책 17장" 전제를 실측하니 틀렸다** — 213모듈이 균일하게 시각 자료가 없는 것이 아니다. `ncs-semi` 84모듈은 이미 원문 도판 **345장**(4.1/모듈), 책 17장은 **80장**(4.7/모듈)을 갖고 있다(`ncs-image-expansion` 2026-07 등이 넣은 것). 진짜로 **시각 자료가 0인 모듈은 129개**다 — `hs-*` 8종 96 + `cert-equip-maintenance` 13 + `daegu-hs-process` 10 + `osha-scs` 10. 이 129모듈이 `first-semiconductor`가 도해를 받기 전과 정확히 같은 상태다. |
| **Solution** | 129모듈을 **우선 대상**으로 삼고, 이미 도판을 가진 101모듈(ncs 84 + 책 17)은 **선별 보완**으로 성격을 갈라 4개 웨이브로 나눈다. 각 웨이브는 독립 PDCA 사이클이 되고, 이 문서는 그 순서·범위·공통 규약을 고정하는 **umbrella plan**이다. 웨이브를 쪼개는 이유는 규모다 — 129모듈은 25,262줄, 전체 230모듈은 51,276줄로 기준선(97모듈 13,055줄)의 **3.9배**다. 한 사이클에 몰면 선행 두 사이클이 가장 어려워했던 **전수 배치 매핑(Step 0)**이 4배가 되고, 자기 검증 실패가 그만큼 늘어난다. |
| **Function UX Effect** | 시각 자료가 하나도 없던 129모듈에서 독자가 **본문을 읽기 전에 구조를 한 장으로 먼저 본다** — 교과서 8권의 장비 구조·공정 흐름, 수험서의 분류 체계, OSHA의 화재 3요소가 그림이 된다. 12종이 같은 시각 언어를 쓰므로 자료원을 옮겨도 **그림 읽는 법을 다시 배우지 않는다**. 번들은 늘지 않는다(전부 서버 컴포넌트). |
| **Core Value** | 12종은 두 사이클(93.6% → 97.3%)에 걸쳐 만들고 계약까지 고정한 자산인데 **한 자료원에만 쓰이고 있다.** 이 확대는 새 코드를 거의 쓰지 않고 **이미 지불한 비용의 회수율을 3.4배로 올리는 일**이다(97 → 최대 330모듈). 동시에 사이트에서 가장 약한 지점을 메운다 — 129모듈은 지금 **글과 표만 있는 상태**이고, 그중 96개가 고등학생용 교과서다. |

### 1.2 이 정정이 계획을 바꾸는 지점

**`first-semiconductor`가 도해를 받은 이유는 "글만 있어서"가 아니라 원문 도판 336개를 저작권상 전면 미사용하기로 했기 때문이다.** 자체 제작이 유일한 수단이었다.

| 상황 | 해당 | 12종의 값 |
|---|---|---|
| **원문 도판 0 + 자체 도해 0** | **129모듈** | **높다** — 시각 자료가 아예 없다. 기준선과 동일 상황 |
| 원문 도판 있음 + 자체 도해 0 | 101모듈 (ncs 84 · 책 17) | **선별적** — 도판이 이미 그 일을 한다. 도판이 못 하는 것(개념 대조·자릿수 차·논리 구조)만 보탠다 |

101모듈에 12종을 균일 적용하면 **같은 내용을 두 번 그리는 일**이 된다. 그래서 이 계획은 129를 먼저 하고, 101은 마지막 웨이브에서 **도판이 커버하지 못하는 것만** 고른다.

### 1.3 규모 — 왜 한 사이클이 아닌가

| | 기준선 | 129모듈 | 전체 230모듈 |
|---|--:|--:|--:|
| 모듈 | 97 | 129 (1.3×) | 230 (2.4×) |
| 줄수 | 13,055 | 25,262 (1.9×) | 51,276 (**3.9×**) |
| 예상 인스턴스 | 140 | ~190 | ~330 |
| 실제 소요 | **2일·2세션** (Act 1회 필요) | — | — |

기준선 사이클은 Check 1차 **78.1%**에서 시작해 Act 1회로 93.6%에 도달했다. 가장 어려운 단계는 **Step 0 전수 배치 매핑**(모듈마다 ⓐ어떤 컴포넌트 ⓑ어떤 데이터 ⓒ왜)이었다. 이것이 3.9배가 되면 매핑 품질이 먼저 무너진다.

## 2. 목표 / 비목표

### 목표

1. **시각 자료 0인 129모듈에 12종 적용** — 웨이브 W1~W3
2. 도판 보유 101모듈은 **선별 보완** — 웨이브 W4, 도판이 못 하는 것만
3. 웨이브별 사이클이 재사용할 **공통 규약 고정** — 자료원 유형별 배치 판정, 파일럿 게이트, 검증 매트릭스 양식
4. `usage.md`를 확대 실적으로 갱신(현재 "97모듈 실적용"만 기록)
5. 번들·SSG 회귀 0 유지

### 비목표

- **13번째 컴포넌트 신설** — `usage.md` §4 기준(같은 패턴 3모듈 이상 반복)에 걸리면 해당 웨이브 Design에서 판단한다. 이 계획이 미리 정하지 않는다.
- **원문 도판 추가·교체** — `ncs-image-expansion` 계열 작업이다. 이 사이클은 자체 도해만 다룬다.
- **`ProcessDiagram` 통합** — `src/components/process/ProcessDiagram.tsx`는 `'use client'` 네비게이션 위젯이라 12종과 다른 축이다. 건드리지 않는다.
- **본문 텍스트 재작성** — 도해 추가와 표 병치만. 3단 레이어 내용은 그대로 둔다.
- **공정 MDX 9개** — `src/content/processes/`는 도해·도판이 모두 0이나 자료원 모듈이 아니라 사이트 자체 콘텐츠다. 별도 판단 대상으로 남긴다(§7 R-5).

## 4. 공통 규약 (웨이브 사이클이 상속할 것)

### 4.1 이미 고정된 계약 — 다시 정하지 않는다

`diagram-set-finishing`이 확대 **전에** 닫아 둔 것들이다. 이 확대가 그 사이클의 수혜자다.

| 계약 | 내용 | 이 확대에 주는 효과 |
|---|---|---|
| **C-1** | 도해 글자 크기 = viewBox 절대 단위, 본문 토글 미연동 | 230모듈에서 글자 단위를 재검토할 필요가 없다 |
| **C-2** | **표 병치가 원칙**, `altTable`은 표를 실제로 대체할 때만 | **자수 문제가 사라진다** — 표를 지우지 않으면 자수 ±0이라 `first-semiconductor`처럼 `baseline.md`(자수 고정값)를 자료원마다 만들 필요가 없다. 현재 `baseline.md`는 `first-semiconductor` 것 하나뿐이다 |
| T1/T2/T3 판정 | `usage.md` §1 — T3(`ValueBars`·`ScaleRuler`)는 조건부 | 배정 기준을 새로 세우지 않는다 |
| `idPrefix` 규약 | `LayerStack`·`NodeGraph` 2종만 필수, 모듈 슬러그 사용 | 그대로 승계 |
| 원문 근거 규약 | 원문에 없는 값을 만들지 않는다(`usage.md` §2.1) | **가장 중요** — 기준선에서 이 규칙이 9건을 되돌렸다 |

### 4.2 웨이브마다 반복할 절차

1. **Step 0 전수 배치 매핑** — 모듈마다 ⓐ컴포넌트 ⓑ데이터 출처(원문 줄 번호) ⓒ이 그림이 없으면 무엇을 못 읽는가. 선행 두 사이클에서 가장 어려웠던 단계다.
2. **파일럿 게이트** — 웨이브의 3~5모듈을 먼저 완성해 시각 언어·자수·렌더를 확인한 뒤 확대한다.
3. **병렬 배치 제작** — 자료원·대단원 단위로 쪼갠다.
4. **게이트 전수** — §6 NFR.

### 4.3 선행 사이클 교훈의 적용 (필수)

세 사이클이 같은 실패를 반복했다. 이 확대는 규모가 커서 반복하면 비용이 크다.

| 교훈 | 출처 | 이 계획의 적용 |
|---|---|---|
| **자기 검증 스크립트를 믿지 말 것** | `diagram-set-finishing` §4 — props 대조 스크립트가 "불일치 0"을 냈으나 실제 7행 불일치. `first-semiconductor-primer`는 자기 검증 4번 실패 | 판정 스크립트에 **의도적으로 틀린 입력(양성 대조군)을 함께 넣어 스크립트를 먼저 검증**한다. 이것이 세 번째 사이클에 걸친 미해결 백로그다 |
| **DoD를 검증 매트릭스에 1:1로 올릴 것** | `diagram-set-finishing` — DoD 7항목 중 1항목이 매트릭스에 없어 Match Rate 97.3%가 미이행을 가리지 못했고 Report 단계에서야 발견 | 각 웨이브 Design의 검증 매트릭스는 **DoD 각 항목을 1:1 항목으로 포함**한다 |
| **규칙 문장의 복제를 추적할 것** | `diagram-set-finishing` M-3 — 같은 규칙이 두 문서에 복제돼 한쪽만 정정 | 문서 정정 시 **문장이 아니라 규칙 단위로 검색**한다 |
| **배치표 미이행을 0으로 셀 것** | `diagram-component-set` — 배치표 12건 중 5건을 정정으로 처리 | Step 0 배치표와 실제 적용을 웨이브 Check에서 **전수 대조** |
