### 1.3 Value Delivered (4-Perspective)

| 관점 | 내용 |
|------|------|
| **Problem (문제)** | 학술 원본 보기 UI를 열어도 "원본 자료에서 해당 페이지를 참고하세요." 한 줄만 나오는 챕터가 17개 중 17개. SourceQuote 인용도 챕터당 1~3개로 부족해 쉬운 설명만 읽고 끝나는 패턴 발생. 사용자가 학술서 원문과 함께 공부할 수 있는 핵심 가치가 무력화됨. |
| **Solution (해결)** | (1) `LayeredExplain` 컴포넌트의 fallback 제거 — `deep.quote`가 없으면 Disclosure 자체를 렌더링하지 않도록 변경. (2) 17개 챕터의 LayeredExplain `deep` 전부에 책 원문 발췌 추가 (각 100~180자, fair use). (3) 챕터당 SourceQuote 2~4개 추가 — 핵심 개념·정의·결론 부분 우선 인용. (4) Ch.1부터 순차 진행해 사용자가 도입부부터 풍부함을 체감하도록. |
| **Function UX Effect (기능 효과)** | (1) 모든 챕터에서 LayeredExplain의 "학술 원본 보기"가 클릭 시 실제 원문을 펼침 — placeholder 박스 사라짐. (2) 쉬운 설명(amber 박스) ↔ 원문(disclosure)을 같은 카드 안에서 비교 학습 가능. (3) 챕터 본문 중간중간에도 SourceQuote가 추가돼 정의·표·결론을 원문으로 확인. (4) Disclosure는 기본 닫힘 상태 유지 — 처음엔 쉬운 설명만 보이고, 학습자가 원하는 순간 펼침. |
| **Core Value (핵심 가치)** | **"쉽게 풀어쓴 설명 + 원문 병독 가능"** — 본 사이트의 핵심 가치 회복. 학술서를 한 번에 통째로 읽기는 어려운 사용자가 사이트의 친절한 해설을 따라가다가, 원하는 지점에서 원문을 한 줄 클릭으로 확인할 수 있게 됨. "공부하는 사람을 위한 진짜 학습 도구"라는 정체성 확립. |

## 2. 작업 정의

### 2.1 컴포넌트 변경 — `LayeredExplain.tsx`

#### 현재 동작 (문제)

```tsx
{deep && (deep.quote || deep.sourcePage) && (
  <Disclosure title={`📖 학술 원본 보기 ...`}>
    {deep.quote ?? (
      <p className="text-sm text-slate-600 dark:text-slate-400">
        원본 자료에서 해당 페이지를 참고하세요.   {/* ← 이게 문제 */}
      </p>
    )}
  </Disclosure>
)}
```

#### 목표 동작

```tsx
{deep && deep.quote && (              // ← quote 있을 때만 렌더
  <Disclosure title={`📖 학술 원본 보기 (p.${deep.sourcePage}) — ${deep.sourceSection}`}>
    <blockquote className="border-l-4 border-brand-400 pl-4 italic">
      {deep.quote}
    </blockquote>
    {deep.sourcePage && (
      <p className="mt-2 text-xs text-slate-500">— 「반도체 산업의 유해인자」 p.{deep.sourcePage}</p>
    )}
  </Disclosure>
)}
```

**원칙**: 인용문이 없는데 "참고하세요"만 띄우는 것은 효용 0. 차라리 안 보여주는 게 낫다.

### 2.3 챕터별 SourceQuote 추가

현재 챕터당 1~3개인 인용을 **4~6개로 확장**. 우선순위:

| 우선순위 | 인용 대상 | 이유 |
|---------|---------|------|
| ★★★ | 핵심 정의 (clean room, 도핑, 확산, etc.) | 학습자가 정확한 표현 확인 필요 |
| ★★★ | 결론·주장 (위험성 평가, 산업보건 시각) | 책 저자의 의견은 요약 불가 |

| ★★ | 역사적 사례 (석면, 라돈 etc.) | 원문 표현의 무게감 |
| ★ | 보조 설명 | 챕터당 4~6개 한도 내에서 |

## 4. 성공 기준 (Acceptance Criteria)

| 번호 | 기준 | 측정 방법 |
|------|------|---------|
| AC-1 | placeholder 문구가 사이트 어디에도 나타나지 않는다 | grep 검색 |
| AC-2 | 모든 챕터의 LayeredExplain은 원문 인용이 채워져 있다 | 17/17 |
| AC-3 | 각 챕터에 SourceQuote가 4개 이상이다 | grep 카운트 |
| AC-4 | SourceQuote는 책의 fair use 한도 내(각 ≤200자) | 각 인용 확인 |
| AC-5 | LayeredExplain의 빈 deep도 안전하게 처리됨 (혹시 남으면 렌더 안 함) | 컴포넌트 로직 확인 |
| AC-6 | 빌드 통과 + 기존 챕터 깨짐 없음 | `npm run build` |

| AC-8 | 인용 텍스트 스타일이 blockquote + 출처 표기로 구분됨 | 시각 확인 |

## 5. 위험 요소 & 대응

| 위험 | 대응 |
|------|------|
| 책 원문 발췌가 fair use 범위를 넘음 | 각 인용 150~200자 이내로 제한. 인용은 핵심 한두 문장만. |
| 17개 챕터 일괄 작업 시간 부족 | Ch.1을 먼저 완료하고 사용자 피드백 받은 후 Ch.2~17 진행. 단계 배치 가능. |
| 원문 정확성 (OCR 오류 가능) | data/*.md 파일에서 grep으로 확인 후 인용. 의심되면 책 페이지와 비교. |
| Disclosure가 너무 많아 페이지 길이 증가 | Disclosure는 기본 닫힘이므로 펼치기 전 길이는 동일. |
| 기존 LayeredExplain 사용처가 컴포넌트 변경으로 깨짐 | placeholder는 항상 안 좋은 UX였으므로 제거가 안전. 기존 동작 회귀 없음. |
