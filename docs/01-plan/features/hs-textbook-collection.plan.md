# Plan — 반도체 고등학교 교과서 카테고리 & 교과서 자료원 8권 확장

> **Feature**: `hs-textbook-collection`
> **작성일**: 2026-07-16 · **Level**: Dynamic · **Cycle 유형**: 카테고리 인프라 신설 + 신규 자료원 로드맵 (umbrella plan)
> **상속**: `daegu-hs-textbook`(교과서 자료원 패턴 원형 — 이하 **"daegu 방식"**) · `multi-source-learning-platform`(Source 레지스트리·라우팅) · `cross-link-system`(통제 어휘) · `ncs-semiconductor`(트랙 그룹핑 선례)
> **사용자 요청 원문**: "현재 업로드된 반도체공정기초를 포함하여 이 폴더(`data/school-text`)에 있는 자료들을 **반도체고등학교교과서**라는 카테고리로 묶어서 관리하고, 각자의 폴더들을 반도체공정기초 페이지를 만들었던 동일한 방식으로 제작"

## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem (문제)** | `data/school-text/`에 반도체고 교과서 8권(OCR 합계 약 46,700줄, daegu 1권의 약 12배 분량)이 추출되어 있으나 사이트에 전혀 반영되지 않았다. 기존 「반도체 공정기초」(`daegu-hs-process`)는 자료원 4개 중 하나로 개별 노출될 뿐 "고교 교과서"라는 묶음 개념이 없고, 교과서가 9권으로 늘면 홈 자료원 카드가 12장 flat 나열되어 선택 UX가 무너진다. |
| **Solution (해법)** | **"반도체 고등학교 교과서" 카테고리**(`SourceCategory`)를 신설해 기존 공정기초 + 신규 8권을 한 묶음으로 관리하고, 각 권을 daegu 방식 그대로 자료원화한다(권=Source, 대단원=트랙 `group`, 중단원=모듈 MDX, 3단 레이어 전면 재작성, 원문 이미지 0, 원저자·발행처 표기). 신규 권은 **공용 `[module]` 라우트 + 통합 로더**로 소스별 라우트 복제 비용을 없앤다. 이번 사이클은 카테고리 인프라 + 파일럿 1권, 나머지 7권은 권별 후속 사이클 로드맵으로 진행. |
| **Function·UX Effect (기능·UX 효과)** | 홈 "자료원 선택"에 **반도체 고등학교 교과서 그룹 섹션**이 생기고 그 안에 교과서 카드가 권 단위로 정렬된다. 각 권은 `/sources/{id}/` 인덱스(대단원 트랙 그룹) + 모듈 페이지(3단 레이어, 이전/다음 내비, cross-link)로 탐색 — 학생이 자기 학교 교과서를 골라 단원 순서 그대로 학습한다. |
| **Core Value (핵심 가치)** | 반도체고 실제 교과 과정 전체(전기·전자 기초 → 소자 → 공정 → 장비 → 후공정 → 인프라·안전)가 사이트와 1:1로 맞물린다. 특정 1권의 보조자료를 넘어 **"반도체고 전 교과 학습 플랫폼"** 으로 확장하는 골격이 이 사이클에서 완성된다. |

- 원문 이미지는 전 권 저작권상 **전면 미사용**(daegu 원칙).

### 1.2 daegu 방식 — "동일한 방식"의 정의 (이번 로드맵의 권당 표준 패턴)

`daegu-hs-textbook` 사이클(2026-07-14, Match Rate 96%)에서 확립:

1. **Source 등록**: `src/lib/sources.ts`에 `kind: 'textbook'`, `accent: 'school'`, `license: 'fair-use'`, attribution(원저자·발행처) 명시. 대단원=`SourceSection.group`(트랙), 중단원=section(모듈). **등록 순서 = 교과서 목차 순서 = 이전/다음 내비 순서**.
2. **라우팅**: `/sources/{id}/` 인덱스(공용 `[source]/page.tsx`가 자동 처리) + `/sources/{id}/{module}/` 모듈 페이지(SSG, `generateStaticParams`).
3. **MDX 콘텐츠**: `src/content/sources/{id}/{module}.mdx` — 3단 레이어(Hook→Easy→Deep) 전면 재작성, 원문 문장·이미지 미사용, 수치·정의만 보존, 페이지 내 출처 표기.
4. **cross-link**: `src/content/sources/{id}/_links.json` 통제 어휘(Topic/Hazard/Chemical) 태깅 → 책·OSHA·NCS·기존 Process와 자동 상호 연결(스크립트가 glob 자동 발견, 무수정).
5. **완성 모듈만 sections 등록**(미완성 모듈 등록 시 SSG notFound로 빌드 실패) — 파일럿 모듈 → 목차 순서 확대.

### 1.3 현재 아키텍처와 이번 확장의 충돌 지점

| 요소 | 현황 | 9권 확장 시 문제 |
|---|---|---|
| `SOURCES` 레지스트리 | 4개(책·OSHA·NCS·daegu) flat | 12개로 증가 — **카테고리 개념 부재** |
| 홈 `SourcePicker` | 카드 4장 flat grid, 카피 "네 가지 자료원이 각각 원리·위험·안전·직무를 맡아요" | 12장 flat 나열 시 선택 UX 붕괴, 카피 falso |
| `PERSPECTIVE` 뱃지 | source id별 하드코딩 4건 | 교과서 9권의 관점 뱃지 체계 필요 |
| 모듈 라우트 | 소스별 디렉터리 복제(`daegu-hs-process/[module]`, `ncs-semi/[module]`, `osha-scs/[part]`) + 소스별 로더(`daeguMdx.tsx` 등) | 8권 복제 시 라우트 8개 + 로더 8개 — 보일러플레이트 과다 |
| 빌드 스크립트 | `build-cross-link`는 `_links.json` glob 자동 발견 · `extract-quotes`는 챕터+OSHA 전용(daegu 미포함 선례) | **양쪽 다 무수정** (교과서 MDX는 인용 인덱스 비대상 — daegu 선례 유지) |
| 배포 | Vercel + 로그인 게이트(middleware, `site-login-gate` 이후 `output:'export'` 아님) | 신규 라우트는 여전히 `generateStaticParams` SSG — 영향 없음 |

## 3. IA 설계 — 카테고리 모델 & 라우트 아키텍처

### 3.1 카테고리 데이터 모델 (제안)

`src/lib/types.ts`에 카테고리 개념 추가:

```ts
export type SourceCategory = 'hs-textbook';
export const SOURCE_CATEGORY_LABELS: Record<SourceCategory, string> = {
  'hs-textbook': '반도체 고등학교 교과서',
};
// Source에 category?: SourceCategory 필드 추가 (미지정 = 독립 자료원)
```

- daegu 포함 교과서 9권에 `category: 'hs-textbook'` 태깅. 책·OSHA·NCS는 미지정(기존 그대로).
- `kind: 'textbook'`과의 관계: kind는 자료 유형(라벨 "교과서"·단위어 "단원"), category는 **묶음 관리 단위**. 유형은 같지만 다른 묶음이 미래에 올 수 있어 분리 유지.

### 3.2 홈 UI 그룹핑 — ✅ A안 확정 (2026-07-16, 사용자 선택)

- **✅ A안 — 홈 그룹 섹션**: `SourcePicker`가 카테고리 없는 소스(책·OSHA·NCS)는 기존 카드 그대로, `hs-textbook` 카테고리는 "반도체 고등학교 교과서" 헤더를 단 **묶음 섹션**으로 렌더(권 카드는 컴팩트하게 3열 등 — Design 확정). 클릭 깊이 불변, 홈에서 전 권이 바로 보임.
- 기각: B안 허브 페이지(`/sources/hs-textbooks/`) — 클릭 깊이 +1, 허브 신규 제작 필요로 기각.
- 공통: 홈 카피 "네 가지 자료원…" 문구를 카테고리 체계에 맞게 갱신, `PERSPECTIVE` 뱃지는 교과서 카테고리 공통 뱃지("교과 — 학교에서 배우는 그대로" 등, Design 확정)로 대응.
- 미등록 권(콘텐츠 준비 전)을 "준비 중" 카드로 노출할지는 Design에서 결정(로드맵 가시화 vs 빈 껍데기 회피).

### 3.3 라우트/로더 아키텍처 — 결정 필요 (§9-1과 함께)

- **A안 (권장) — 공용 동적 라우트**: `src/app/sources/[source]/[module]/page.tsx` 1개 + 통합 로더 `src/lib/schoolTextMdx.tsx`(source→module 2단 레지스트리). Next.js는 정적 세그먼트 우선이므로 기존 3개 특정 라우트(daegu·NCS·OSHA)는 **무수정 공존**. 신규 권 추가 비용 = MDX + 로더 1줄 + sections 등록.
- **B안 — daegu 패턴 복제**: 권마다 `src/app/sources/{id}/[module]/page.tsx` + `{x}Mdx.tsx` 생성(총 16파일). 선례와 완전 동일하나 보일러플레이트 8배.
- A안 채택 시 daegu 라우트의 공용 라우트 이관(코드 통합)은 **비목표** — 기존 URL·코드 무수정 원칙 우선, 통합은 별도 리팩터 사이클.

## 4. 콘텐츠 재구성 전략 — daegu 원칙 전 권 승계

- **전면 재작성**: 원문 문장 구조·표현 재사용 금지, 개념·수치·절차만 근거로 3단 레이어(Hook→Easy→Deep) 재작성. 원문 이미지(권당 240~650개) 전면 미사용, 필요한 다이어그램은 자체 제작.
- **출처 표기**: 페이지 하단 "참고: 「{제목}」 ({저자·발행처})" — daegu 표기 패턴 승계. 저자 OCR 미확인 권은 발행처만 표기(권별 사이클에서 판권 재확인).
- **용어·수치**: `terms.json`과 일관 유지(충돌 시 기존 우선), 정의·수치는 보존하되 문장은 새로.
- **중복 주제 차별화**: 교과서 모듈은 "단원 학습 흐름(학습목표→개념→핵심정리)" 각도, 기존 Process/daegu 페이지와는 cross-link로 상호 연결(daegu §3 확정 원칙 재사용).

### 발행처별 저작권 리스크

| 발행처 | 권수 | 성격 | 리스크 | 방침 |
|---|---|---|---|---|
| 렛유인 | 1 (+기존 1) | 사설 교육기업 상업 출판 | 높음 | daegu 확정 정책 그대로(전면 재작성+출처 표기) |
| 크리아트 | 2 | 교과서 전문 출판사(인정교과서 추정) | 높음 (이용허락 미확인) | 동일 보수 원칙 |
| 에이치앤지 | 3 | "2015 개정 교육과정" 인정교과서 추정 | 높음 (이용허락 미확인) | 동일 보수 원칙 |
| 충남반도체고 | 1 | 학교 개발 교재 추정 | 중간 (비상업적이나 미확인) | 동일 보수 원칙 |

### 5.2 파일럿 권 — ✅ A안 확정 (2026-07-16, 사용자 선택): **반도체 기초 (렛유인)**

- daegu 「반도체 공정기초」와 같은 발행처·같은 시리즈(공정기초의 선행편: 개념·산업·소자). 확정된 저작권 정책·문체 톤을 그대로 승계해 파일럿 리스크 최소, 분량도 최소(4,056줄). 학습 위계상 공정기초 앞에 놓여 "기초→공정" 동선 완성.
- 기각: B안 인프라 일반(서울시교육청) — 저작권 부담은 최소지만 발행 주체 성격이 달라 daegu 정책 승계 실증으로 약해 기각. 로드맵 P7 유지.
