# Gap 분석 — 자체 도해 컴포넌트 세트

> **Feature**: `diagram-component-set` · **분석일**: 2026-08-10 · **Level**: Dynamic
> **Design**: `docs/02-design/features/diagram-component-set.design.md`
> **Plan**: `docs/01-plan/features/diagram-component-set.plan.md`
> **분석 방법**: `gap-detector` 에이전트 + 오케스트레이터 재검증 (지적 4건을 파일로 직접 대조)

---

## 0. 요약

```text
┌──────────────────────────────────────────────────────────────┐
│  1차 측정  Match Rate 78.1%  (212 검증항목 중 165.5)          │
│  Act 반영  Match Rate 93.6%  (212 검증항목 중 198.5)  ← 게이트 통과 │
│  Gap: High 4 → 1 잔존 (G-1·G-3 육안) · Medium 3 → 1 · Low 4 → 3 │
└──────────────────────────────────────────────────────────────┘
```

> **이 문서는 1차 측정(78.1%) 기록이며, §7에 Act 반영 결과를 덧붙였다.** 사용자 결정은 "보조를 채운다"였고, 그에 따라 Gap-1·Gap-2·Gap-7이 해소됐다.

구현 자체의 품질은 높다 — 12종 전부 서버 컴포넌트로 **번들 증가 0**, 97모듈 전부에 도해가 들어갔고 `typecheck`·`lint` 무오류다. 점수를 끌어내린 것은 **문서와 실제의 어긋남**이다: Design §1.2 배치표가 계획한 133 인스턴스 중 107만 구현됐고, 그중 11모듈은 계획과 **다른 컴포넌트**가 들어갔는데 배치표가 정정되지 않았다.

즉 이 사이클의 Gap은 "구현이 부족하다"기보다 **"구현이 설계를 앞질러 갔고 설계 문서가 따라오지 않았다"**에 가깝다.

## 2. Gap 목록

### Gap-1 (High) — 보조 도해 26건 미적용

**기준**: Design §1.2 배치표 (주 97 + 보조 36 = 133)
**실측**: 107 인스턴스 = 주 97 + 추가 10

| 보조 컴포넌트 | 빠진 모듈 | 수 |
|---|---|--:|
| `LayerStack` | 018 · 040 · 060 · 061 · 062 · 066 | 6 |
| `NodeGraph` | 028 · 030 · 031 · 045 · 049 | 5 |
| `CompareCards` | 004 · 047 · 067 · 085 · 088 | 5 |
| `CurvePlot` | 011 · 022 · 041 | 3 |
| `ValueBars` | 078 · 087 | 2 |
| `Timeline`·`TreeBranch`·`FlowSteps`·`ScaleRuler`·`LatticeDiagram` | col-3 · 042 · 052 · 082 · 079 | 5 |
| | **합계** | **26** |

**주의할 집계 함정**: "추가 10"과 "계획된 보조 10"은 다른 수다. 실제 내역은 계획된 보조 4건(017 `CurvePlot`·019 `NodeGraph`·029 `NodeGraph`·063 `LayerStack`) + 004 `LatticeDiagram` 3연의 여분 2 + **계획에 없던 추가 4건**(003·013 `ValueBars`, 031 `TruthTable` 2번째, 058 `LayerStack` 2번째)이다. 두 수가 우연히 10으로 같아 오독하기 쉽다.

**영향**: `CurvePlot`은 3건이 빠져 97모듈 통틀어 **017 단 1회**만 쓰인다 — 컴포넌트 1종을 만들어 1회 쓴 셈이다.

### Gap-2 (High) — 주 도해 11모듈이 배치표와 다른 컴포넌트

**기준**: Design §1.2 · §8.2("배치표와 실제 MDX 대조 — 어긋나면 배치표를 정정하거나 MDX를 고친다")
**실측**: 주 도해 일치 **86/97 = 88.7%**

| 모듈 | 배치표 | 실제 |
|---|---|---|
| 014 | `LayerStack` | `ValueBars` |
| 025 · 050 | `Timeline` | `ValueBars` · `ScaleRuler` |
| 065 | `CompareCards` | `LayerStack` |
| 070 · 073 | `FlowSteps` | `NodeGraph` |
| 071 · 074 | `FlowSteps` | `ScaleRuler` · `CompareCards` |
| 079 | `CompareCards`(+`LatticeDiagram`) | `ValueBars` |
| col-4 · col-6 | `CompareCards` | `TreeBranch` |

**성격**: 내용상 대체가 타당한 건이 많다 — col-4는 계층 파라미터라 `TreeBranch`가 맞고, 079는 원서가 35%/90% 두 수치만 제시해 `ValueBars`가 자연스럽다. **문제는 §8.2가 요구한 대조가 수행되지 않아 §1.2가 11군데 거짓 기술로 남았다는 점**이다.

> 주의: 003·019는 계획 컴포넌트가 **존재하되 등장 순서만 다르다**. "첫 등장" 기준으로 세면 13건이 되지만 실제 부재는 11건이다(재검증 완료).

### Gap-3 (High) — FR-8 표 대체 텍스트 8/97

**기준**: Plan FR-8 "도해별 표 대체 텍스트 제공" · Design §4
**실측**: `altTable` **9 인스턴스 / 8 모듈** (001·002·010·013·017·018·019·029) = 인스턴스 기준 8.4%

**완화 요인**: 대부분의 모듈은 표를 지우지 않고 도해와 **병치**했다(`030-and-gate.mdx:44~61`이 전형). 전체 diff가 `1726 insertions / 54 deletions`인 것이 이를 뒷받침한다 — **정보 손실은 없다**.

**부수 문제**: 선행 사이클 §5.1에 추가한 자수 예외 문안이 근거로 *"`altTable`에 동일 정보가 남으므로"*를 들었는데, **실제 메커니즘은 "본문 표 유지"**다. 근거 문장과 실제가 어긋난다.

### Gap-4 (High) — 게이트 G-1·G-3 육안 미확인

**기준**: Design §8.1
**상황**: 로그인 게이트(`middleware.ts` 세션 쿠키)와 Chrome 확장 미연결로 실렌더 확인 불가. 오케스트레이터가 자격증명을 입력할 수 없다.

**정적 대체 검증 결과** (전부 파일 확인):

| 항목 | 결과 |
|---|---|
| 하드코딩 색 (16진·rgb) | **0건** — 전부 Tailwind 유틸 |
| `dark:` 대응 | 1건 누락 → **Check 중 수정** (§3) |
| 본문 가로 스크롤 경로 | 넓은 도해 5종 `overflow-x-auto`, `CompareCards` 모바일 카드 스택, `FlowSteps` `sm:flex-row` — **구조상 발생 경로 없음** |
| 시각 언어 일관 | 12종이 `DIM`·`STROKE`·`TEXT`·`CARD` 공유 확인 (예외 2건은 Gap-8) |
| G-7 SVG id 충돌 | `idPrefix` 31건이 인스턴스 31개와 정확히 일치, 019·058 한 페이지 2개도 충돌 없음 — **정적 통과** |

**잔여**: 라이트/다크 실렌더와 5모듈 나란히 대조는 사람 확인이 필요하다.

### Gap-5 (Medium) — props 6건이 §2.2와 불일치

| 컴포넌트 | Design §2.2 | 구현 | 성격 |

| `Timeline` | `span?` · `year` 수치 | `span` 없음 · `year: string` | `year` 문자열화는 `usage.md`에 의도로 명문화(`'이후'` 표기) / `span`은 미구현 |
| `TruthTable` | `highlight?: (row) => boolean` | `highlight?: Bit \| null` | 단순화 |

### Gap-6 (Medium) — §3.2 상대 단위 글자 크기 미이행

**기준**: Design §3.2 "SVG `<text>`는 `0.8em` 같은 상대 단위를 쓰고 CSS로 크기를 준다"
**실측**: `tokens.ts`가 `font: 13`을 **viewBox 절대 좌표**로 두고 6종이 하드코딩. `DiagramFrame`의 `not-prose`가 `globals.css`의 `.font-sm/md/lg .prose` 규칙을 차단.

**영향**: `FontSizeToggle`을 키워도 도해 라벨은 그대로여서 본문과 비율이 어긋난다. 다만 viewBox 스케일 안에서 `em`을 쓰면 도해 폭과 글자 크기가 따로 놀아 레이아웃이 깨지는 문제가 있어, **구현 시 의도적으로 절대값을 택했으나 그 판단을 Design에 정정 기록하지 않았다**.

### Gap-7 (Medium) — 배치 의도 미실현 1건

088에 `ValueBars`(양방향)를 배정했으나 `direction="diverging"`을 넘기지 않아 "한쪽은 올리고 한쪽은 내린다"는 배정 의도가 시각적으로 드러나지 않는다. (Gap-5의 dead code와 같은 뿌리 — 코드는 §3에서 수정했고 MDX 적용은 Act 대상.)
