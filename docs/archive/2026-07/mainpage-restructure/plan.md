## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem (문제)** | 현재 홈 IA는 2026-07-14 `homepage-learning-hub` 작업에서 **"4개 자료원"** 기준으로 설계됐다. 그러나 이후 고교 교과서가 계속 추가되어 지금은 **자료원 11개**(학술서·OSHA·NCS 3종 + 고교 교과서 **8종**)로 성장했다. 홈 구조는 이 성장을 따라오지 못했다 — ① `PlatformHero`가 **"4개 자료원"을 하드코딩**(실측 11개)하고, ② `LearningPathSection`의 4단계 동선은 관점당 자료원 1개씩만 링크해 **교과서 8종 중 hs-semicon-basics 1종만 노출**(나머지 7종은 SourcePicker 군집으로만 도달), ③ `SourcePicker`("어느 자료부터?")와 `LearningPathSection`("이렇게 시작해")이 **역할이 겹치는 두 개의 라우팅 장치**로 스크롤만 길어진다. 결과적으로 첫 화면이 늘어난 콘텐츠를 담아내지 못한다. |
| **Solution (해법)** | 홈 **본문 IA를 재배치**한다: (권장) 상단에 **역할별 퀵-진입 스트립**(진로 준비·수업 보조·교양)을 개인화 없는 **앵커 스크롤** 방식으로 추가하고, 본문은 **관점(원리·위험·안전·직무)으로 자료원을 군집화**해 교과서 8종을 모두 노출하며, 중복된 두 라우팅 장치를 **역할 분담**(SourcePicker=전체 카탈로그 / 관점 군집=목적별 진입)으로 정리한다. 콘텐츠 페이지·URL·데이터 파이프라인은 무수정. |
| **Function·UX Effect (기능·UX 효과)** | 첫 화면에서 "나는 무엇을 하러 왔는가"(진로/수업/교양)에 맞는 진입점이 즉시 보이고, 8개 교과서를 포함한 자료원 전체가 관점별로 발견 가능해진다. 중복 라우팅 통합으로 스크롤 길이가 줄고, 하드코딩 수치(4개)가 코드 파생 실값으로 교정된다. |
| **Core Value (핵심 가치)** | 성장한 콘텐츠(11자료원)와 홈 첫인상의 **재정렬** — `homepage-learning-hub`가 세운 "각자 목적에 맞는 자료로 30초 안에 도달" 목표를, 자료원이 늘어난 현 시점에도 실제로 달성하는 학습 관문으로 갱신. |

## 2. 목표 / 비목표

### 목표
- 홈 첫 화면~본문 IA를 **11개 자료원 규모**에 맞게 재배치.
- **역할별 진입점**을 첫 화면에 노출(진로·수업·교양 등) — 정적·앵커 기반, 개인화·분기 페이지 없음.
- 교과서 8종 전체가 홈 동선에서 **발견 가능**하도록 관점별 군집화.
- 중복 라우팅 장치(SourcePicker vs LearningPath) **역할 분담**으로 정리, 스크롤 길이 축소.
- 하드코딩 수치("4개 자료원") → **코드 파생 실값**으로 교정.

### 비목표 (이번 사이클 제외)
- URL·라우팅 구조 변경 (모든 기존 경로 유지 — SEO·북마크 보존).
- 자료원 상세/콘텐츠 페이지(`/chapter/*`, `/sources/*`, `/process/*` 등) 수정.
- 신규 콘텐츠 집필, 검색 기능 신설, 개인화·로그인 기반 추천, 다국어 홈.
- 사이트명·로고 교체, 색·타이포 등 **비주얼 리뉴얼**(이번은 IA·동선 한정 — 별도 사이클).
- 데이터 파이프라인·`quotes.json`·`cross-link.json` 변경.

## 3. IA 재배치 설계 — 권장안 + 대안

> **핵심 결정(진입 기준)은 §9-1에서 사용자 확인 대기 중.** 아래 권장안은 그 확인 전 기본 제안이다.

### 권장: **A안 — 역할 퀵-진입 + 관점 군집(하이브리드)**

```text
1. PlatformHero (문구·수치만 갱신)
   - "4개 자료원" 하드코딩 → SOURCES.length 파생값
   - "네 가지 관점" 서사는 유지 (관점=4, 자료원=11 구분해 표기)

2. RoleQuickEntry (신규, 얇은 스트립)
   "무엇을 하러 오셨나요?" — [진로 준비][수업·교사][교양·입문] 3~4개 pill
   → 클릭 시 해당 관점 군집으로 앵커 스크롤 (새 페이지·분기 없음)

3. 관점별 자료원 군집 (LearningPathSection 확장 재설계)
   원리 → 교과서 8종(대표 + "8종 전체 보기")
   위험 → 학술서 17챕터
   안전 → OSHA 5파트
   직무 → NCS 트랙
   ※ 관점당 자료원 1개 제약 해소, 교과서 전체 노출

4. SourcePicker (역할 재정의: '전체 카탈로그')
   "자료원 전체 보기"로 문구 조정, 본문 군집과 중복 아닌 카탈로그로 하단 배치

5. SpecialSection(공정) — 유지 (횡단 도구)
6. SpecialSection(유해물질·직업병) — 유지 (횡단 도구)
7. FooterLinks — 유지
```

- 장점: 성장한 교과서 전부 노출, 역할별 진입으로 원 목표(30초 도달) 실현, 중복 라우팅 해소, 변경 범위 홈+홈 전용 컴포넌트에 국한.
- 단점: 신규 컴포넌트 1~2개(RoleQuickEntry·관점 군집), 홈 섹션 재설계로 Design 비용 증가.
- 주의: 2026-07-14 플랜은 "학습자 유형 **분기형 홈**"(별도 페이지·클릭 부담)을 기각했다. 본 A안은 **분기 페이지 없이 앵커 스크롤**만 쓰므로 그 기각 사유(개인화 없는 분기의 클릭 부담)를 피한다.

### 대안 B: 관점 군집만 재설계 (역할 스트립 없음)
LearningPathSection을 관점당 다-자료원 군집으로만 바꾸고 역할 진입은 생략. 변경 최소·교과서 노출 문제는 해결하나, "목적별 진입" 목표는 미달.

### 대안 C: SourcePicker/LearningPath 통합 단일 섹션
두 섹션을 하나로 합쳐 스크롤만 줄임. 가장 보수적이나 역할별 진입 부재·프레이밍 개선 없음.

**→ A안을 기본 골격으로 제안**, 진입 기준(§9-1) 확정 후 Design에서 섹션 계약 확정.
