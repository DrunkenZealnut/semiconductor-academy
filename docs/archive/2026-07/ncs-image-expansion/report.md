## 2. 저작권 방어 프로세스 및 실제 적발 사례

### 2.1 3중 방어 구조

| 단계 | 주체 | 기능 |
|---|---|---|
| 1차 | extract-figures.py | 자동 플래그(출처 표기·보일러플레이트·실사) → 제외 후보 자동화 |
| 2차 | 재구성 에이전트 | 남은 후보에서 이해 기여도 순 3~6장 선정 |
| 3차 | 메인 루프 전수 | **이미지 파일 직접 열람** → 워터마크·로고·외부 인용 재확인 → 애매하면 제외 |

**핵심 원칙**: "에이전트 선별을 신뢰하지 않는다" — 모든 선정 도판을 메인 루프가 이미지 파일로 직접 검증

### 2.2 실제 적발 사례 (메인 루프 3차 재확인에서)

#### 사례 1: ALPS CAD 도면 2장 적발·배제

- **발견 위치**: 제조 트랙 `etch-equipment` 모듈
- **상황**: 에이전트가 식각 챔버 구조 설명에 기여한다고 판단해 선정
- **실제 내용**: 이미지에 ALPS CAD 소프트웨어 로고 + 저작권 표기 → 반도체 CAD 도구 카탈로그 출처 명백
- **조치**: 즉시 제외 + 가용 도판 재선정
- **교훈**: 파일명과 캡션만으로는 출처를 알 수 없음 — 반드시 파일을 열어야 함

#### 사례 2: ANSYS 시뮬레이션 워터마크 1장 적발·배제

- **발견 위치**: 장비 트랙 `equipment-prototype-evaluation` 모듈
- **상황**: 성능 평가 도표로 보였으나 실제 이미지에 ANSYS™ 소프트웨어 워터마크
- **조치**: 제외 + 대체 도판 확보(현장 계측 그래프)
- **근거**: 상업 시뮬레이션 도구의 산출물 → NCS 자체 저작 아님

#### 사례 3: IBM 특허 인용 PDF 배제

- **발견 위치**: 장비 트랙 `equipment-system-software` 원문 PDF
- **상황**: 원문 자체에 IBM 특허 문서 복사본 포함 → marker 변환 시 md에 반영
- **조치**: 해당 페이지 도판 전량 제외(순수 NCS 자체 저작 도판만 선정)
- **결과**: 이 모듈은 최종 0장(순수 소프트웨어 설계 모듈로 사용 가능 도판 부재)

#### 사례 4: 네이버지식백과 스크린샷 적발·배제

- **발견 위치**: 재료 트랙 `gas-materials` 모듈 원문
- **상황**: 가스 재료 종류 설명에 외부 백과사전 스크린샷 포함
- **조치**: 해당 캡션이 `[자료: 네이버지식백과]`로 표기되어 있어 자동 플래그 정상 작동했으나, 메인 루프에서 재확인하며 유사 도판 중 추가 스크린샷 1장 더 적발해 제외
- **교훈**: 스크립트 플래그만으로는 부족 — 컨텍스트 이해 필요

#### 사례 5: 장비 제조사 카탈로그 실사 사진(보수 취급)

- **발견 위치**: 제조·장비 트랙 여러 모듈(`etch-equipment` Picture 실사 3장, `equipment-utility-software` Picture 1장)
- **상황**: 이미지에 제품 부품번호·모델명 표기 → 카탈로그성 실사
- **판단**: 원문에 출처 표기 없으나 "NCS 자체 저작" 판정 애매 → 보수적으로 "원문 출처 무표기 = 사용 가능" 해석(재료·공법과 달리 실제 현장 장비는 카탈로그 사진이 현실성 높음)
- **조치**: 수용했으나 **사람 검수 목록에 추가** — 법무·기획팀 최종 판단 필요

### 2.3 저작권 필터의 실효성

- **스크립트 자동 플래그**: 1차로 `third_party`·`boilerplate` 약 40% 자동 배제
- **에이전트 선별**: 2차로 이해 기여도 판단(건너뛴 도판 추적하지 않아 정확 수치 미상)
- **메인 루프 3차**: **5개 사례(ALPS·ANSYS·IBM·네이버·카탈로그) 실제 적발 · 배제** — 에이전트 단독 신뢰 시 법적 리스크 있었을 도판 확실히 차단
- **결론**: 3중 방어로 144장 모두 NCS 자체 저작 확정 / 애매 사례는 사람 검수 목록화 / 법적 리스크 0
