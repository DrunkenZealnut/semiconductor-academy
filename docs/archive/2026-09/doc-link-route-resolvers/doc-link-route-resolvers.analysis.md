## 1. ★이 사이클이 배운 것 — 같은 실패의 **세 가지 층**

`exit 2` 계약 목록이 세 번 낡았고, **원인이 매번 달랐다.**

| # | 원인 | 고친 것 |
|:--:|---|---|
| 1·2차 | **편집 배치의 뒤 항목이 죽어 쓰기가 통째로 안 됐는데 ✅만 보고 넘어갔다** | **도구를 고쳤다** — 편집마다 즉시 쓰고 **다시 읽어 확인** |
| 3차 | **쓰기는 성공했고 손으로 센 열거가 불완전했다** — 같은 배치가 만든 자리 둘을 빠뜨렸고, *"`fail()`이 가는 자리 전부"* 라 적어 놓고 절반은 `fail()`이 아니었다 | **열거를 지웠다** |

> **도구를 고쳐도 손 열거는 안 고쳐진다.**
> 이 파일은 이미 상한 목록에서 *"손으로 세는 수는 다음에도 틀린다 — 목록만 남기면 틀릴 수가 없다"* 로
> 한 번 강등했는데 **목록도 틀렸다.** 다음 강등은 하나뿐이다 — **유도하거나 지운다.**

지금은 이렇게 적혀 있다:

```text
자리를 알고 싶으면 소스에게 물어라 —
  rg 'fail\(|process\.exit\(2\)' scripts/verify-doc-links.mjs
각 자리는 자기 사유 문자열을 들고 있고, 그것이 유일한 진실이다.
```

## 2. 치명 결함 — 지뢰를 거짓말로 바꿀 뻔했다

```text
norm.replace(/\[[^\]]+\]/, v)          ← 비전역
/sources/[source]/[module] + 'src-a/mod-a'  →  /sources/src-a/mod-a/[module]
```

**206건 전량이 쓰레기**였고, 진짜 링크는 집합에 없으니 `exit 2`(정직한 지뢰)가
**거짓 `exit 1`**("라우트가 `src/app`에 없다")이 된다 — **시작보다 나쁘다.**

**왜 조용했나**: `expanded`가 `values.length`를 찍어 출력엔 `→ 206`이 정직하게 나오고,
실제 저장소에 그런 링크가 0건이라 본 검사도 초록이었다. 그리고 대조군 `D-17`이
**브래킷 하나짜리** 템플릿을 써서 못 봤다 — **fixture의 모양이 판별력을 정한다.**

→ 다중 브래킷 **조립**(치환이 아니라) + **세그먼트 수 단언** + `D-20`(브래킷 둘)·`D-21`(수 불일치).

## 5. 상한 — 안 재는 것

| 자리 | 왜 |
|---|---|
| ★**`!DLG_CHILD`로 조건 지어진 자리들** | **구조적으로 관측 불가** — 자식을 `DLG_CHILD` 없이 돌리면 자체검사가 **재귀**한다. 둘: **본 검사 앞 게이트**(가장 값진 무보증 자리) · **죽은 키 검사의 `!DLG_CHILD ||` 분지**. 줄이려면 **조건을 없애야** 한다(자식 전부가 `tsx`를 띄우게 된다 — 비용을 재고 정할 일) |
| `tsx` 부재 가드 | **행동상 잉여** — 지워도 `spawnSync`가 ENOENT로 같은 `fail` 경로로 가고 D-19가 밟는다 |
| `TS_PROBE`가 앱 본문의 **필사본** | 가짜 트리 소유(Design §0.5)를 포기하지 않는 한 못 닫는다. **지금은 앱과 일치함을 확인했다** |
| 빈 세그먼트(`'a/'`) | 개수 단언을 통과해 매칭 불가 라우트를 조용히 만든다(실물 0건 · 코드 주석에 적었다) |
| catch-all `[...x]` | 등록하면 세그먼트 단언이 `exit 2`를 낸다(실물 0건). **성질이 바뀌었다** — 미등록이면 여전히 거짓 위반 |
| 선행 상한 전부 | `dieOnCrash` · 무리 이름 가드 · 갈래/출처 가드 · `CONTROLS` 대조 · 식별자 단언 둘 |

## 7. 남기는 문장

> **지뢰를 없애는 일이 거짓말을 만들 수 있다.**
> `exit 2`(정직하게 *"판정 못 하겠다"*)를 `exit 1`(*"대상이 없다"*)로 바꾸는 것은
> 개선이 아니라 **악화**다 — 저자에게 없는 잘못을 말하기 때문이다.
>
> **같은 실패라도 원인은 매번 다르다.** 계약 목록이 세 번 낡았는데
> 두 번은 **쓰기가 안 됐고** 한 번은 **손으로 센 열거가 불완전**했다.
> 도구를 고쳐도 손 열거는 안 고쳐진다 — **유도하거나 지워야 한다.**
>
> **장치를 늘리면 옛 장치가 무력해진다.** 해석기를 1 → 7로 늘리자
> 키↔트리 대응이 눈에서 사라졌고, 대조군 fixture 둘이 실제 템플릿 이름을 빌려 쓰고 있어
> **등록하는 순간 무너질 뻔했다**(Design D-0이 실측으로 먼저 막았다).
