## 2. 이 사이클이 실제로 한 일

### 2.1 ★가장 값진 순간 — **지뢰를 없애다 거짓말을 만들 뻔했다**

1차 판독이 **62점**을 준 이유 하나:

```js
norm.replace(/\[[^\]]+\]/, v)          // ← 비전역
/sources/[source]/[module] + 'src-a/mod-a'  →  /sources/src-a/mod-a/[module]
```

**206건 전량이 쓰레기 문자열**이었다. 진짜 링크는 집합에 없으니, 정직한 `exit 2`가
**거짓 `exit 1`**(*"라우트가 `src/app`에 없다"*)로 바뀐다.

**왜 조용했나 — 셋이 겹쳤다.**

1. `expanded`가 `values.length`를 찍어 출력엔 `→ 206`이 **정직하게** 나온다
2. 실제 저장소에 그런 링크가 0건이라 본 검사도 **초록**
3. 대조군 `D-17`이 **브래킷 하나짜리** 템플릿을 써서 못 봤다

→ 다중 브래킷 **세그먼트 조립**(치환이 아니다) + **개수 단언** + `D-20`(브래킷 둘) · `D-21`(수 불일치).

> **fixture의 모양이 대조군의 판별력을 정한다.** 하나짜리로 만든 대조군은 둘짜리 결함을 **영영 못 본다.**

### 2.2 ★두 번째 — 같은 실패가 세 번, **원인은 매번 달랐다**

`exit 2` 계약 목록이 **세 번** 낡았다.

| 회차 | 원인 | 고친 것 |
|:--:|---|---|
| 1·2차 | **편집 배치의 뒤 항목이 죽어 쓰기가 통째로 안 됐는데 ✅만 보고 넘어갔다** | **도구를 고쳤다** — 편집마다 즉시 쓰고 **다시 읽어 확인** |
| 3차 | **쓰기는 성공했고 손으로 센 열거가 불완전했다** — 같은 배치가 만든 자리 둘을 빠뜨렸고, *"`fail()`이 가는 자리 전부"* 라 적어 놓고 절반은 `fail()`이 아니었다 | **열거를 지웠다** |

지금 `CLAUDE.md`와 스크립트 헤더는 이렇게만 말한다:

```text
자리를 알고 싶으면 소스에게 물어라 —
  rg 'fail\(|process\.exit\(2\)' scripts/verify-doc-links.mjs
각 자리가 자기 사유 문자열을 들고 있고, 그것이 유일한 진실이다.
```

> **도구를 고쳐도 손 열거는 안 고쳐진다.** 선행 사이클이 *"손으로 세는 수는 다음에도 틀린다 —
> 목록만 남기면 틀릴 수가 없다"* 로 한 번 강등했는데 **목록도 틀렸다.**
> 남은 강등은 하나뿐이다 — **유도하거나 지운다.**

### 2.3 ★세 번째 — **장치를 늘리면 옛 장치가 무력해진다**

해석기가 1 → 8이 되자 **하나일 때 눈에 보이던 것이 안 보이게 됐다.**

| 판독 | 늘려서 사라진 것 |
|:--:|---|
| 1차 | 해석기 7 중 **4가 무대조군** · `TS_PROBE`가 앱의 가드 둘을 삼킴 |
| 2차 | **osha ↔ ncs ↔ daegu를 맞바꿔도 조용** · **키↔트리 대응**이 눈에서 사라짐 |
| 3차 | `DLG_KEYCHECK` 분지의 **배선**(판정은 덮였는데 배선이 안 덮였다) |

그리고 Design 단계의 **D-0**이 실측으로 먼저 막은 것 — 대조군 fixture 둘이
**실제 템플릿 이름**을 빌려 쓰고 있어, 그 라우트를 등록하는 순간 **조용히 무너질** 참이었다.
→ **합성 템플릿**(`합성/[없는것]`·`합성둘/[없는것]`)으로 바꿔 영구 표적으로 만들었다.

## 4. 상한 — 안 재는 것 (85%의 정체)

| 자리 | 왜 |
|---|---|
| ★**`!DLG_CHILD`로 조건 지어진 자리들** | **구조적으로 관측 불가** — 자식을 `DLG_CHILD` 없이 돌리면 자체검사가 **재귀**한다. 둘: **본 검사 앞 게이트**(가장 값진 무보증 자리) · **죽은 키 검사의 `!DLG_CHILD ||` 분지** |
| `TS_PROBE`가 앱 본문의 **필사본** | 가짜 트리 소유(Design §0.5)를 포기하지 않는 한 못 닫는다. **지금은 앱과 일치함을 확인했다** |
| `tsx` 부재 가드 | **행동상 잉여** — 지워도 `spawnSync`가 ENOENT로 같은 `fail` 경로로 가고 `D-19`가 밟는다 |
| 빈 세그먼트(`'a/'`) | 개수 단언을 통과해 매칭 불가 라우트를 조용히 만든다(실물 0건 · 코드 주석에 적었다) |
| catch-all `[...x]` | 등록하면 개수 단언이 `exit 2`를 낸다(실물 0건). **미등록이면 여전히 거짓 위반** |
| 선행 상한 전부 | 성공 출력이 스스로 말한다 — 여기 옮겨 적지 않는다 |

> **90%를 만들려고 대조군을 억지로 세우지 않았다.** 위 자리들은 *대조군을 하나 더 쓰면 되는*
> 종류가 아니라 **검사기가 자기를 검사하는 구조 자체**가 막는다. 세우려면 `!DLG_CHILD` 조건을
> 없애야 하고(자식 26개가 전부 `tsx`를 띄운다) 그 비용은 아직 안 쟀다 — **F-24**.

## 6. 남기는 문장

> **지뢰를 없애는 일이 거짓말을 만들 수 있다.**
> `exit 2`(정직하게 *"판정 못 하겠다"*)를 `exit 1`(*"대상이 없다"*)로 바꾸는 것은
> 개선이 아니라 **악화**다 — 저자에게 **없는 잘못**을 말하기 때문이다.
>
> **같은 실패라도 원인은 매번 다르다.** 도구를 고쳐도 손 열거는 안 고쳐진다 —
> **유도하거나 지워야 한다.**
>
> **미러를 만들지 않는 길이 있었다.** `.mjs`가 TS를 못 읽는다는 사실은 참이지만,
> 그것이 **세 번째 수동 미러**의 근거는 아니었다. 앱이 `generateStaticParams`에서 쓰는
> **바로 그 함수**를 부르면 된다.
