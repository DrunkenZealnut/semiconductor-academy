# 동적 라우트를 앱의 원천에서 푼다 — Design

> Plan: [doc-link-route-resolvers.plan.md](doc-link-route-resolvers.plan.md)
> **한 줄**: 지뢰를 없애는 순간 **그 지뢰를 지키던 대조군 둘이 조용히 무너진다** — 그것이 이 설계의 중심이다.

---

## 0. 착수 실측 — 열린 문제 여섯을 재서 정한다

### 0.0 ★가장 먼저 잰 것 — **등록이 대조군을 깨뜨린다**

| 대조군 | 지금 쓰는 "미등록 예시" | 등록하면 |
|---|---|---|
| `D-01` 정상 트리(`okTree`) | `src/app/chapter/[slug]/page.tsx` | 그 템플릿에 해석기가 생겨 **`미등록 템플릿` 줄이 안 찍힌다** → `wantReason`이 어긋나 **빨강** |
| `D-05` 해석기 없는 동적 라우트 → `exit 2` | `src/app/sources/[source]/page.tsx` | 해석기가 생겨 **`exit 2`가 아니라 판정이 난다** → **빨강** |

**둘 다 실제 템플릿 이름을 빌려 쓰고 있었다.** 등록은 그 이름을 빼앗는다.

→ **D-0. 두 fixture를 「영영 등록되지 않을 합성 템플릿」으로 바꾼다** (`/합성/[없는것]`).
D-2(*"해석기 없는 동적 라우트는 조용히 통과시키지 않는다"*)를 지키는 대조군이 **실제 등록 여부와
무관해진다.** 열린 문제 F의 답이고, **이것을 안 하면 이 사이클이 선행의 안전망을 먹고 자란다.**

> 선행 사이클이 일곱 판독 내내 짚은 문장이 여기서 한 겹 위로 온다 —
> *장치를 세우면 그 장치가 무대조군이 된다*에 더해, **장치를 늘리면 옛 장치가 무력해진다.**

### 0.1 ★열린 문제 A — `tsx`로 **앱의 원천에서** 푼다

Plan §1.3이 `tsx`가 실제 TS를 평가함을 쟀다. Design이 물어야 할 것은 **대조군 안에서도 되는가**다.

```text
임시 cwd + 그 트리가 소유한 가짜 `src/lib/fake.ts`
  node_modules/.bin/tsx -e "import { SECTIONS } from './src/lib/fake.ts'"
  → 가짜 TS에서 2   ·  0.19초
```

**된다.** 그러므로 TS 기반 해석기도 **가짜 트리로 대조군을 세울 수 있다** — 지금
`processes.json`을 가짜로 두는 것과 같은 방식이다.

| 안 | 라우트 | 결합 | 미러 | 판정 |
|---|:--:|---|:--:|:--:|
| ① JSON 2종만 | 47 | 없음 | 없음 | 가장 걸 법한 챕터는 덮인다 |
| ② **`tsx`로 전부** | **366** | 앱 TS | **없음** | ← **채택** |
| ③ 새 JSON 미러 | 366 | 빌드 스크립트 | **세 번째 수동 미러** | ✗ |

**③은 `CLAUDE.md`가 명시적으로 경계하는 것**이고(*"한쪽만 고치면 빌드 검증이 깨진다"*),
②가 그것을 피하면서 같은 값을 낸다. **미러를 만들지 않고 원천에서 유도한다** —
이 저장소가 관문마다 지켜 온 원칙이다.

→ **D-1. `tsx`를 **한 번만** 부른다.** 다섯 템플릿을 각각 부르면 다섯 번 뜨는데, 한 번에
전부 받아 오면 0.35초다. **필요할 때만** 부른다 — 스캔된 `src/app`에 TS 기반 템플릿이
하나도 없으면(대부분의 대조군 트리가 그렇다) **아예 안 뜬다.**

→ **D-2. `tsx`는 절대 경로로 부른다** — `node_modules/.bin/tsx`를 **관문 자신의 위치**에서 푼다.
`npx`도 cwd 상대 경로도 아니다(자식은 임시 cwd에서 돈다).

### 0.2 해석기가 실행될 조건 — 이미 옳다

```js
for (const p of pages) { … const resolver = ROUTE_RESOLVERS[norm]; … }
```

해석기는 **스캔된 `src/app`에 그 템플릿이 있을 때만** 돈다(실측 확인). 그래서
가짜 트리에 그 라우트 디렉터리가 없으면 **해석기도 `tsx`도 안 돈다** — 기존 대조군 14건은
`chapter/[slug]` 하나를 빼면 그대로 싸다.

### 0.3 열린 문제 B·D — 해석기가 죽으면 `exit 2`, 그리고 **선을 적는다**

`sources.ts`의 `generateStaticParams`에는 **의도된 `throw`** 가 있다(로더 미등록 시).
그 예외는 지금도 `fail()` → **`exit 2`** 로 간다. **옳다** — 라우트를 열거할 수 없으면
검사기가 자기 범위를 주장할 수 없다.

→ **D-3. 선을 문서에 적는다.** 이 관문은 *"라우트를 **열거**할 수 있나"* 만 본다.
앱 데이터의 **내용**(제목이 비었나, 순서가 맞나)은 안 본다 — 그것은 다른 관문의 일이다.
**적어 두지 않으면 다음 사람이 여기에 데이터 검사를 얹는다.**

### 0.4 열린 문제 C — 구체 라우트 집합

366개를 `Set`에 넣는다. **모호성이 사라진다** — `/sources/osha-scs/x`가
`[source]/[module]`과 `osha-scs/[part]` 둘에 걸리는 문제가, 구체 집합에서는 존재하지 않는다.
비용은 무시할 만하다(문자열 366개).

### 0.5 열린 문제 E — 대조군은 **가짜 TS**를 소유한다

가짜 트리가 `src/lib/sources.ts`·`src/lib/schoolTextMdx.tsx`를 **자기 것으로** 쓴다.
JSX 없는 `.tsx`는 그냥 TS라 문제없다(실측). 그러면 대조군이 **실제 저장소와 무관**해지고,
이 관문이 지켜 온 성질(*"대부분은 가짜 트리를 소유해 저장소 상태와 무관하다"*)이 유지된다.

### 0.6 새로 생기는 실패 모드

`tsx`가 없거나 죽으면? → **`exit 2`**. 파서 import 실패와 같은 부류다
(*판정을 흉내 내지 않고 죽는다*).

> ★**← Check 2·3차**: *"대조군을 세운다"* 는 **「죽으면」만** 지켜졌다(D-19·D-22).
> **「없으면」**(`existsSync(bin)`)은 가짜 트리로 지울 수 없어 못 세운다.
> ★3차가 **더 강한 근거**를 냈다 — 그 가드는 **행동상 잉여**다: 지워도 `spawnSync`가
> ENOENT로 `status !== 0`을 내 **같은 `fail` 경로**로 가고, 그 경로는 D-19가 밟는다.
> 즉 *못 세우는 것*이 아니라 *셀 것이 없는 것*에 가깝다. 상한 목록에는 그 근거로 적혀 있다.

## 1. 무엇을 만드나

### 1.1 해석기 일곱 — **이 사이클이 더하는 것**

> ⚠️ 선행 사이클의 `/process/[slug]`를 합쳐 레지스트리 총계는 **8종 · 전개 375**다.
> 그 수는 여기 두 번 적지 않는다 — **실행이 찍는다**(`동적 라우트: … → N`).

```text
JSON 2종   chapters.json → slug        ·  chemicals.json → id
TS   5종   tsx 한 번으로 다섯을 함께 받는다
           getOrderedSources() · listSchoolTextSourceIds()×sections
           OSHA_SCS · NCS_SEMI · DAEGU_HS
```

> ★**← Check 1차 G-1**: 초판 서술(`listSchoolTextSourceIds()×sections`)은 **앱의 가드 둘을 빠뜨렸다.**
> 앱은 `getSource` 미존재와 `hasModuleLoader` 미등록에서 **throw**하는데 프로브는 `?? []`로 삼켰다 —
> *"앱이 쓰는 바로 그 함수를 부른다"* 가 **가장 큰 해석기에서 거짓**이었고, 로더 없는 모듈을
> 유효 라우트로 인정해 **앱이 빌드 못 하는 URL에 링크를 걸어도 초록**이었다.
> 지금은 두 `throw`를 그대로 진다(대조군 D-22가 관측한다).
>
> ★**대가를 적는다**: 프로브는 앱의 `generateStaticParams`를 *부르는* 것이 아니라 **본문을 옮겨 적는다**
> (가짜 트리를 소유하려면 불가피하다 — §0.5). 앱에 셋째 가드가 붙으면 프로브는 모른다.
> **작지만 미러다.** 그 사실을 여기 적어 두는 것이 지금 할 수 있는 전부다.
>
> ⚠️ **정정 (2026-09-05 · CodeRabbit PR #46 재리뷰 + 실측)** — 마지막 문장이 **틀렸다.**
> *"전부"* 라고 적을 때 **재보지 않은 선택지**가 있었다: 앱의 `page.tsx`가 내보내는
> `generateStaticParams`를 **`tsx`로 그대로 부를 수 있다.** 실측했다 —
> `src/app/sources/[source]/[module]/page.tsx` → **206** · `src/app/chapter/[slug]/page.tsx` → **17**,
> 필사본 프로브의 수와 **정확히 일치**한다. 즉 **본문을 옮겨 적을 필요가 없었다.**
> 조건절(*"가짜 트리를 소유하려면 불가피하다"*)은 **여전히 참일 수 있다** — 처분 대조군의 가짜 트리에는
> `page.tsx`가 없으니 그쪽은 프로브가 필요하다. 그러나 **본 검사에서는 앱을 직접 부르고**
> 가짜 트리에서만 프로브를 쓰는 길, 또는 **둘을 대조해 어긋나면 `exit 2`** 를 내는 길이 열려 있다.
> **재보지 않고 "전부"라고 적은 것이 이 사이클의 마지막 교훈이다** → **F-28**.

`ROUTE_RESOLVERS`는 지금 모양 그대로 두고, TS 다섯은 **게으른 공용 로더**를 공유한다 —
첫 호출에서 `tsx`를 한 번 띄우고 결과를 캐시한다.

### 1.2 fixture를 합성 템플릿으로 (D-0)

```text
okTree     src/app/chapter/[slug]/    →  src/app/합성/[없는것]/
D-05       src/app/sources/[source]/  →  src/app/합성둘/[없는것]/
```

**이 두 줄이 이 사이클에서 가장 중요한 편집이다.** 안 하면 대조군 둘이 조용히 죽고,
그 사실은 *다음 사이클이 라우트를 하나 더 등록할 때* 드러난다.

### 1.2b Check가 더한 것 — ← Check 1·2차

| 무엇 | 왜 |
|---|---|
| **다중 브래킷 전개 + 세그먼트 수 단언** | 초판 `replace`가 **비전역**이라 `[source]/[module]` **206건이 쓰레기 문자열**이었다. 지뢰(`exit 2`)를 **거짓 `exit 1`** 로 바꾼 것이라 시작보다 나빴다 |
| **세그먼트 조립**(치환이 아니라) | `String.replace`의 치환 패턴(`$&`)·값 안의 `[…]` — 같은 계열의 잔여를 **못 쓰게** 만든다 |
| **`keys()`**(`.filter(Boolean)` 제거) | 조용한 축소는 세 줄 위에서 거부한 `?? p.id` 폴백과 같은 부류였다 |
| **죽은 키 단언** | 해석기 키가 1 → 7이 되면서 *키↔트리 대응*이 눈에서 사라졌다(렌더 관문의 ε) |
| **D-20~26** | FR-6이 3/7이었다 — *등록만 하고 안 재면* 선행이 일곱 번 겪은 자리다 |

### 1.3 안 보는 것에 한 줄

> 이 관문은 라우트를 **열거**할 수 있는지만 본다. 앱 데이터의 **내용**은 안 본다.

## 2. 착수 순서

```text
① fixture 둘을 합성 템플릿으로 — **등록보다 먼저** 한다
② JSON 2종 등록 → 라우트 집합·본 검사 확인
③ TS 5종: 게으른 tsx 로더 → 366 확인
④ 대조군: 새 해석기마다 · 오타 슬러그 · tsx 부재 · 해석기 사망 · 남은 미등록
⑤ 되돌림 G-4·G-5·G-6·G-7
⑥ CLAUDE.md · Check
```

**①이 먼저인 이유** — 순서를 바꾸면 ②에서 대조군 둘이 빨개지고, 그것을 *"등록 때문에 난 정상적인
빨강"* 으로 읽고 fixture를 고치게 된다. 그러면 **왜 고쳤는지가 기록에 안 남는다.**
먼저 고치면 ②의 빨강은 **진짜 결함**뿐이다.

## 3. 위험

| 위험 | 대응 |
|---|---|
| ★**등록이 옛 대조군을 먹는다** | §0.0 — 실측으로 발견했다. D-0을 **①번으로** 한다 |
| ★**미등록이 0이 되어 D-2가 겨눌 것을 잃는다** | 합성 템플릿이 **영구 표적**이 된다. 실제 등록 여부와 무관해진다 |
| **관문이 앱 런타임에 기댄다** | `tsx` 실패·`sources.ts` 예외는 전부 `exit 2`. **선을 적는다**(D-3) |
| **자식이 무거워진다** | 해석기는 **그 템플릿이 트리에 있을 때만** 돈다(§0.2). 기존 14건은 그대로 |
| ★**등록만 하고 안 재는 것** | 해석기 일곱에 대조군을 붙인다. 선행이 일곱 판독 내내 짚은 자리다 |
| **`tsx` 기동이 매 실행 0.35초** | 지금 관문이 약 7초라 5% 미만. 그리고 **필요할 때만** 뜬다 |
