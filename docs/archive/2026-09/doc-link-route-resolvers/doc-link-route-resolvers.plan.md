# 동적 라우트를 앱의 원천에서 푼다 — Plan

> **선행**: `doc-link-gate`(87%, 2026-09-03 아카이브) 파생 **F-14**
> **한 줄**: 관문이 *"여기는 못 본다"* 고 정직하게 말하는데, **저자가 가장 걸 법한 링크가 바로 거기다.**

---

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 문서 링크 관문이 동적 라우트 **7종을 미등록으로 선언**하고, 그리로 가는 링크를 만나면 `exit 2`를 낸다. 정직한 처분이지만 **지뢰**다 — 실측: 챕터 링크 하나를 걸면 곧바로 `exit 2`이고, **콘텐츠 저자가 가장 걸 법한 것이 챕터 링크**다. |
| **Solution** | 해석기를 등록해 `exit 2`(주장 못 함)를 **`0`/`1`(판정)** 로 바꾼다. ★핵심은 **어디서 푸느냐** — 앱은 `generateStaticParams`로 전개하는데 그 원천이 **JSON 2종 · TypeScript 5종**이다. `.mjs`는 TS를 못 읽는다(저장소가 *"두 개의 수동 미러"* 로 이미 앓는 문제). **실측: `tsx`가 앱의 진짜 TS를 그대로 평가한다**(0.35초). |
| **Function · UX Effect** | 저자가 챕터·화학물질·자료원 링크를 걸 수 있게 된다. **오타 난 슬러그는 그 자리에서 잡힌다** — 지금은 아예 검사가 멈춘다. |
| **Core Value** | *"안 본다고 말했으니 괜찮다"* 와 *"볼 수 있는데 안 본다"* 는 다르다. 선행 사이클이 **말하는 것**을 재게 만들었다면, 이 사이클은 **말한 뒤 남은 구멍**을 메운다. |

## 1. 착수 전 실측

> 이 절의 수는 전부 이번에 **직접 재서** 얻었다.

### 1.1 지금 무슨 일이 나나

```text
docs 어딘가에 [1장](/chapter/what-is-semiconductor/) 한 줄
  → exit 2
     ❌ 해석기가 없는 동적 라우트로 가는 링크가 1건 있다.
        ROUTE_RESOLVERS 에 '/chapter/[slug]' 해석기를 등록하라.
```

**관문이 멈춘다.** 판정이 아니라 *"주장할 수 없음"* 이고, 그것이 설계 의도(D-2)였다 —
조용히 통과시키면 그 라우트는 영영 무검사이기 때문이다. **그러나 지뢰인 것도 사실이다.**

### 1.2 ★7종이 무엇에서 오나 — **둘은 JSON, 다섯은 TypeScript**

| 템플릿 | 원천 | 전개 |
|---|---|:--:|
| `/chapter/[slug]` | `src/data/chapters.json` | **17** |
| `/chemicals/[id]` | `src/data/chemicals.json` | **30** |
| `/sources/[source]` | `sources.ts` `getOrderedSources()` | 14 |
| `/sources/[source]/[module]` | `sources.ts` + `schoolTextMdx.tsx` | **206** |
| `/sources/osha-scs/[part]` | `sources.ts` `OSHA_SCS.sections` | 5 |
| `/sources/ncs-semi/[module]` | `sources.ts` `NCS_SEMI.sections` | 84 |
| `/sources/daegu-hs-process/[module]` | `sources.ts` `DAEGU_HS.sections` | 10 |
| | **계** | **366** |

**JSON 2종 = 47 · TS 5종 = 319.** 지금 라우트 집합은 19이므로 **20배가 된다.**

### 1.3 ★`.mjs`는 TypeScript를 못 읽는다 — 그런데 `tsx`가 있다

`CLAUDE.md`가 명시한 저장소의 지병이다:

> `.mjs` 빌드 스크립트는 TypeScript를 import할 수 없어, 단일 진실을 **수동 미러**로 유지한다.
> 한쪽만 고치면 빌드 검증이 깨지거나 UI 불일치가 발생한다.

**그런데 `tsx`가 직접 devDependency로 있고, 실제로 앱의 TS를 평가한다:**

```text
npx tsx -e "import { getOrderedSources } from './src/lib/sources.ts'; …"
  → /sources/[source] 14 · /sources/[source]/[module] 206 · osha 5 · ncs 84 · daegu 10
  소요 0.35초 · 경로 별칭(@/*) 걸림돌 없음
```

**미러를 새로 만들지 않고 앱의 진짜 원천에서 유도할 수 있다.**
이것이 이 사이클의 핵심 발견이고, 열린 문제 A가 여기서 갈린다.

### 1.4 지금 조용한 것

```text
그 7종으로 가는 링크가 지금 0건이다 · 그래서 아무도 안 운다
저자가 챕터 링크를 처음 거는 날 exit 2다
```

**이것이 F-14다.**

## 2. 열린 문제 — Design이 정한다

| # | 문제 |
|:--:|---|
| **A** | ★**어디서 푸나.** ① JSON 2종만 등록(새 결합 0 · 47라우트 · **가장 걸 법한 챕터는 덮인다**) · ② `tsx`로 앱의 TS까지(366라우트 · **미러 없음** · 관문이 앱 런타임에 기댄다 · +0.35초) · ③ 새 JSON 미러를 만든다(**세 번째 수동 미러** — `CLAUDE.md`가 경계하는 바로 그것) |
| **B** | **`tsx`가 죽으면 어떻게 되나.** `sources.ts`의 `generateStaticParams`에는 **의도된 `throw`** 가 있다(로더 미등록 시). 그 예외를 `exit 2`로 볼 것인가, 아니면 관문이 앱의 건강까지 재는 것이 되나 |
| **C** | **366라우트를 집합으로 들 것인가.** 구체 라우트 집합이면 모호성이 없다(`/sources/osha-scs/x`가 `[source]/[module]`과 `osha-scs/[part]` 둘에 걸리는 문제가 사라진다). 대신 매 실행 366개를 만든다 |
| **D** | **어디까지가 이 관문의 일인가.** 해석기가 앱 데이터를 읽으면 **데이터가 깨졌을 때도 관문이 운다.** 그것이 값인가 범위 침범인가 |
| **E** | **대조군을 어떻게 싸게 유지하나.** 지금 처분 대조군은 가짜 트리를 소유한다. `tsx`를 쓰면 자식이 **실제 저장소의 TS**를 읽어야 하나, 아니면 가짜 트리에 가짜 TS를 둘 수 있나 |
| **F** | **`exit 2` 지뢰를 아예 없앨 것인가.** 7종을 다 등록하면 미등록 템플릿이 0이 된다 — 그러면 D-2(*"조용히 통과시키지 않는다"*)를 지키는 대조군은 **무엇을 겨누나** |

## 3. 기능 요구

| # | 내용 |
|:--:|---|
| FR-1 | 최소한 `/chapter/[slug]`·`/chemicals/[id]`를 등록해 **가장 걸 법한 링크가 판정된다** |
| FR-2 | 오타 슬러그는 **`exit 1`**(대상 없음)이지 `exit 2`가 아니다 |
| FR-3 | **미등록으로 남는 템플릿이 있으면 계속 말한다**(선행 FR-4를 깨지 않는다) |
| FR-4 | 해석기가 **미러를 새로 만들지 않는다** — 앱의 원천에서 유도하거나, 못 하면 그 사실을 적는다 |
| FR-5 | 해석기가 죽으면 **`exit 2`** — 조용히 빈 집합을 쓰지 않는다(선행 처방 유지) |
| FR-6 | 대조군이 **새 해석기마다** 선다 — 등록만 하고 안 재면 선행이 일곱 번 겪은 그 자리다 |
| FR-7 | 되돌려 확인하고 기록 |
