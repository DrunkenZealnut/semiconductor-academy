# 자체검사가 자기 분모를 지킨다 — Plan

> **선행**: `render-gate-derivation-claim`(90%, 2026-08-30 아카이브) 잔존 **D-2**
> **한 줄**: 감사의 분모는 지키면서 관문의 분모는 안 지킨다.

---

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 자체검사는 대조군 **40건**을 돌리는데 **그 수를 아무도 안 잰다.** 착수 전 실측: 대조군 하나를 통째로 지우니 **39건인데 `✅ 전 항목 통과 · exit 0`** 이다. 조용히 준다. **선행 사이클이 이미 그 대가를 치렀다** — 35→36이 됐는데 아무도 안 울었고, `CLAUDE.md`의 수치가 두 사이클 동안 표류했다. |
| **Solution** | 세 무리(**판정 · 범위 · 처분**)의 개수를 **손으로 적고 실행 집계와 대조**한다. 어긋나면 `exit 2` — *검사기가 자기 범위를 주장할 수 없다.* 선행 사이클이 감사에 세운 `RULE_CLAIMS`와 **같은 처방**이고, 이번엔 그것을 **관문 자신**에게 적용한다. |
| **Function · UX Effect** | **독자에게 보이는 변화는 없다.** 검사기가 자기 **개수**를 증명하는 사이클이다. |
| **Core Value** | *"대조군이 40건 있다"* 와 *"40건이라고 말하는 것이 참이다"* 는 다른 주장이다. 감사(`RULES_MIN`·`RULE_CLAIMS`·`assertCasesMirrorCallSites`)는 이미 자기 분모를 지킨다 — **관문만 안 지킨다.** |

## 1. 착수 전 실측

### 1.1 지금 대조군을 지우면

```text
⑰h(범위 대조군) 삭제
  → 대조군 39건 · ✅ 전 항목 통과 · exit 0
```

**조용하다.** 이것이 D-2다.

### 1.2 ★유도할 원천이 없다 — 이것이 설계를 결정한다

| 후보 | 대조군을 지우면 |
|---|---|
| `fixtures.length` | 배열에서 지우면 **함께 준다** — 공허한 미러 |
| 소스의 `spawnChildAgainst(` 개수 | 호출을 지우면 **함께 준다** — 공허 |
| `scases`/`cases.length` | 항목을 지우면 **함께 준다** — 공허 |

**셋 다 같은 곳에서 나온다.** 감사가 `CASES`를 **호출부**라는 다른 원천에서 유도하는 것과 다르다 —
자체검사의 대조군 수는 **자기 자신 말고 근거가 없다.**

→ 선행 사이클이 세운 원칙 그대로 간다:
**유도할 원천이 있으면 유도하고, 없으면 손으로 적되 유도값과 대조한다.**
`RULE_CLAIMS`가 그 자리였고, 이번에는 관문의 세 무리다.

### 1.3 출력 자리는 넷이다

```text
:782   처분 (spawnChildAgainst 안)
:1239  범위 (scases 루프)
:1245  범위 (cases 루프)
:1286  판정 (fixtures 루프)
```

**Act에서 한 번 열어 보고 접었던 이유가 이것이다** — `RULES_MIN`처럼 한 줄이 아니다.
다만 세 무리 함수가 이미 나뉘어 있으므로(`selfTestFixtures` · `selfTestScope` · `selfTestDispositions`)
**무리별로 세면** 자리는 셋으로 준다.

### 1.4 지금 셋의 반환 모양

| 함수 | 지금 | 필요한 것 |
|---|---|---|
| `selfTestFixtures()` | 배열을 반환 | 그대로 쓸 수 있다 |
| `selfTestScope()` | `boolean` | **개수도** 돌려줘야 한다 |
| `selfTestDispositions()` | `boolean` | **개수도** 돌려줘야 한다 |

## 2. 열린 문제 — Design이 정한다

| # | 문제 |
|:--:|---|
| **A** | **한 수인가 세 수인가.** 총계 하나(40)면 간단하지만 *"어느 무리가 줄었는지"* 를 안 말한다. 무리별(14·13·13)이면 진단이 정확한데 손 숫자가 셋이 된다 |
| **B** | **어디서 세나.** 무리 함수가 개수를 돌려주게 할 것인가(반환 모양 변경), 아니면 공용 `note()` 헬퍼로 출력 자리 넷을 묶을 것인가 |
| **C** | **`CLAUDE.md`의 수치와 어떻게 잇나.** 지금은 문서가 손으로 적은 수치를 들고 있고 코드는 모른다. 코드가 자기 수를 알게 되면 **문서와 코드 사이에 또 하나의 미러**가 생긴다 — 그것을 대조할 것인가, 아니면 문서가 코드를 가리키게 할 것인가 |
| **D** | **감사에 규칙을 더할 것인가.** 이 판정을 훼손하는 항목을 감사에 넣으면 항목이 18 → 19가 되고 약 25초 는다. 자체검사 자신을 훼손하는 것이라 **자기 참조**가 된다 — 그것이 성립하는가 |

## 7. 위험

| 위험 | 대응 |
|---|---|
| ★**공허한 미러를 하나 더 만든다** | §1.2 — 유도가 전부 공허하다는 것을 **먼저 쟀다.** 손 숫자를 실행 집계와 대조하는 것이 유일한 길이고, 그 대조가 **다른 층**(선언 vs 실행)에서 이뤄지므로 공허하지 않다 |

| **자기 참조** | 열린 문제 D — 자체검사가 자기 개수를 단언하는데 그것을 감사가 훼손하면 무엇이 무엇을 재는가 |
