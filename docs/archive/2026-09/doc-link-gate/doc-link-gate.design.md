## 0. 착수 실측 — 열린 문제 여섯을 재서 정한다

### 0.0 ★먼저 뒤집힌 것 — Plan §1.6이 틀렸다

Plan은 *"「저장소 전체 0건」이라 적은 문장 곁에 예시 4건이 있는데 아무도 안 운다"* 고 적었다.
**파서에 물으니 그 4건은 링크가 아니다.** 전부 코드 스팬(`` ` ``) 안이라 CommonMark가 링크로 안 본다.

```text
정규식 스캐너   `../../01-plan/features/x.plan.md`  → 죽은 링크 4건이라 보고
파서            같은 자리                            → 링크가 아니다(코드 스팬)
```

| | |
|---|---|
| `_INDEX.md`의 *"재스캔 0건"* | **참이었다** |
| 그것을 뒤집었다고 본 내 경보 | **내 도구의 거짓 경보였다** |

**틀린 것은 문장이 아니라 그 문장을 재던 자였다.** 이 사이클의 주제가 그대로 나왔다 —
*"재는 도구가 틀리면 고쳤다도 안 고쳤다도 못 믿는다."*

→ 착수 ①의 내용이 바뀐다(§2). *"거짓 문장을 정정한다"* 가 아니라
**"어떻게 쟀는지를 적는다"** 다. 수가 아니라 **판정 근거**가 빠져 있었다.

### 0.1 열린 문제 A — 파서를 쓴다. `remark-mdx`는 안 쓴다

| 구성 | `.md` | `.mdx` | 비고 |
|---|:--:|:--:|---|
| `remark-parse` | 127 | 24 | 기준 |
| **`+ remark-gfm`** | **150** | **24** | ← 채택 |
| `+ remark-gfm + remark-mdx` | 144 | 24 | **`.md` 13개가 파싱 실패** |

- **gfm은 필요하다** — `.md`에서 +23건(전부 자동 링크된 외부 URL). 앱도 GitHub도 GFM이다.
- **`remark-mdx`는 안 쓴다** — `.mdx`에서 링크 집합 차이가 **정확히 0**이고(`gfm`만 vs `gfm+mdx`, 양방향 0),
  `.md`에서는 `<br>`·`<ol>`·`<2026-05` 같은 것에 걸려 **13개가 죽는다.**
  *얻는 것이 없고 잃는 것이 있다.*

**정규식이 아닌 이유는 Plan §1.3에서 이미 쟀다** — 사고 링크 후보 4건 중 파서가 인정한 것은 1건,
**거짓 경보 75%**.

**의존**: `remark-gfm`만 직접 의존이고 `unified`·`remark-parse`·`unist-util-visit`는 전이 의존이다
(`@mdx-js/loader` → `@mdx-js/mdx` 사슬). → **셋을 `devDependencies`로 올린다.**
렌더 관문이 `playwright-core`를 그렇게 두고 있는 것과 같은 선례다. 설치된 판이
`unified 11.0.5 · remark-parse 11.0.0 · unist-util-visit 5.1.0`이라 **잠금 파일 변동은 항목 추가뿐**이어야 한다(Do에서 확인).

**import 실패는 `exit 2`** — 검사기가 자기 범위를 주장할 수 없다.

### 0.2 열린 문제 B — 라우트를 본다. 유도하고, 못 풀면 운다

실측: 라우트 링크 **23건 · 17종 · 전부 유효**.

| 갈래 | 종수 | 근거 |
|---|:--:|---|
| 정적 | 8 | `src/app/{about,chemicals,cleanroom,electromagnetic,occupational-disease,process-overview,risks-of-new-tech,what-is-semiconductor}/page.*` |
| 동적 `process/[slug]` | 9 | `processes.json`의 슬러그 9종과 정확히 일치 |

**지금은 조용하다. 그래서 안 볼 이유가 되지 않는다** — 슬러그 하나가 바뀌면 **챕터 본문의 9건이 한꺼번에 죽고**,
로그인 게이트 뒤라 아무도 안 본다. 이 링크들을 쓰는 사람은 콘텐츠 저자다.

→ **D-1. 정적 라우트는 `src/app` 트리에서 유도하고, 동적 세그먼트는 해석기 등록제로 푼다.**
지금 필요한 해석기는 `process/[slug]` 하나뿐이다(측정).

→ **D-2. ★해석기가 없는 동적 라우트를 만나면 조용히 통과시키지 않는다 — `exit 2`.**
렌더 관문의 δ와 같은 처분이다. *"검사 목록에서 빠진 것"* 을 통과로 세면 그 관문은 헛것이다.
`/sources/{id}/{module}/` 같은 링크가 나중에 생기면 **그때 관문이 먼저 운다.**

### 0.3 ★열린 문제 C — allow 파일을 **만들지 않는다**

Plan은 도해 관문의 `diagram-check-allow.json` 선례를 들어 *"예시를 어떻게 가르나"* 를 물었다.
**재 보니 가를 것이 없다.**

```text
파일 후보 115건 · 모양(글로브·플레이스홀더) 0건 · 해석 실패 1건
```

이유는 §0.0과 같다 — **파서가 코드 스팬을 건너뛴다.** 문서가 링크를 *설명하는* 자리는
거의 언제나 백틱 안이고, 실측한 두 사례(가상 경로 예시 · `[…](…)` 문법 설명)가 **둘 다 그렇다.**

> **필요를 재지 않고 장치를 만들지 않는다.**
> 도해 관문의 allow 파일도 필요가 측정된 **뒤에** 생겼다. 지금 만들면 **등재 0건짜리 장치**가
> 하나 더 생기고, 그것은 이 저장소가 반복해 앓은 병이다(*덮을 수 없는 것을 덮었다고 세면…*).

**대신 위반 메시지가 길을 준다** — 진짜로 예시를 쓰려던 사람에게 *"백틱으로 감싸라"* 고 말한다.
그것이 더 나은 마크다운이기도 하다(렌더될 때 링크가 안 생긴다). **우회로가 공짜다.**

→ **D-3. allow 파일은 없다. 필요가 생기면 그때 만들고, 그 diff가 근거가 된다.**
이 결정을 관문 주석에 적는다 — 안 적으면 다음 사람이 *"왜 없지"* 로 다시 만든다.

### 0.4 열린 문제 D — 사고 링크는 **같은 판정**으로 잡힌다

별도 판정을 만들 필요가 없다. 실측이 그렇게 말한다:

```text
파일 후보 해석 실패 1건 = src/content/sources/hs-basic-tech-1/electronic-devices.mdx:111  「1[H](헨리)」
```

**관문은 의도를 모른다.** 알 필요도 없다 — 어느 쪽이든 고쳐야 한다.
메시지가 두 길을 다 제시한다:

```text
❌ 링크 대상이 없다 — electronic-devices.mdx:111  「헨리」
   ① 정말 링크라면 대상 경로를 고쳐라.
   ② 링크로 만들 의도가 아니었다면 대괄호를 없애라(`1[H](헨리)` → `1H(헨리)`).
      대괄호 직후 여는 괄호는 링크 문법이다 — 이 규칙은
      docs/archive/2026-07/chapters-source-fidelity/design.md §7에 이미 적혀 있다.
```

**마지막 줄이 이 사이클의 요점이다** — 규칙은 적혀 있었고, 지켜지지 않았고, 아무도 몰랐다.

### 0.5 열린 문제 E — 종료 코드는 기존 계약 그대로

| 코드 | 뜻 | 이 관문에서 |
|:--:|---|---|
| `0` | 통과 | |
| `1` | **콘텐츠 위반** | 링크 대상이 없다 · 라우트가 없다 |
| `2` | **검사기가 자기 범위를 주장할 수 없다** | 파서 import 실패 · 대상 파일 0개 · **해석기 없는 동적 라우트**(§0.2) · `src/app` 또는 데이터 파일을 못 읽음 · **자체검사 실패** · **대조군 수가 선언과 다름** |

### 0.6 열린 문제 F — 감사는 **안 만든다**. 그러나 자리는 비워 둔다

선행 사이클이 감사 비용을 실측했다: **항목 24개 × 자체검사 한 번 = 약 7분.**
그리고 감사가 답하는 질문은 *"판정이 본 검사에서 살아 있는가(배선)"* 인데,
**이 관문은 판정과 본 검사 사이의 층이 얇다** — 순수 함수 하나를 한 자리에서 부른다.

→ **D-4. 감사를 만들지 않는다. 대신 판정 호출을 한 자리로 모으고 그 사실을 적는다.**
나중에 층이 두꺼워지면 그때 붙인다. **안 만든 것을 백로그로 선언한다** — 안 적으면 *"덮었다"* 로 읽힌다.

### 0.7 분모 — 선행 사이클의 처방을 그대로

```js
const CONTROLS = { 판정: N, 처분: N };
const seen     = { 판정: [], 처분: [] };   // ← Check 6차에 이렇게 뒤집혔다
```

**짝은 키가 정한다**(선행 N-2b). 실행 집계와 `!==`로 대조하고 어긋나면 `exit 2`.
집계는 **판정을 찍는 자리**에서 올린다.

> ★**← Check 6차 B: 「배열 길이가 아니다」가 여기서 뒤집혔다.**
> 초판 설계는 선행 사이클의 처방(`ran[g] += 1`)을 그대로 옮겼는데, 이 관문에는 **대조군 이름**이
> 필요했다(식별자 인용). 수와 이름을 따로 두니 `push`만 지워도 수가 살아 조용했고,
> 헬퍼로 묶어도 **두 문장은 여전히 두 문장**이라 그대로였다(실측 exit 0).
> → **원천을 하나로**: 이름 배열의 **길이가 곧 수**다. 선행의 「배열 길이가 아니다」는
> *선언 배열*(`fixtures.length`)을 두고 한 말이고, 여기 배열은 **실행이 채운다** — 다른 것이다.

## 1. 무엇을 만드나

### 1.1 `scripts/verify-doc-links.mjs` — `npm run verify:links`

```text
① 대상 파일 수집     .md · .mdx (node_modules·.next·.git·data·.bkit 제외)
② 파싱               unified().use(remarkParse).use(remarkGfm)
③ 참조 추출          visit(tree, …) — link · image · html 속성(src/href)
                     ← Check 2차 G-1: 초판은 `visit(tree, 'link')`였다. 마크다운 이미지는 4건뿐이고
                       살아 있는 페이지의 이미지는 **여러 줄 `<ImageFigure … src="/…" />`** 꼴 425건이라 0.9%만 덮고 있었다
                       (3차 A-1: 초판은 `<img src=`라 적었는데 그 꼴은 `src/content`에 없다)
④ 분류               외부 | 앵커 | 라우트 | 파일
⑤ 해석               파일 → 문서 기준 상대 · 라우트 → 유도한 라우트 집합
⑥ 처분               위반 있으면 1 · 주장할 수 없으면 2 · 아니면 0
```

**④와 ⑤를 순수 함수로 뽑는다** — `classify(url)` · `resolveFile(fromFile, url)` · `resolveRoute(url, routes)`.
대조군이 브라우저도 자식 프로세스도 없이 이것들을 직접 먹인다(싸다).

### 1.2 안 보는 것을 말한다

성공 출력에 **범위 밖을 적는다.** 선행 사이클의 규약이다 —
*"덮지 않은 것을 말하지 않으면 이 수치가 「닫았다」로 읽힌다."*

```text
문서 N개 · 참조 N건 — file N · route N · public N · external N · anchor N
   출처: link N · image N · src N · href N
   ← ★**수를 적지 않는다.** 초판은 여기 실수를 적었고 두 번 낡았다(178 산술 오류 → 177 → 603).
     형식만 보인다 — 수는 실행이 찍는다(`CLAUDE.md`의 "수를 두 곳에 적지 않는다" 규칙).
   ※ 안 보는 것: 외부 URL(네트워크) · 인라인 코드의 경로 언급(1295건 중 256건이
     해석 실패이나 대부분 아카이브 문서의 정당한 역사 기술이다) · 앵커의 실재 여부
```

### 1.3 자체검사

| 무리 | 무엇 | 비용 |
|---|---|---|
| **판정** | `classify`·`resolveFile`·`resolveRoute`에 fixture를 직접 먹인다 | 즉시 |
| **처분** | 자식 프로세스를 **임시 cwd**에서 돌려 종료 코드와 사유를 본다 | 자식당 수백 ms |

처분 대조군이 반드시 덮어야 할 것: 죽은 파일 링크 → `1` · 죽은 라우트 → `1` ·
**해석기 없는 동적 라우트 → `2`** · 대상 파일 0개 → `2` · 정상 트리 → `0`(과잉 발화).

> ← **Check가 여기에 여섯을 더했다.** 빈 목적지 → `1` · 죽은 이미지 → `1` · `route.*` 인정 → `0` ·
> 절대 경로 이미지의 `public/` 해석 → `0`/`1` · JSX `src=""` → `1` · 링크의 `public/` 폴백 → `0`.
> 그중 **`public/` 배선 둘**은 1차 Act에서 순수 함수만 덮고 **배선을 안 덮어** 2차가 다시 잡았다 —
> *"순수 함수는 옳고 배선이 무대조군"* 의 재발이다.

## 2. 착수 순서

```text
① _INDEX.md에 **어떻게 쟀는지**를 적는다 (§0.0 — 수가 아니라 판정 근거가 빠졌다)
② devDependencies 셋 추가 · 잠금 파일 변동이 항목 추가뿐인지 확인
③ 순수 함수 셋 + 라우트 유도 → 지금 상태에서 위반 1건(헨리)이 나오는지 확인
④ 대조군 + 개수 선언 → 되돌림 G-4·G-5·G-6·G-7
⑤ FR-6 사고 링크 수정 → 관문이 초록
⑥ package.json 스크립트 · CLAUDE.md · Check
```

**③이 ⑤보다 먼저인 이유** — 고치기 전에 **관문이 그것을 잡는지** 봐야 한다.
먼저 고치면 관문이 무엇을 잡는지 영영 모른다.
