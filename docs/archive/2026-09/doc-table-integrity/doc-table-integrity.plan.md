# 표가 깨지는 것을 잰다 — Plan

> **선행**: `doc-link-route-resolvers`(85%, 2026-09-05 아카이브) 파생 **F-27**
> **한 줄**: 마크다운이 **적힌 것과 다르게 렌더되는데** 아무도 안 본다 — 링크에 이어 **표**가 그렇다.

---

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | GFM 표 안의 리터럴 `\|`는 **백틱 안이라도** 열 구분자로 파싱된다(파이프 이스케이프가 인라인 파싱보다 **먼저** 온다). 그래서 셀이 쪼개지고 **뒤 내용이 렌더에서 사라진다.** 실측: 저장소에 **데이터가 잘리는 행 4건** · 셀이 모자란 행 **11건** · ★**셀 수는 맞는데 코드 스팬이 깨진 행 1건**. 직전 사이클이 **자기 손으로 3건을 새로 만들었고**, 잡은 것은 관문이 아니라 CodeRabbit이었다. |
| **Solution** | `verify:links`가 이미 만드는 **바로 그 트리**에 검사 둘을 얹는다 — ① 표의 **헤더 셀 수 ↔ 각 행의 셀 수**, ② **깨진 코드 스팬**(셀 텍스트에 홀수 개 백틱이 남았다). ★**둘인 이유는 실측이다**: ②만 잡는 행이 실물에 **1건** 있다. |
| **Function · UX Effect** | 표를 고치다 파이프를 흘리면 **그 자리에서 `exit 1`**. 저자는 `\|`로 이스케이프하거나 코드 펜스로 옮기면 된다 — **우회로가 공짜다.** 기존 결함 16건도 이 사이클에서 실제로 고친다. |
| **Core Value** | `1[H](헨리)`와 **같은 계열**이다 — *적혀 있었고, 다르게 렌더됐고, 아무도 몰랐다.* 선행 사이클이 **링크 모양**을 재게 만들었다면 이 사이클은 **표 모양**을 잰다. |

## 1. 착수 전 실측

> 이 절의 수는 전부 이번에 **직접 재서** 얻었다.

### 1.1 분모와 실물

```text
.md/.mdx 574개 · 표 2,604개 · 데이터 행 14,050 · 표가 있는 파일 557/574
                                  ↑ 착수 시점 스냅숏 (⚠️ Check 정정: 초판 14,051)
```

| 성질 | 건수 | 실물 |
|---|:--:|---|
| ★**셀 > 열** — 데이터가 렌더에서 **잘린다** | **4** | `2026-05/filter-button-promotion/report.md:234~236`(열3→4 · 우선순위 `P1`이 사라진다) · `2026-07/chapters-source-fidelity/design.md:101`(열3→**6** · `` `<Callout type="info \| warning \| tip \| source">` ``) |
| 셀 < 열 — **빈 칸**으로 렌더된다 | **11** | `docs/03-analysis/ch2-deep-content.analysis.md`(열5인데 행이 4) · `2026-08/diagram-expansion/…w4-design.md` |
| ★**셀 수는 맞는데 코드 스팬이 깨졌다** | **1** | `2026-05/quotes-source-filter/analysis.md:34` |

### 1.2 ★한 신호로는 못 본다 — 실측이 그렇게 말한다

`quotes-source-filter/analysis.md:34`은 **셀 4 = 열 4**로 멀쩡한데, 파서가 이렇게 읽는다:

```text
[3] text("BookQuoteCard ") + code("href={\") + text("/chapter/${…}/`}")
                           + code("(98), OshaQuoteCard") + text("href={quote.partHref}") …
```

원인은 파이프가 아니라 **백틱 중첩**(`` `href={\`…\`}` ``)이다. **결함의 계열은 같고**(적힌 것과
다르게 렌더된다) **신호는 다르다.** 렌더 관문의 **η**(두 유도가 어긋나면 운다)와 같은 모양이다.

> 셀 수만 재면 이 1건을 **영영 못 본다.** 백틱만 재면 4건 중 3건을 못 본다.

### 1.3 붙이는 비용이 사실상 0이다

```text
scripts/verify-doc-links.mjs:399  const PROC = unified().use(remarkParse).use(remarkGfm)
scripts/verify-doc-links.mjs:411  visit(PROC.parse(source), (n) => { … })
```

**관문이 이미 전 문서의 트리를 만들고 순회한다.** `table` 노드는 그 순회에 이미 들어온다 —
파일을 다시 읽지도, 다시 파싱하지도 않는다. 기준선 **5.92초**(문서 574 · 참조 616).
독립 측정으로 파싱+표 순회만 2.33초인데, **그 2.33초는 이미 지불된 값**이다.

`markdownlint`는 devDependency에 **없다**(있는 것은 `unified`·`remark-parse`·`remark-gfm`).
새 의존성을 들이지 않는다.

### 1.4 판별력 사전 확인

```text
훼손판  | x | 죽은 키 검사의 `!DLG_CHILD ||` 분지 |   → 셀 4 (열 2) ✅ 잡힌다
정상판  … `!DLG_CHILD \|\|` …                      → 셀 2        ✅ 조용하다
```

**직전 사이클이 만든 3건을 이 검사가 잡는다.** 그리고 고친 판본에는 울지 않는다 —
*거짓 경보투성이 관문은 곧 무시된다.*

## 2. 열린 문제 — Design이 정한다

| # | 문제 |
|:--:|---|
| **A** | ★**셀 < 열도 위반인가.** 11건이고 데이터 손실은 없다(빈 칸 렌더). 넣으면 *"열이 빠졌다"* 는 진짜 버그를 잡지만 **고칠 것이 11건 늘고** 거짓 경보 위험도 는다. 넣는다면 **같은 처분인가 다른 처분인가.** |
| **B** | **깨진 코드 스팬을 어떻게 판정하나.** *"셀 텍스트 노드에 홀수 개 백틱"* 은 탐침이지 정의가 아니다. 정당하게 백틱 하나를 쓰는 글이 있으면 거짓 경보다 — **실측으로 세야 한다**(지금 1건 외에 몇인지). |
| **C** | **기존 16건을 이 사이클에서 고치나.** 관문을 세우면 `exit 1`이라 **안 고치면 초록이 안 난다.** 전건 수정이 기본인데, `2026-07/chapters-source-fidelity/design.md:101`은 **설계 문서의 본문**이라 고치면 역사 기술이 바뀐다(→ `\|` 이스케이프는 렌더만 바꾸고 뜻은 그대로다 — 그 근거를 적어야 한다). |
| **D** | **allow 파일을 만드나.** 선행 관문은 **일부러 안 만들었고** 그 근거는 *"필요가 0으로 측정됐다"* 였다. 여기도 재야 한다 — 표를 **설명하는** 문서가 깨진 표를 예시로 들 자리가 있나. 우회로(`\|`·코드 펜스)가 공짜라면 필요는 0일 가능성이 크다. |
| **E** | ★**어디까지가 «표»인가.** HTML `<table>`은 파서가 `html` 노드로 준다(셀을 못 센다) · MDX의 JSX 표도 마찬가지 · **코드 펜스 안의 표는 표가 아니다**(파서가 그렇게 본다 — 이게 우회로다). 이 셋을 **상한으로 적을 것인가, 재려 할 것인가.** |
| **F** | **대조군을 몇으로 어떤 모양으로.** 선행이 일곱 판독 내내 짚은 자리다 — *장치를 세우면 그 장치가 무대조군이 된다.* 판정(순수 함수에 표를 직접 먹인다)과 처분(자식 프로세스)이 각각 필요하고, **fixture의 모양이 판별력을 정한다**(직전 사이클의 `D-17`이 브래킷 하나짜리라 결함을 못 본 그 자리). |
