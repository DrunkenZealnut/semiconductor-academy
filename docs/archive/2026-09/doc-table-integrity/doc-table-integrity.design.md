# 표가 깨지는 것을 잰다 — Design

> Plan: [doc-table-integrity.plan.md](doc-table-integrity.plan.md)
> **한 줄**: Plan이 *"신호 둘이 필요하다"* 고 했는데, **재보니 둘 다 안 먹고 표적은 표 결함이 아니었다.**

## 0. ★D-0 — 착수 전에 Plan을 무너뜨린 실측

Plan §1.2가 이 사이클의 숫자(**G-5**)를 *"셀 수만으로는 못 보는 1건이 있다"* 에 걸었다.
그 1건은 `docs/archive/2026-05/quotes-source-filter/analysis.md:34`이다. **셋을 쟀다.**

### 0.1 후보 신호 ①(홀수 백틱) — 거짓 경보를 내고, 합성 결함엔 조용했다

```text
🔇 조용  정상 코드 스팬
🔔 운다  이스케이프된 백틱 하나       ← ★거짓 경보 (정당한 글이다)
🔇 조용  이중 백틱으로 감싼 백틱
🔇 조용  깨진 코드 스팬(합성)         ← ★표적을 놓쳤다 (패리티가 우연히 맞았다)
```

판별이 **우연한 패리티**에 달려 있다. 저장소에 `\`` 를 쓰는 파일이 이미 **7개** 있다 —
그 중 하나가 표 셀에 들어오는 날 **거짓 경보**다.

### 0.2 후보 신호 ②(원문 줄에서 이스케이프를 뺀 백틱 패리티) — 더 나빴다

```text
🔇 조용  ★실물 결함 FR-05        ← 표적을 놓쳤다
🔔 운다  이중 백틱                ← 거짓 경보
저장소 전량: ②가 우는 행 0건      ← 아무것도 못 잡는다
```

### 0.3 ★그래서 표적 자체를 의심했다 — **그것은 표 결함이 아니다**

FR-05 셀의 내용을 **표 밖에서** 파싱해 봤다:

```text
표 밖 파싱: T"BookQuoteCard " + C"href={\\" + T"/chapter/${…}/`}" + C"(98), OshaQuoteCard" + …
표  안 파싱: T"BookQuoteCard " + C"href={\\" + T"/chapter/${…}/`}" + C"(98), OshaQuoteCard" + …
                                                                        ↑ 완전히 같다
```

**표와 무관하다.** 원인은 `` `href={\`…\`}` `` — **코드 스팬 안에는 이스케이프가 없다**(CommonMark).
백틱이 첫 짝에서 닫히는 저작 실수이고, 표 안에 있든 밖에 있든 똑같이 깨진다.

> **Plan §1.2가 잘못 분류했다.** *"결함 계열은 같고 신호는 다르다"* 고 적었는데,
> 계열도 다르다 — 하나는 **표 파싱**이 뜻을 바꾸는 것이고 다른 하나는 **코드 스팬 저작 실수**다.
> **G-5는 폐기한다.** 후보 신호를 둘 만들어 재보고 표적까지 되짚어서야 알았다.
> *신호를 세우기 전에 그 신호가 겨누는 것이 정말 그 자리에 있는지 먼저 잰다.*

### 0.4 D-0 둘째 — 기존 대조군은 안 깨진다

```text
자체검사 fixture 안의 표: 0개
```

직전 사이클은 여기서 **대조군 fixture 둘이 실제 템플릿 이름을 빌려 써** 무너질 뻔했다.
이번엔 fixture에 표가 없어 새 검사가 기존 55건 중 하나도 건드리지 않는다. **확인하고 적는다.**

## 2. 무엇을 만드나

### 2.1 규칙 하나 · 순수 함수 하나

```text
tableViolations(tree) →  [{ line, want, got }]
  표마다: want = 헤더 행의 셀 수
  데이터 행마다: got ≠ want 이면 위반
```

**기존 순회에 얹지 않고 별도 함수로 뺀다** — `refsIn()`은 `link`·`image`·`html`만 보고
**노드 하나씩** 처리하는데, 표는 **행 사이 관계**를 봐야 해서 모양이 다르다.
같은 `PROC.parse()` 결과를 **한 번 더 순회**한다(트리는 이미 메모리에 있다).

> ★**대가를 적는다**: `refsIn()`이 `parse`를 자기 안에서 부르므로, 지금 모양대로면
> **파싱이 두 번** 일어난다. 그래서 `parse`를 호출부로 올리고 두 함수가 **트리를 받는다.**
> 이것이 이 사이클의 유일한 기존 코드 변경이고, **되돌림으로 확인한다**(D-29).
>
> ⚠️ **Check 정정** — `D-29`가 그것을 잰다는 계획은 **틀렸다**(§3.4 정정 참조). 실제로 이 이동을
> 지킨 것은 **기존 판정 대조군 10건**이었다 — 옮기는 즉시 빨개졌다. *장치를 새로 세우기 전에
> 기존 장치가 이미 우는지 본다.* 그리고 파싱 조립은 이제 `treeOf()` **하나**로 모여
> 판정과 본 검사가 **같은 함수**를 부른다 — 이음매가 생길 자리를 없앴다.

### 2.2 실패 메시지 — 우회로를 말한다

```text
❌ 표의 셀 수가 헤더와 다르다 — N건
   docs/…/x.md:98  헤더 열 2 → 이 행 셀 4
      ① 셀 안의 리터럴 `|`는 **백틱 안이라도** 열 구분자다 — `\|`로 이스케이프하라.
      ② 표를 설명하려던 것이면 **코드 펜스**로 옮겨라 — 파서가 표로 보지 않는다.
      ③ 열을 정말 더하거나 뺄 생각이었으면 **헤더**를 함께 고쳐라.
```

**종료 코드 `1`**(콘텐츠 위반) — 죽은 링크와 같은 계약이다. `2`가 아니다:
검사기는 자기 범위를 **주장할 수 있다**(트리가 있고 표가 있다).

```text

④ 기존 15건 수정 (+ FR-05 1건은 코드 스팬 저작 수정)
⑤ CLAUDE.md · 되돌림 · Check
```

**①이 먼저인 이유** — 기존 검사를 깨뜨릴 수 있는 유일한 변경이라, 새 기능을 얹기 전에
**돌아가는 것부터** 확인한다.
