**H-2의 프레임이 정확했다.** 에이전트의 말:

## 2. Check에서 재귀를 다시 만들었다

⑧(`--all` 배관)의 초안은 자식을 `--all`로 띄우고 **본 검사까지 가는** 시나리오였다. 그 순간 **D-2가 막았던 재귀가 그대로 되살아났다** — `--all` 자식 → 웨이브 자식 5개 → 각자 `selfTest` → 또 `--all`.

관문이 통째로 깨진 뒤에야 알았다.

**고친 방법**: 웨이브 자식이 **시작 단언에서 죽는** 시나리오를 고른다(`src/components` 미연결 → `readTones`에서 `exit 2`). `selfTest`에 도달하지 않으므로 손자가 없다.

> **재귀 회피는 "플래그를 만들었으니 끝"이 아니다.** `--assert-only`는 자식을 **그 인자로 띄울 때만** 듣는다. 새 대조군이 다른 인자를 쓰면 방어가 사라진다. Design §0.1의 교훈을 적어 놓고도 나흘 뒤(같은 세션 안에서) 같은 함정에 빠졌다.

또 하나: D-14를 넣자 **기존 대조군 ①③이 깨졌다.** 최소 트리가 등록 자료원 14개 중 하나만 만들었기 때문이다. 하네스가 등록 디렉터리를 전부 빈 채로 만들도록(`scaffold`) 고쳤다 — **새 단언을 더하면 기존 대조군의 전제가 바뀐다.**

## 3. 처분 되돌림 — 6종 전부 비공허

| 되돌린 것 | 깨지는 대조군 |
|---|---|
| D-10 처분 제거 | ② D-10 |
| D-11 처분 제거 | ③ D-11 |
| `tokens.ts` 가드 제거 | ④ `tokens.ts` |
| `globals.css` 가드 제거 | ⑤ `globals.css` |
| 콘텐츠 루트 가드 제거 | ⑥ 콘텐츠 루트 |
| D-14 처분 제거 | ⑦ 등록됐는데 없음 |

각각 **해당 대조군만** 깨진다.

**⑤에서 되돌림이 한 번 불완전했다.** `globals.css` 가드는 두 곳(`readPalette`·`readColorTokens`)인데 하나만 되돌리자 다른 하나가 먼저 걸려 **"되돌렸는데 통과"** 가 나왔다. 대조군이 공허한 것이 아니라 **되돌림 실험이 틀린 것**이었다 — 둘 다 되돌리니 깨졌다.

> **비공허성 실험도 검증이 필요하다.** "되돌렸는데 통과했다"는 두 가지를 뜻할 수 있다: 대조군이 공허하거나, **되돌림이 불완전하거나**. 앞의 결론으로 바로 가면 멀쩡한 대조군을 버린다.

## 6. 이 사이클이 남기는 교훈

1. **규칙을 만든 자리에서 그 규칙을 어기기 쉽다.** Design D-3이 *"종료 코드만 보면 공허하다"* 를 정해 놓고, 그 문서가 만든 대조군 ④의 사유 정규식이 성공 배너에 걸렸다. 규칙은 자기 자신에게도 적용해야 한다.
2. **고치지 않기로 한 것에 대해 절대 명제를 쓰지 않는다.** 범위 밖으로 미루는 판단과, 미룬 채로 "이러이러하다"를 공표하는 것은 다르다. 미룬다면 문서에 단서를 남긴다.
3. **재귀 회피는 인자에 붙는 성질이지 코드베이스에 붙는 성질이 아니다.** `--assert-only`를 만들어 놓고, 다른 인자로 자식을 띄우는 대조군을 새로 쓰자 재귀가 그대로 돌아왔다.
4. **새 단언은 기존 대조군의 전제를 바꾼다.** D-14를 더하자 최소 트리를 쓰던 ①③이 깨졌다.
5. **"되돌렸는데 통과했다"를 곧바로 "공허하다"로 읽지 않는다.** 되돌림 자체가 불완전할 수 있다 — `globals.css` 두 곳 중 하나만 되돌린 경우가 그랬다.
