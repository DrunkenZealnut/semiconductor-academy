# 관문 종료 코드 계약 검증 — Design

> Plan: `docs/01-plan/features/diagram-gate-exit-contract.plan.md`
> 범위(Plan D-1·D-2): **D-10·D-11 두 건만 · 검증만**

---

## 0. Design 단계에서 드러난 것

### 0.1 자식 프로세스 대조군은 **무한 재귀**가 된다

Plan §3의 A안(임시 cwd + 심링크)을 만들어 보니 곧바로 걸렸다.

시작 단언은 `selfTest()` **앞**에서 돈다.

```js
assertRegistryComplete();          // ← 여기서 exit 2
const globalPrefixes = assertGlobalIdPrefix();
if (!selfTest(tones)) { … }        // ← 대조군이 사는 곳
if (argv.includes('--self-test')) process.exit(0);
```

대조군을 `selfTest()` 안에 두고 자식을 `--self-test`로 띄우면, **자식의 `selfTest()`가 또 자식을 낳는다.**

**양성 두 건은 우연히 안전하다** — 시작 단언이 `selfTest` 전에 터져 자식이 거기서 끝난다. **위험한 것은 음성 대조군**이다: 정상 트리라 단언을 통과하고 `selfTest`까지 가서 손자를 낳는다. *"정상일 때 아무 일도 안 일어난다"* 를 확인하려다 무한히 프로세스를 만든다.

### 0.2 A안은 실제로 작동한다 (실측)

| 대조군 | 종료 코드 | 사유 문자열 | 총시간 |
|---|:--:|---|:--:|
| 음성 — 등록된 자료원 하나뿐 | **0** | (❌ 없음) | 28ms |
| D-10 양성 — 미등록 자료원 | **2** | `WAVES에 없는 자료원에 도해가 있다` | 25ms |
| D-11 양성 — `idPrefix` 중복 | **2** | `idPrefix가 전역에서 중복이다` | 27ms |

**합계 80ms** — 트리 구성·정리 포함. 관문의 "밀리초" 성격을 깨지 않는다(G-7).

**전체 `src/content`를 복사할 필요가 없다.** 처음에는 336개 `.mdx`를 `cpSync`했으나(73ms), 최소 트리로 충분하다 — `assertRegistryComplete`는 *도해를 가진 미등록 디렉터리*를 찾을 뿐이고, **등록됐는데 없는 디렉터리는 잡지 않는다.** 파일 두 개면 된다.

### 0.2a Do 실측 — 네 대조군의 최종 결과

| 대조군 | 종료 | 사유 판정 |
|---|:--:|---|
| ① 음성 — 정상 트리 | **0** | — |
| ② D-10 미등록 자료원 | **2** | `WAVES에 없는 자료원` |
| ③ D-11 `idPrefix` 중복 | **2** | `idPrefix가 전역에서 중복` |
| ④ `tokens.ts` 못 읽음 | **2** | `tokens.ts` |

**④는 가드를 넣기 전에 먼저 실패했다** — `종료 1 (기대 2)`. 대조군이 실제 결함을 잡고 있다는 뜻이고, 그 뒤 `readOrExit2()`를 넣어 통과로 바뀌었다. **대조군을 먼저 쓰고 고치는 순서**가 이 사이클에서 유효했다.

### 0.3 처분을 되돌리면 양성이 무너진다 (비공허성 실측)

`assertRegistryComplete()` → `assertRegistryComplete({ hard: false })`, `assertGlobalIdPrefix()` → `{ hard: false }`로 되돌린 사본:

```
✅ 음성 — 등록된 자료원 하나뿐        종료 0 (기대 0)
❌ D-10 양성 — 미등록 자료원          종료 0 (기대 2)
❌ D-11 양성 — idPrefix 중복          종료 0 (기대 2)
```

**이 대조군이 겨누는 것이 정확히 `hard`다.** 기존 `hard: false` 대조군은 이 되돌림에도 계속 통과한다 — 두 대조군이 서로 다른 것을 증명한다는 Plan D-3이 실측으로 확인됐다.

## 1. 결정

### D-1 · 이음매는 **A안(임시 cwd + 심링크)** — 생산 코드에 검사 전용 이음매를 만들지 않는다

임시 디렉터리에 `node_modules`·`docs`·`src/components`·`src/styles`를 **심링크**하고 `src/content`만 진짜로 만든다. 검사기는 이미 전부 cwd 상대 경로로 읽으므로 **cwd 자체가 이미 있는 이음매**다.

Plan §3 B안(`DGM_CONTENT_ROOT` 같은 환경변수)을 버리는 이유: **실제 실행에서 잘못 설정되면 관문이 엉뚱한 트리를 보고 눈먼 채 통과한다.** 이 저장소가 반복해서 막아 온 실패이고, 검사를 강화하려다 그 구멍을 새로 뚫는 것은 앞뒤가 안 맞는다.

### D-2 · 재귀는 **`--assert-only` 플래그**로 끊는다

시작 단언 뒤·`selfTest` 앞에서 끝내는 인자를 만든다.

```js
assertRegistryComplete();
const globalPrefixes = assertGlobalIdPrefix();
console.log(`자료원 등록 완전 · idPrefix 전역 ${globalPrefixes}개 유일\n`);

if (argv.includes('--assert-only')) process.exit(0);   // ← 신설
if (!selfTest(tones)) { … }
```

**환경변수 가드가 아니라 인자로 하는 이유**: 숨은 검사 전용 스위치가 아니라 **사람도 쓸 수 있는 정직한 의미**를 갖는다 — *"시작 단언만 돌리고 끝낸다."* 새 자료원을 추가한 사람이 등록을 확인하는 데 쓸 수 있다.

**부수 이득**: 음성 대조군이 56개 대조군을 다시 돌지 않는다. 실측 52ms → **28ms**.

### D-3 · **판정은 종료 코드 + 사유 문자열** 둘 다 본다

Plan §7이 지목한 위험이 실측에서 실제로 났다. 임시 cwd만 만들고 심링크를 안 걸면 `tokens.ts` ENOENT로 먼저 죽는다 — 그때도 "실패"지만 **D-10 때문이 아니다.**

```
종료 코드만 본다  →  심링크가 깨져도 "통과"한다        (공허)
사유까지 본다     →  D-10 때문에 2가 났음을 증명한다
```

### D-4 · `tokens.ts` 존재 가드를 **범위에 넣는다** (Plan §1.2가 Design에 넘긴 판단)

**이것은 Plan 범위의 확대다.** Plan D-1은 "D-10·D-11 두 건만"이었고, 이 건은 착수 전 실측에서 **새로 발견된 것**이라 Plan이 §1.2에 적고 판단을 Design으로 넘겼다. 넣기로 한다.

근거 셋:
1. **같은 계약이다.** 이 사이클의 주제는 "`exit 2`가 옳게 나는가"이고, `tokens.ts` 없음은 **종료 코드를 잘못 내는** 건이다(2가 아니라 1).
2. **잘못된 방향으로 틀렸다.** `--all` 부모는 `status === 2`만 중단 신호로 본다. 코드 1이면 **웨이브 실패로 집계하고 계속 진행** — 색을 하나도 못 읽는 상태로 남은 웨이브를 "검사"한다.
3. **비용이 2줄이다.** `theme.css`가 이미 같은 가드를 갖고 있어 형태를 그대로 따른다.

**대가**: 대조군이 하나 더 는다(3 → 4). 그것까지 포함해도 총시간은 100ms대다.

> **범위를 넓히는 결정을 여기 명시해 둔다.** 선행 `diagram-gate-coverage`는 범위 밖 항목을 결정 없이 고쳐 Check에서 감점됐다. 이번에는 Plan이 판단을 위임했고 Design이 이유를 적어 결정한다 — 그 차이가 중요하다.

## 2. 대조군 설계

| # | 대조군 | 기대 | 겨누는 것 |
|:--:|---|---|---|
| ① | **음성** — 등록된 자료원 하나뿐인 정상 트리 | 종료 **0** | 하네스 자체. 이것이 0이 아니면 ②③④가 전부 공허하다 |
| ② | **D-10 양성** — 미등록 자료원에 도해 | 종료 **2** + 사유가 `WAVES에 없는 자료원` | D-10의 **처분** |
| ③ | **D-11 양성** — `idPrefix` 전역 중복 | 종료 **2** + 사유가 `idPrefix가 전역에서 중복` | D-11의 **처분** |
| ④ | **D-4 양성** — `src/components` 심링크 없음 | 종료 **2** + 사유가 `tokens.ts` | 읽기 실패가 1이 아니라 2로 나는가 |

**①을 먼저 만든다.** 하네스가 틀리면 양성이 "통과"해도 아무 의미가 없다 — §0.1이 그 실증이다.

**기존 `hard: false` 대조군 3건은 그대로 둔다.** 감지와 처분은 다른 주장이고, §0.3이 둘이 다른 것을 증명함을 보였다.

대조군 **56 → 60** (Check에서 ⑤⑥⑦⑧을 더해 최종 **64**).

### 3.1 G-7 미충족 — 관문이 두 배가 됐다

```
HEAD --all   0.56초
Do   --all   1.07초      (단독 --wave 실측 0.09 → 0.18초)
현재 --all   1.72초      (Check에서 대조군 4건 추가)
```

**원인은 중복이다.** `--all` 부모는 `selfTest`를 돌지 않고 자식 5개를 띄운다. 자식이 **각자** 종료 코드 대조군을 돌아 **손자 20개**가 뜬다 — 같은 사실 8개를 40번 증명한다.

**중복 제거를 하지 않기로 했다.** 부모가 한 번만 돌게 하려면 자식이 "나는 자식이다"를 알아야 하고, 어떤 형태(환경변수·내부 플래그)든 **잘못 쓰면 대조군을 건너뛴다**는 성질을 갖는다. 그것은 D-1에서 B안을 버린 이유와 같은 종류의 위험이고, **Design이 정하지 않은 결정**이다.

대신 **비용을 인정하고 `CLAUDE.md`를 실측값("약 1.7초")으로 고쳤다.** 문서가 광고하는 값이 거짓이 되는 쪽이 더 나쁘다. 중복 제거는 백로그로 넘긴다.

> **G-7은 "빠르다"가 아니라 "문서와 맞다"로 충족된다고 다시 읽을 수도 있었다.** 그렇게 재정의하지 않았다 — 게이트를 통과시키려고 게이트의 뜻을 바꾸는 것이기 때문이다. **미충족으로 적고 이유를 남긴다.**

### 3.2 Do 중 발견 → **Check에서 처분** (D-4 확장)

Do 중 `globals.css`에 가드가 없는 것을 발견하고 **고치지 않은 채 Check에 올렸다.** Check(H-2)가 그 판단을 이렇게 갈랐다.

> 범위 밖 항목을 결정 없이 고치지 않은 것은 옳다 — 선행 사이클의 감점 사유를 반복하지 않았다.
> 어긋난 것은 **고치지 않은 채 절대 명제를 문서에 새로 새긴 것**이다.

맞는 지적이다. `CLAUDE.md`·`usage.md`에 *"팔레트·토큰을 못 읽으면 2"* 를 **단서 없이** 못 박아 놓고 세 경로(`globals.css` · 콘텐츠 루트 부재 · Tone 파싱 실패)가 **1**을 내고 있었다. 둘 중 하나였어야 했다 — 고치거나, 공표한 계약에 단서를 달거나.

**Check에서 고치는 쪽을 골랐다.** Check가 찾은 것을 고치는 것은 범위 위반이 아니라 사이클이 도는 것이다.

## 4. 구현 순서

```text
① --assert-only 플래그 (D-2)              ← 이것 없이는 ②가 재귀한다
② 하네스 + 대조군 ① 음성                  ← 하네스가 옳게 도는지가 먼저
③ 대조군 ② D-10 + 되돌려 실패 확인
④ 대조군 ③ D-11 + 되돌려 실패 확인
⑤ tokens.ts 가드 (D-4) + 대조군 ④
⑥ 문서 · Check
```

①이 맨 앞인 이유는 §0.1이다. ②가 ③④보다 앞인 이유는 §2의 ①이다.

## 5. 위험

### 5.1 G-4 실측 — 되돌리면 무엇이 깨지나

```
D-10 처분 제거 (hard: false)          → ❌ 실패  ② D-10 미등록 자료원 → exit 2
D-11 처분 제거 (hard: false)          → ❌ 실패  ③ D-11 idPrefix 전역 중복 → exit 2
tokens.ts 가드 제거 (readOrExit2 무력화) → ❌ 실패  ④ tokens.ts를 못 읽으면 exit 1이 아니라 exit 2
```

셋 다 **해당 대조군만** 깨진다 — 되돌림이 엉뚱한 것을 무너뜨리지 않는다는 것까지 확인됐다. 기존 `hard: false` 대조군 3건은 앞의 둘을 되돌려도 계속 통과한다(§0.3).

### 5.2 남은 위험

| 위험 | 대응 |
|---|---|
| **심링크가 깨져 다른 이유로 2가 난다** | D-3(사유 문자열까지 판정). 실측에서 실제로 겪었다 |
| **음성 대조군이 재귀한다** | D-2(`--assert-only`). 자식이 `selfTest`에 도달하지 않는다 |
| **자식이 소스 트리를 오염** | G-5. 선행 PR #34에서 프로브가 `src/`에 새어 `typecheck`를 깨뜨린 전례가 있다 |
| **`--assert-only`가 관문을 우회하는 데 쓰인다** | 이 인자는 **본 검사를 건너뛴다** — 사람이 `verify:diagram` 대신 이것을 쓰면 아무것도 검사하지 않는다. 출력에 그 사실을 명시한다 |
| **범위가 D-4로 넓어진 것을 잊는다** | Design D-4에 확대 사실과 근거를 적었다. Check에서 이 문단을 근거로 판정한다 |
