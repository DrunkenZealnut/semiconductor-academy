## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 검사기에 `exit 2` 경로가 **12개**인데 **종료 코드로 검증된 것이 0개**다. 대조군 56건은 전부 in-process 반환값만 본다. D-10·D-11은 결정문 자체가 *"경고가 아니라 실패"* 인데, 그 **처분**이 검사 밖에 있다. |
| **Solution** | `spawnSync`로 검사기를 자식 프로세스로 띄워 **종료 코드를 단언하는** 대조군을 만든다. D-10(미등록 자료원)·D-11(`idPrefix` 전역 중복) 두 건이 실제로 **2**를 내는지 고정한다. |
| **Function · UX Effect** | 독자에게 보이는 변화는 없다. 이것은 **검사기가 자기 계약을 지키는지** 보는 사이클이다. |
| **Core Value** | **결정문과 실행을 잇는다.** "감지한다"와 "감지하면 실패한다"는 다른 주장이고, 지금은 앞의 것만 증명돼 있다. |

## 1. 문제

`diagram-gate-coverage` Check가 L-3으로 남긴 것:

> D-10·D-11 대조군이 `hard: false`라 **`exit 2` 처분 자체는 미검증**이다. "경고가 아니라 실패"가 D-10의 핵심인데 그 핵심이 대조군 밖에 있다.

**R-1과 같은 모양이다.** R-1도 "사실을 적는 데서 멈춘" 항목이었고 한 사이클을 통째로 썼다. 여기서도 *결정은 적혀 있고 이행은 절반만 증명돼 있다*.

### 1.1 착수 전 실측

**`exit 2` 경로 12개 · 종료 코드로 검증된 것 0개.**

| 사유 | 위치 | 대조군 |
|---|---|:--:|
| 팔레트·토큰 읽기 실패 4종 | L124 · L136 · L234 · L246 | 반환값만 |
| C-19 해석 실패 | L356 | 반환값만 |
| 배치표 없음 | L1561 | 없음 |
| **D-10 미등록 자료원** | L1607 | **`hard: false`** |
| **D-11 `idPrefix` 전역 중복** | L1637 | **`hard: false`** |
| 자체검사 실패 → 본 검사 미실행 | L1654 | 없음 |
| 인자 오류 3종 | L1670 · L1678 · L1682 | 없음 |

`--all` 부모의 배관도 미검증이다.

```js
const r = spawnSync(process.execPath, [process.argv[1], ...args], { stdio: 'inherit' });
if (r.status === 2) process.exit(2);   // ← 이 줄이 도는지 아무도 안 본다
if (r.status !== 0) failed += 1;
```

**유리한 사실 하나** — `spawnSync`는 이미 `--all` 경로에서 쓰이고 있다. 자식 프로세스 대조군에 새 의존성이 필요 없다.

### 1.2 실측 중 발견한 결함 — `tokens.ts`에 존재 가드가 없다

임시 cwd에서 검사기를 돌려 시작 단언을 터뜨리려다 **먼저 다른 것이 터졌다**.

```
Error: ENOENT: no such file or directory, open 'src/components/diagram/tokens.ts'
실제 종료코드: 1
```

`theme.css`는 L122가 `existsSync`로 막아 `exit 2`를 내는데, **`tokens.ts`는 가드 없이 `readFileSync`** 라 ENOENT가 그대로 올라가고 Node가 **코드 1**을 낸다.

이 검사기의 계약에서 **1 = 콘텐츠 위반**, **2 = 검사기가 자기 범위를 주장할 수 없음**이다. 토큰 파일이 없는 것은 명백히 후자인데 전자로 나온다. 그 결과 `--all` 부모는 이것을 **중단 신호가 아니라 웨이브 실패로 집계하고 계속 진행**한다 — 색을 하나도 못 읽는 상태에서 남은 웨이브를 "검사"한다.

> **선행 사이클이 세운 규약을 그대로 어긴다** — `diagram-render-gate`의 *"색을 못 읽는 것은 '통과'가 아니다"*. 못 읽는 것을 통과로 처리하지는 않지만, **콘텐츠 위반으로 오분류**한다.

이 건은 D-10·D-11과 **같은 계약**(종료 코드의 의미)에 속하므로 Design에서 범위 편입 여부를 판단한다.

## 2. 결정

### D-1 · 범위는 **D-10·D-11 두 건**만 (사용자 결정)

L-3 문언대로 간다. 나머지 10개 경로는 남긴다.

**대가를 적어 둔다**: 자식 프로세스 하네스를 한 번 만들면 나머지는 거의 공짜다. 지금 안 하면 **같은 성격의 백로그가 그대로 남고**, 다음에 또 "결정은 적혀 있고 처분은 미검증"이 반복된다. 이 선택은 범위를 좁혀 사이클을 확실히 닫는 쪽이고, 하네스가 생기면 후속이 싸진다는 것이 근거다.

### D-2 · 종료 코드 **소비자는 만들지 않는다** (사용자 결정)

CI·git 훅·`prebuild` 연결 모두 범위 밖. 지금도 `--all` 부모가 자식의 `status === 2`를 소비하므로 종료 코드가 무의미하지 않다 — 이 사이클은 **그 소비가 옳게 도는지**만 본다.

### D-3 · 대조군은 **종료 코드를 단언한다**

`hard: false`로 반환값을 보는 기존 대조군을 **없애지 않는다.** 둘은 다른 것을 증명한다.

```
hard: false   "미등록을 감지한다"        ← 이미 있음, 유지
자식 프로세스  "감지하면 2로 끝난다"      ← 이 사이클
```

## 3. 열린 문제 (Design에서 정한다)

**시작 단언을 터뜨리려면 검사기가 잘못된 트리를 보게 해야 하는데, 그 이음매를 어디에 둘 것인가.** §1.2가 보여주듯 순진한 방법은 공허 대조군을 만든다.

| 안 | 방법 | 위험 |
|---|---|---|
| **A. 임시 cwd + 심링크** | 임시 디렉터리에 `node_modules`·`src/styles`·`src/components`를 심링크하고 `src/content`만 조작 | 생산 코드에 이음매 0. 심링크 구성이 깨지면 **다른 이유로 exit 2**가 나 공허해진다 — 그것을 막는 음성 대조군이 필요하다 |
| **B. 환경변수 root 재정의** | `DGM_CONTENT_ROOT` 같은 것을 읽게 한다 | **생산 코드에 검사 전용 이음매**가 생긴다. 실제 실행에서 잘못 설정되면 관문이 엉뚱한 트리를 보고 **눈먼 채 통과**한다 — 이 저장소가 반복해서 막아 온 실패다 |
| **C. 처분 분리** | 단언은 결과만 반환하고 별도 함수가 종료 코드를 정한다 | 종료 코드 결정은 검사할 수 있으나 **배선(main이 실제로 그것을 부르는가)** 은 여전히 미검증 |

**A가 유력하다** — 생산 코드를 건드리지 않는 것이 이 저장소의 우선순위와 맞는다. 다만 A의 위험이 바로 이 사이클이 고치려는 병(공허 대조군)과 같은 종류라, **"exit 2가 났다"가 아니라 "D-10 때문에 exit 2가 났다"를 구별**하는 판정이 필수다(표준 출력의 사유 문자열까지 본다).
