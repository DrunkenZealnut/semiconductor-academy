| **Solution** | `spawnSync`로 검사기를 자식 프로세스로 띄워 종료 코드를 단언하는 대조군 설계. 임시 cwd + 심링크(생산 코드 무오염) + `--assert-only` 플래그(재귀 제어) + 사유 문자열까지 판정(거짓 통과 방지). |
| **Function · UX Effect** | **독자에게 보이는 변화는 없다.** 이 사이클은 **검사기가 자기 계약을 지키는지 보는 사이클**이다. 도해 렌더나 사용자 경험은 변함이 없다. |

## 3. 주요 발견 및 교훈

### 이 사이클이 세운 규칙 실증

**Design D-3**: *"종료 코드만 보면 공허하다"* → 종료 코드 + 사유 문자열 둘 다 본다

이 규칙을 정한 바로 그 문서가 만든 대조군 ④에서 사유 정규식이 **성공 배너에 걸려** 실제로는 공허했다. **규칙을 만든 자리에서 그 규칙을 어기기 쉽다는 것의 실증.**

### 범위를 좁힐 때의 위험

**Do에서 발견한 `globals.css` 가드 부재**를 "범위 밖이니 Check에 올린다"고 판단한 것은 옳았다. 틀린 것은 **고치지 않은 채로 `CLAUDE.md`·`usage.md`에 "팔레트·토큰을 못 읽으면 2"를 단서 없이 못 박은 것**이다.

> 미루려면 문서에 단서를 남긴다. 고치거나, 고치지 않으면 공표한 계약이 거짓이 되지 않도록 문구를 보정한다.

### 재귀 회피는 코드베이스에 붙는 성질이 아니라 인자에 붙는 성질

`--assert-only` 플래그를 설계하고 나서도 새 대조군 ⑧을 다른 인자로 띄우자 **재귀가 그대로 돌아왔다.** 나중에 인자를 추가할 때마다 회피 로직을 다시 확인해야 한다.

### 새 단언이 기존 대조군의 전제를 바꾼다

D-14 시작 단언을 넣자 **최소 트리를 쓰던 기존 대조군 ①③이 깨졌다** — 등록 자료원 14개 중 하나만 만들었기 때문. 하네스가 등록 디렉터리를 전부 빈 채 만들도록 수정했다.

### 되돌림 실험의 완성도

**"되돌렸는데 통과했다"가 곧 "공허하다"는 뜻이 아니다.** `globals.css` 가드는 두 곳인데 하나만 되돌리니 다른 하나가 먼저 걸려 실패로 보였고, 둘 다 되돌리니 깨졌다. **되돌림 자체가 불완전할 수 있다.**

## 4. 기술 세부사항

### 이음매 설계: 임시 cwd + 심링크

```
임시 디렉터리 (생산 코드 무오염)
├── node_modules → (실제 심링크)
├── docs → (실제 심링크)
├── src/
│   ├── components/ → (실제 심링크)
│   ├── styles/ → (실제 심링크)
│   └── content/ → (실제 콘텐츠 — 시나리오별로 조작)
└── scripts/ → (실제 심링크)
```

- 검사기는 전부 cwd 상대 경로로 읽으므로 **cwd 자체가 이미 있는 이음매**
- 생산 코드에 검사 전용 이음매 0

### 재귀 제어: `--assert-only` 플래그

```js
assertRegistryComplete();
const globalPrefixes = assertGlobalIdPrefix();
console.log(`자료원 등록 완전 · idPrefix 전역 ${globalPrefixes}개 유일\n`);

if (argv.includes('--assert-only')) process.exit(0);  // ← D-2
if (!selfTest(tones)) { … }
```

- 시작 단언 뒤·`selfTest` 앞에서 끝남
- 정상 트리에서는 음성 대조군이 재귀하지 않음 (손자 대조군 불가)
