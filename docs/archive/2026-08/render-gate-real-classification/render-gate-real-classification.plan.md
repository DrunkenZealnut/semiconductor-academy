# 실제 컴포넌트의 분류를 서버 없이 주장한다 (R2) — Plan

> **선행**: `render-gate-derivation-claim`(90%, 2026-08-30 아카이브) 잔존 **D-5**
> **한 줄**: 규칙이 옳게 **동작한다**(R1)는 닫혔다. 규칙이 **실제 컴포넌트를** 옳게 가른다(R2)는 아직 서버가 필요하다.

---

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 선행 사이클이 **B-8을 절반만 닫았다.** 유도 규칙(`*.tsx` 중 `'<svg'` 포함)이 **옳게 동작한다**(R1)는 ㉘이 가짜 트리로 증명한다. 그러나 **실제 12종이 그 규칙에 옳게 분류되는가**(R2)는 여전히 **서버·브라우저·약 2분**이 드는 본 검사(δ)만 본다. 부분 오분류 — 한 종만 유도에서 빠지는 것 — 는 자체검사가 **아예 못 본다**(선행 G-5 실측: `LayerStack` 하나만 빼면 자체검사 통과·본 검사만 `δ LayerStack — 36페이지`). |
| **Solution** | **근거가 다른 둘째 신호로 대조한다.** 착수 전 실측: 유도(`'<svg'`) **6종**과 `<text` 보유 **6종**이 **정확히 일치**하고, G-5를 재현하면(`LayerStack`만 제외) **어긋남이 즉시 잡힌다** — **0.42ms · 서버 불필요.** 이 저장소에 선례가 있다 — γ가 배럴과 `readdir`를 *"같은 디렉터리를 보지만 근거가 다르다"* 로 대조한다. |
| **Function · UX Effect** | **독자에게 보이는 변화는 없다.** 검사기가 **실제 컴포넌트에 대한** 자기 분류를 증명하는 사이클이다. |
| **Core Value** | *"규칙이 옳게 동작한다"* 와 *"규칙이 실제를 옳게 가른다"* 는 다른 주장이다. R2를 **서버 없이** 덮으면 부분 오분류가 **약 2분 → 1ms**로 내려온다 — 그리고 **남는 잔여를 정확히 그린다.** |

## 1. 착수 전 실측

### 1.1 지금 무엇이 어떻게 갈리나

```text
ALL     12종  (DiagramFrame은 래퍼라 명시적으로 뺀다)
유도    6종   CurvePlot · LabeledFigure · LatticeDiagram · LayerStack · NodeGraph · ScaleRuler
비유도  6종   CompareCards · FlowSteps · Timeline · TreeBranch · TruthTable · ValueBars
배럴    12종
```

### 1.2 ★근거가 다른 둘째 신호가 이미 있다

| 신호 | 무엇을 묻나 | 결과 |
|---|---|---|
| `'<svg'` (현재 유도) | **SVG를 그리는가** | 6종 |
| `<text` | **거기에 글자를 넣는가** | **6종 — 정확히 일치** |

**어긋남 0.** 그리고 `SVG인데 <text> 없음`·`비SVG인데 <text> 있음` 둘 다 **없다.**

### 1.3 ★선행 G-5를 서버 없이 잡는다

```text
정상                        일치
LayerStack 하나만 제외      ★어긋남 — `<text만: LayerStack`
```

**선행 사이클이 G-6으로 요구했다가 "R2는 못 한다"로 남긴 바로 그 모양**이고, 여기서는 **0.42ms**에 잡힌다.

| | 증거 | 비용 |
|---|---|---|
| 지금 | 본 검사의 δ | **서버 + 브라우저 + 약 2분** |
| 후보 | 두 유도의 대조 | **0.42ms** |

### 1.4 ★맹점을 먼저 적는다

**두 신호가 함께 사라지면 조용하다.** 파일에서 `<svg`와 `<text`를 **모두** 지우면 6=5로 같이 줄어 대조가 성립한다. 그때는 **관측(브라우저)만** 어긋남을 본다.

> 그러므로 이 사이클은 R2를 **다 닫지 못한다.** 닫는 것은 *"규칙이 실제 종 하나를 놓친다"* 이고,
> 남는 것은 *"컴포넌트가 실제로 SVG 그리기를 그만뒀다"* 다. **그 경계를 정확히 그리는 것이 이 사이클의 절반이다.**

## 2. 열린 문제 — Design이 실측으로 정한다

| # | 문제 |
|:--:|---|
| **A** | **둘째 신호 대조**와 **유도 규칙 자체를 바꾸는 것**(`'<svg'` → `'<svg' && '<text'`) 중 무엇인가. 후자는 규칙이 δ의 실제 의도(*"글자 있는 SVG"*)에 가까워지지만 **대조자가 사라져 미러가 없어진다.** 전자는 미러를 남기지만 규칙은 여전히 의도와 어긋난 채다. **둘 다 걸어 보고 무엇이 무엇을 배타적으로 잡는지 잰다** (사용자 선택) |
| **B** | **어디에 놓나.** `scopeStatic`의 새 판정(η?)인가, 시작 단언인가, 별도 함수인가. 판정이면 종료 코드 계약(`2` = 검사기가 자기 범위를 주장할 수 없음)에 맞고 대조군을 붙일 수 있다 |
| **C** | **`<text`가 정말 독립인가.** 같은 파일을 읽으므로 **파일 단위 훼손에는 함께 흔들린다.** 독립성은 *"어떤 성질을 묻는가"* 수준이다. γ(배럴 vs readdir)는 **다른 파일**을 읽어 더 독립적이다 — 이 차이를 문서에 적을 것인가, 아니면 더 독립적인 셋째 신호가 있나(예: MDX 사용처, `data-diagram` 리터럴) |
| **D** | **잔여를 어떻게 고정하나.** §1.4의 맹점은 본 검사만 본다. *"조용히 빠지는 것과 이유를 적고 빠지는 것은 다르다"* — 검사로 고정할 수 없다면 **어디에** 적나 |

## 3. 기능 요구

| # | 내용 |
|:--:|---|
| FR-1 | **실제 컴포넌트의 분류를 서버 없이 주장한다** — 유도 결과와 근거가 다른 둘째 신호를 대조 |
| FR-2 | **부분 오분류를 잡는다** — 선행 G-5(`LayerStack` 하나만 제외)를 서버 없이 재현하고 검출 |
| FR-3 | 새 판정에 **대조군**을 붙인다 — 이 저장소의 규약(*판정을 만들면 그것을 주장하는 대조군을 함께 만든다*) |
| FR-4 | **감사에 그 판정의 훼손을 더한다** — 주장 대조군(`wantBroken`)과 함께 |
| FR-5 | **맹점을 검사가 아니라 문서로 고정한다** — §1.4. R2가 **다 닫히지 않는다**는 사실과 그 경계 |
| FR-6 | 되돌려 확인하고 기록 (FR-7 관례) |
| FR-7 | 새 손 숫자를 만들면 **유도값과 대조**한다 — 선행 사이클의 원칙(§7.5) |

## 4. 게이트

| # | 충족 |
|:--:|---|
| G-1 | `typecheck` 0 · `lint` 0 |
| G-2 | `verify:diagram` 5웨이브 전 항목 통과 |
| G-3 | 자체검사 전 항목 통과 (대조군 36 → N) |
| G-4 | 감사 배선·규칙 전 항목 · 원복 확인 |
| **G-5** | ★**선행 G-5를 서버 없이 재현·검출** — `LayerStack` 하나만 유도에서 빼면 **자체검사가 운다** |
| **G-6** | ★**잔여의 경계가 문서에 그려진다** — 무엇이 닫혔고 무엇이 본 검사에 남는지 |
| G-7 | FR-6 되돌림 기록 |
| G-8 | 감사 시간 실측 — 항목이 늘면 `(배선 + 규칙) × 자체검사`로 곱해진다(선행 §4.3) |

**G-5가 이 사이클의 숫자다.** 선행 사이클이 *"의도한 결과"* 로 남긴 것을 실제로 닫는다.

## 5. 착수 순서

```text
① 두 후보(A)를 시제품으로 걸어 본다 — 무엇이 무엇을 배타적으로 잡는지 먼저 잰다
② 감사에 그 판정의 훼손을 더해 지금이 0/N임을 고정
③ 판정 신설 → 감사 재실행 (N/N이 되어야 한다)
④ 대조군 → 되돌려 확인
⑤ 잔여의 경계를 문서에 그린다 · Check
```

**①이 먼저인 이유는 네 사이클 연속으로 같다** — 착수 전 실측이 매번 설계를 뒤집었다. 특히 선행 사이클은 *"요구가 무엇을 잡는지 재 보지 않으면 장식을 주장으로 착각한다"* 를 두 번 겪었다.
