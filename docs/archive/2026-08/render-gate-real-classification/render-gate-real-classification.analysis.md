## 1. ★G-A — 이 사이클의 주제가 **거꾸로** 남아 있었다

**자리**: `audit-render-wiring.mjs` 성공 요약 줄

```text
:535   ※ R1만 잰다. R2는 서버가 필요한 본 검사만 본다.
:189   // 실제 트리를 쓰는 ㉛이 그것을 본다(R2).
:328   //   ${REAL_TEXTUAL_KIND} → 실제 저장소에서 η가 운다 → **R2**
```

**같은 파일 안에서 모순**이고, **사람이 보는 쪽이 틀렸다.**

선행 사이클에는 그 문장이 참이었다. η·㉛이 서면서 R2의 대부분이 여기로 왔는데 **문구만 그대로 남았다.**

> 이 사이클의 최상위 위험은 *"닫았다고 적고 안 닫는 것"* 이었다.
> **그 반대(닫았는데 안 닫았다고 적는 것)를 감사의 마지막 줄에 남겼다.**
> 다음 사람이 그 줄을 읽고 R2를 다시 열린 것으로 취급한다.

## 2. G-B·G-C — 둘째 유도가 **첫째만큼의 보호를 못 받았다**

| | `'<svg'` 유도 | `<text` 유도 (신설) |
|---|:--:|:--:|
| 시작 가드 | ✅ | ❌ → **G-B** |
| 감사 규칙 훼손 | 4건 | **0건** → **G-C** |
| 요약 문구의 인정 | ✅ | ❌ → **G-A** |

**셋이 한 뿌리다.** 판정을 하나 더하면 그 판정을 지키는 장치도 함께 만들어야 하는데, **판정만 만들었다.**

### 2.1 G-B가 왜 중한가

`textual`이 비면 η가 *"SVG로 분류됐는데 글자가 없다"* 를 **6줄** 낸다 —
실제 6종이 동시에 글자를 잃는 **불가능한 세계**이고, **검사기가 자기 고장을 콘텐츠 탓으로** 말하는 것이다.

㉗이 세운 원칙 그대로다 — *종료 코드는 둘 다 2지만 진단이 달라야 한다.* `SVG_COMPONENTS`와 **대칭인** 가드를 넣었다.

## 3. ★훼손의 모양을 재 보지 않으면 엉뚱한 것을 건다

G-C를 고치며 *"둘째 유도를 **반전**하면 시작 가드가 잡는다"* 고 적고 규칙을 그렇게 걸었다. **틀렸다.**

| 훼손 | 실측 |
|---|---|
| **반전** (`!/<text`) | textual이 **여집합**이 된다 → ⑲⑳㉒㉕㉖㉗이 먼저 터지고 **㉛은 안 깨진다** · 가드도 안 걸린다(비는 게 아니라 뒤집힌다) |
| **삭제** | 전 종이 textual → 비SVG 6종이 η로 운다 → **㉛이 깨진다** ✅ |

삭제로 바꾸고 주장 행(`wantBroken: ['㉛']`)으로 되돌렸다.

> 선행 사이클이 ㉘·㉚에서 배운 것과 같다 — **요구가 무엇을 잡는지 재라.** 이번엔 **훼손이 무엇을 바꾸는지** 재야 했다.

## 4. G-E — 잔여를 실제보다 작게 그렸다

설계 §5 초판은 잔여를 ④ 하나로 좁혔다. η가 대조하는 것은 **두 개의 어휘 술어**이므로 잔여는 더 넓다 — ④b(죽은 텍스트) · ④c(조건부 렌더) · ④d(빈 `<text>`) · ④e(`foreignObject`).

**이것이 최상위 위험이 걸린 자리다.** *"다 닫았다고 적는 것"* 을 완전히 피하지 못했고, 판독이 그것을 잡았다. §5.1로 다시 썼다.

## 8. 이 사이클이 남기는 문장

> **유도를 하나 더 만들었으면 보호도 하나 더 만들어야 한다.**
> 가드도, 규칙도, 요약 문구도. 판정만 만들면 그 판정이 **첫째만큼 지켜지지 않는다.**

그리고 하나 더 — **성공 메시지는 성공이 아니다.** 편집 스크립트가 파일에 쓰지 않았는데 `✅`가 일곱 개 찍혔고, 자체검사 수를 세어서야 알았다.
