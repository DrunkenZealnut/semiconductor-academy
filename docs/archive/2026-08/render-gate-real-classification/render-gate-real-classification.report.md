## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 선행 사이클이 **B-8을 절반만 닫았다.** 유도 규칙(`*.tsx` 중 `'<svg'`)이 **옳게 동작한다**(R1)는 ㉘이 가짜 트리로 증명했지만, **실제 12종이 그 규칙에 옳게 분류되는가**(R2)는 여전히 **서버·브라우저·약 2분**이 드는 본 검사(δ)만 봤다. 유도가 실제 종 **하나만** 놓쳐도 자체검사는 조용했다(선행 G-5: `LayerStack` 하나만 빼면 `δ LayerStack — 36페이지`). |
| **Solution** | **근거가 다른 둘째 유도를 세워 대조한다.** `'<svg'`가 *"SVG를 그리는가"* 를 묻고 `<text`가 *"거기에 글자를 넣는가"* 를 묻는다 — δ의 실제 대상이 **글자 있는 SVG**이므로 둘은 같아야 하고, 어긋나면 **η**로 `exit 2`다. 브라우저 앞에서 돌고 **0.42ms**다. |
| **Function · UX Effect** | **독자에게 보이는 변화는 없다.** 다만 **저작자에게는 있다** — 새 도해 종은 이제 *"글자 있는 SVG인가, 장식인가, HTML인가"* 를 **명시해야** 한다(`usage.md` §2.1.1d′). |
| **Core Value** | R2의 대부분이 **약 2분 → 1ms**로 내려왔다. 그리고 **남는 경계를 정확히 그렸다** — 선행이 *"R2는 본 검사만 본다"* 였다면 지금은 *"R2 중 **두 어휘 술어가 못 가르는 것**만 본 검사가 본다"* 다. |

## 1. 무엇을 만들었나

### 1.1 η — 두 유도가 어긋난다

```text
η {종} — SVG로 분류됐는데 글자가 없다
η {종} — 글자가 있는데 SVG로 분류되지 않았다
```

`scopeStatic()`에 넣었다 — γ·ε·α₀·σ와 **같은 뜻의 `exit 2`**다. *검사기가 자기 범위를 주장할 수 없다.*

**η는 관측을 하나도 안 한다.** 그래서 `1`(콘텐츠 위반)을 낼 자격이 없다 — 파일만 보고 지목하면 그것이 ㉚이 막는 **거짓 지목**이다. ⑤가 결함인지 정당한 장식인지는 파일만으로 못 가르고, 그래서 사유가 *"장식이면 `DiagramFrame`처럼 이유를 적고 빼라"* 로 **사람에게 넘긴다.**

### 1.2 대조군 (36 → 40)

| 무리 | 대조군 | 무엇을 주장하나 |
|---|---|---|
| **범위** | ⑰f · ⑰g · ⑰h | 판정 함수가 두 방향을 옳게 낸다 |
| **처분** | **㉛** | ★**실제 트리**에서 η가 돈다 — **R2** |

**㉛은 ⑳과 함께 실제 트리를 쓰는 둘째 대조군이다.** R2는 정의상 실제 트리에서만 주장할 수 있다 — 가짜 트리에서 증명하면 **R1이지 R2가 아니다.**

`denyReason: [/η /]`이 **유일한 판별자**다(실측 — 제거하면 훼손에서 통과한다). 선행 ㉚에서 `denyReason`이 **장식**으로 드러난 적이 있어 이번엔 재서 확인했다.

### 1.3 감사 (배선 11 → 12 · 규칙 4 → 5)

| 항목 | 주장 대조군 |
|---|---|
| `scopeStatic.textual` 비우기 | ㉛ |
| `한 종만 제외`(가짜 종 + **실제 종**) | ㉘(R1) · **㉛(R2)** |

## 4. ★Check가 잡은 것 — **유도를 하나 더 만들었는데 보호는 안 만들었다**

| | `'<svg'` 유도 | `<text` 유도(신설) |
|---|:--:|:--:|
| 시작 가드 | ✅ | ❌ → **G-B** |
| 감사 규칙 훼손 | 4건 | **0건** → **G-C** |
| 요약 문구의 인정 | ✅ | ❌ → **G-A** |

### 4.1 G-A가 가장 아프다

```text
:535   ※ R1만 잰다. R2는 서버가 필요한 본 검사만 본다.
:189   // 실제 트리를 쓰는 ㉛이 그것을 본다(R2).
```

**같은 파일 안에서 모순**이고, **사람이 보는 쪽이 틀렸다.**

> 이 사이클의 최상위 위험은 *"닫았다고 적고 안 닫는 것"* 이었다.
> **그 반대(닫았는데 안 닫았다고 적는 것)를 감사의 마지막 줄에 남겼다.**
> 다음 사람이 그 줄을 읽고 R2를 다시 열린 것으로 취급한다.

### 4.2 G-E — 잔여를 실제보다 작게 그렸다

설계 §5 초판은 잔여를 ④(두 신호가 함께 사라짐) 하나로 좁혔다. **η가 대조하는 것은 두 개의 어휘 술어**이므로 잔여는 넓다 — ④b(주석에만 남은 `<text`) · ④c(조건부 렌더) · ④d(빈 `<text></text>`) · ④e(`foreignObject`).

**최상위 위험이 걸린 자리였고, 완전히 피하지 못했다.** 판독이 잡아 §5.1로 다시 썼다.

## 5. η가 조용하던 거짓말 둘을 드러냈다

| 자리 | 무엇이 틀렸나 |
|---|---|
| ⑰b(γ 대조군) | 파일이 디렉터리를 떠났는데 `textual`엔 남아 있었다 — **파일이 없는데 글자는 있다** |
| **`SVGC` 스텁** | `<svg`만 있고 `<text`가 없었다 — 실제 6종은 **모두** 글자가 있는데 |

**`SVGC`가 더 무겁다. 처분 대조군 11건이 그 위에서 돌고 있었다.** 스텁이 실제와 다른 성질을 가지면 **가짜 트리가 불가능한 세계**가 되고, 거기서 얻은 통과는 아무것도 뜻하지 않는다.

> **판정을 하나 더하면 기존 fixture가 그 판정에게도 말을 건다.** 그때 조용하던 거짓말이 드러난다.

## 8. 교훈

> **유도를 하나 더 만들었으면 보호도 하나 더 만들어야 한다.**
> 가드도, 규칙도, 요약 문구도. 판정만 만들면 그 판정이 **첫째만큼 지켜지지 않는다.**

둘이 더 붙는다.

1. **훼손이 무엇을 바꾸는지 재라.** 선행이 ㉘·㉚에서 *"요구가 무엇을 잡는지 재라"* 를 배웠다면, 이번엔 그 짝을 배웠다 — 반전과 삭제는 다른 것을 깨뜨린다.
2. **성공 메시지는 성공이 아니다.** 편집 스크립트가 파일에 쓰지 않았는데 `✅`가 일곱 개 찍혔고, **자체검사 수를 세어서야** 알았다.
