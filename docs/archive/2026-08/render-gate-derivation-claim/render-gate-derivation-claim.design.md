# 렌더 관문 유도 규칙의 주장 — Design

> Plan: `./render-gate-derivation-claim.plan.md`
> **한 줄**: 거를 것이 없는 트리에서는 거르는 규칙을 검사할 수 없다.

## 0. Design 착수 실측 — 시제품이 결정적인 것을 뒤집었다

㉖(음성 자식)에 `범위: 유도 1종 · 배럴 1종`을 요구해 규칙 훼손 3종을 걸어 봤다.

```text
음성            exit 0 · 통과            ← 주장 자체는 성립한다
D-1 규칙 삭제   ㉖ 안 깨짐 · ㉒㉓만 깨짐   ← ★주장이 못 잡았다
D-2 반전        ㉖ 깨짐 ✅
D-3 오타        아무도 안 깨짐 · 시작 가드가 잡는다
```

### 0.1 ★왜 D-1을 못 잡았나 — **거를 것이 없는 트리**

㉖의 `CLEAN` 트리에는 `Alpha.tsx` **하나**뿐이다. 그 하나가 `<svg`를 갖고 있으므로 **필터를 지워도 유도 결과가 그대로 1종**이다. ㉒㉓이 D-1을 잡는 것은 그 트리에 `Extra.tsx`(비SVG)가 **함께** 있기 때문이다.

→ **D-1. 규칙을 주장하는 대조군의 트리는 `<svg` 있는 종과 없는 종을 **둘 다** 가져야 한다.** 그리고 배너로 유도 결과를 요구한다.

> **★초판의 `유도 1종 / 배럴 2종`은 둘 다 틀렸다**(Check) — 실패 경로의 배너에 배럴이 없고,
> 대칭 fixture에서는 `유도 1종`이 **반전에서도** 뜬다. 지금 요구는 비대칭 fixture의 `유도 2종` 하나다. §1.1·§5.2.

### 0.2 ★D-3은 대조군이 잡을 수 없다 — 부모가 먼저 죽는다

리터럴을 오타로 바꾸면 `SVG_COMPONENTS`가 비고, **부모**가 모듈 적재 시점에 `SVG_COMPONENTS.length === 0` 가드로 `exit 2`한다. **대조군이 하나도 돌지 않는다.**

맞는 처분이다 — 그러나 *"규칙이 틀렸다"* 는 진단은 아니고, **대조군으로 고정할 수도 없다**(자식을 띄우려 해도 부모가 먼저 죽는다).

→ **D-2. 감사의 규칙 항목에 이 사실을 선언한다** — `wantBroken: []` + 이유. **조용히 빠지는 것과 이유를 적고 빠지는 것은 다르다**(선행 사이클의 규약).

### 0.3 ★열린 문제 A의 답 — 주장은 **둘**이고 하나만 덮인다

| | 주장 | 자체검사로 덮이나 |
|---|---|---|
| **R1** | *"유도 **규칙**이 옳게 동작한다"* | ✅ 가짜 트리 자식이 **실제 규칙 코드**를 가짜 입력에 적용한다 |
| **R2** | *"**실제 컴포넌트**가 규칙에 옳게 분류된다"* | ❌ 부분 오분류는 **서버가 필요한 본 검사(δ)** 만 본다(선행 G-5 실측) |

→ **D-3. R1만 덮고, R2는 덮지 않는다고 문서와 감사에 못 박는다.** 가짜 트리로 R1을 덮고 *"B-8을 닫았다"* 고 적으면 **Plan §8이 최상위 위험으로 적은 그대로** 된다 — 닫았다고 적고 안 닫는 것이다.

**R2의 유일한 증거는 본 검사의 δ**이고, 그것은 선행 사이클이 G-5로 실측했다(92→56페이지에서 `δ LayerStack — 36개`). 이 사이클은 **그 사실을 기록으로 고정**하되 자체검사로 옮기지 않는다 — 옮기려면 페이지 순회를 자식에서 되풀이해야 하고, 그것은 본 검사를 두 번 도는 일이다.

## 1. 무엇을 만드나

### 1.1 ㉘ — 유도를 **주장하는** 대조군

> **★이 절은 Check에서 다시 썼다.** 초판(대칭 fixture · `δ Extra` 요구)은 **틀렸고**,
> 아래가 구현이다. 초판이 왜 틀렸는지는 §5.2에 남긴다.

```text
가짜 트리:  Alpha.tsx  ( <svg 있다 )
            Beta.tsx   ( <svg 있다 )   ← ★**비대칭**이라야 배너가 판별한다
            Extra.tsx  ( <svg 없다 )   ← **거를 것**이 있어야 규칙이 검사된다
            index.ts   ( 셋 다 export )
MDX:        a.mdx( <Alpha /><Beta /> ) · e1.mdx( <Extra /> ) · e2.mdx( <Extra /> )
스텁:       셋 다 글자 있는 SVG를 그린다
주장:       exit 2 · 배너 `유도 2종`   ← **요구는 이것 하나뿐이다**
```

**왜 비대칭인가.** SVG 1종 + 비SVG 1종이면 필터를 **반전해도 유도 결과가 1↔1로 같아**
`유도 1종`이 성공 배너에 그대로 뜬다. SVG 2 + 비SVG 1이면 정상 `유도 2종` · 반전 `유도 1종` ·
삭제 `유도 3종` · **부분 제외 `유도 1종`** 으로 갈린다.

**`δ Extra`를 요구하지 않는다.** 9조합 실측 결과 **어느 훼손도 배타적으로 잡지 못했다** —
삭제·반전에서는 `wantStatus: 2`가 먼저 판별하고, 부분 제외에서는 **δ가 여전히 뜬다.**
그래서 `δ만` 남기면 부분 제외를 **종료 0으로 통째로 놓친다.**

**`denyReason`도 두지 않는다.** 초판의 `/δ Alpha —/`는 두 훼손 모두에서 무동작이었다.
그리고 *"반전되면 α₀/α가 운다"* 는 서술은 **틀렸다** — `scopeStatic()`·`scopeViolations()`는
둘 다 `for (const c of svg)`로 도므로 **유도에서 빠진 종을 아예 보지 않는다.**

> ㉒㉓이 이미 이 모양이다. **다른 점은 ㉘이 그것을 자기 이름으로 주장한다는 것**이다 — ㉒㉓은 *"δ가 페이지를 짚는다"* 를 주장하고 규칙은 부수적으로 지킨다. ㉘을 더한다고 ㉒㉓의 보호가 사라지지 않는다(Plan §8의 마지막 위험).

### 1.2 감사의 범위를 규칙까지

| # | 훼손 | 주장 대조군 |
|:--:|---|---|
| 1 | 유도 필터 삭제 | ㉘ |
| 2 | 필터 반전 | ㉘ |
| 3 | **한 종만 제외**(부분 오분류) | ㉘ |
| 4 | **판정 대상을 넓힌다**(상한 · `kindsSvg → kinds`) | **㉚** |
| — | 리터럴 오타 | **없음** — 부모의 시작 가드(§0.2). 이유와 **사유 정규식**을 적고 **분모 밖에서** 센다 |

**두 수를 따로 낸다**(열린 문제 B) — `배선 11/11 · 규칙 4/4(+ 가드 1/1)`.
**가드는 분모에 넣지 않는다** — 넣고 다시 더하면 이중 계상이다(`const ruleClaimable = RULES.filter((r) => !r[5]).length` 가 분모에서 뺀다).

3·4는 Check 1회차 뒤에 더했다. **3이 Plan G-6이 요구한 모양**(선행 G-5 · `LayerStack` 하나만 제외)이고,
**4는 상한**이다 — 그때까지 규칙 훼손이 전부 *좁히는* 쪽이라 **문턱이 한쪽만 고정돼 있었다.**

### 1.3 B-10 · B-12

| # | 방법 |
|:--:|---|
| **B-10** | ζ 표본이 넣은 페이지에만 **넓은 문서**를 내는 경로별 스텁 → `exit 1 · [가로 넘침]`을 주장하는 자식. 판정 범위는 **안 좁힌다**(열린 문제 C — 좁히면 실제 넘침을 놓친다) |
| **B-12** | 감사가 `audited: false`로 **선언**하는 것에 더해, 그 선언이 참인지(그 호출부를 훼손해도 본 검사 판정이 안 바뀌는지) **한 번 실측해 기록**한다. 대조군으로 만들지는 않는다 — 면책 문구의 유무를 주장하려면 부모의 저장소 상태에 기대야 한다 |

## 2. 착수 순서

```text
① 감사에 규칙 3항목 — 지금 상태(주장 대조군 0/3)를 고정
② ㉘ 신설 → 감사 재실행 (규칙 2/2 + 가드 1이 되어야 한다 — Check 뒤 **4/4**)
③ B-10 자식 → 되돌려 확인
④ B-12 실측 기록
⑤ 되돌려 확인(FR-7) · 문서 · Check
```

**②에서 감사를 다시 도는 이유**는 선행 사이클과 같다 — ㉘이 정말 두 규칙을 덮는지, 한 걸음마다 봐야 안다.

## 5. Do 실측

### 5.1 한 걸음마다 감사를 돌렸다

```text
① 감사에 규칙 3항목        배선 11/11 · 규칙 **0/2** (+가드 1/1)   ← 기준선
② ㉘ 유도를 주장하는 대조군  배선 11/11 · 규칙 **2/2** (+가드 1/1)
③ Check 1회차 반영 뒤       배선 11/11 · 규칙 **4/4** (+가드 1/1)   ← 부분 제외 · 상한 추가
```

두 규칙 훼손이 모두 **㉘을 주장 대조군으로** 깨뜨린다. 예전에는 ㉒㉓이 **부수적으로** 깨졌을 뿐이라 감사가 `❌ 안 잡힘 … 주장 대조군 ㉘ 이 안 깨졌다`로 정확히 지적했다.

### 5.2 ★`배럴 2종` 요구가 빗나갔다 — 실패 경로의 배너는 다르다

㉘의 첫 판은 `유도 1종`과 `배럴 2종`을 함께 요구했는데 후자가 안 맞았다.

| 경로 | 배너 |
|---|---|
| 성공 | `범위: 유도 N종 / 관측 M종(SVG K종) / 배럴 B종 / 페이지 P` |
| `scopeViolations` 실패(δ) | `유도 N종 / 관측 M종 / MDX K종` — **배럴이 없다** |
| `scopeStatic` 실패 | `유도 N종 / 배럴 B종 / 디렉터리 D종 / 페이지 P` |

㉘은 δ로 실패하는 경로를 타므로 배럴 수를 못 본다. **요구를 실제 출력에 맞췄다.**

> **★그 다음이 더 중요하다(Check 1회차).** 그때 `δ Extra`를 *"거를 것이 트리에 있다는 증명"* 으로
> 함께 걸었는데, **9조합 실측 결과 어느 훼손도 배타적으로 잡지 못했다.** 걷어냈다.
> 그리고 fixture가 **대칭**이라 배너 `유도 1종`도 반전에서 그대로 떠, 실제 판별자는 `wantStatus: 2`뿐이었다.
> **요구가 무엇을 잡는지 재 보지 않으면 장식을 주장으로 착각한다** — §1.1이 지금 모습이 된 이유다.

### 5.3 ★★감사 스크립트가 소스를 훼손한 채 남겼다 — 자기 방어가 잡았다

규칙 감사를 붙이자 `restore()`가 **두 번째 호출에서 무동작**이 됐다. `restored` 플래그를 시그널 재진입 방지용으로 뒀는데, 감사 구간이 배선·규칙 **둘**로 늘면서 정상 흐름의 반복 원복까지 막았다.

```text
❌❌ 원복 뒤 자체검사가 2로 끝났다 — 저장소가 망가진 채 남았을 수 있다.

실제로:  scripts/verify-diagram-render.mjs:81  …includes('<svq')   ← 훼손이 남았다
         자체검사 exit 2
```

**선행 사이클이 넣어 둔 *"원복을 믿지 않고 확인한다"* 가 값을 했다.** 그것이 없었으면 훼손된 소스로 다음 작업을 계속했을 것이다.

→ `restore()`는 **언제나 쓴다.** 재진입 방지는 `signalled`가 따로 진다 — **플래그 하나가 두 목적을 겸하면 하나가 조용히 깨진다.**

### 5.4 FR-7 되돌림 3/3

| 되돌림 | 결과 | 지금 무엇이 지나 |
|---|---|---|
| ㉘의 fixture에서 `Extra`를 뺀다(거를 것이 없는 트리) | ❌ **㉘만** 깨진다 — §0.1이 옳았다 | ★감사 규칙 **'한 종만 제외'** 가 매 실행마다 같은 성질을 확인한다 — 손으로 한 번 되돌려 본 기록보다 **강하다** |
| ζ 표본을 지운다 | ❌ ㉙ ㉓ 깨진다 | 손 기록 |
| 진단 경로(`realTreeScopeViolations`)를 훼손 | **종료 0 · 아무도 안 깨짐** — B-12의 선언이 참이다 | 손 기록 |
| **상한을 넓힌다**(`kindsSvg → kinds`) | ❌ **㉚만** 깨진다 | ★감사 규칙 **'판정 대상을 넓힌다'** |
| ㉚에서 `denyReason`을 뺀다 | **차이 없음** — ㉚은 똑같이 깨진다 | ★그래서 **걷어냈다**(Check A-2) |
| 가드 행에서 `guardReason`을 뺀다 | ❌ `exit 2` — *"가드 행인데 guardReason이 없다"* | ★Check N-2 |
| 감사에 `SIGTERM`을 보낸다(자식이 죽는다) | ❌ `exit 2` — *"자식이 판정을 내지 못했다 — 시그널 SIGTERM"* | ★Check N-1. **고치기 전이라면 `무대조군`으로 보고됐다** |
| `RULES`에서 한 행을 **지운다** | ❌ `exit 2` — `규칙 훼손이 4개인데 RULES_MIN은 5이다`. **훼손 단계 진입 전**에 죽는다 | ★A-1 수정 |
| `RULES`에 한 행을 **더한다** | ❌ `exit 2` — `6개인데 5이다`. **초판의 `<`가 못 잡던 방향** | ★A-1 수정이 `!==`인 이유 |

**앞의 세 행은 대칭 fixture 시절 측정이다.** 1·4행은 이후 감사 규칙이 **자동으로** 이어받았고,
2·3행은 여전히 손 기록이다 — 그 사실을 적어 둔다.

세 번째가 **B-12의 답**이다. 감사가 그 자리를 `audited: false`로 선언하며 *"훼손하면 면책 문구만 흔들리고 본 검사 판정은 그대로"* 라고 적었는데, **실측이 그것을 확인했다.** 선언을 검사로 바꾸지는 않았다 — 면책의 유무를 주장하려면 부모의 저장소 상태에 기대야 한다.

## 7. Act에서 드러난 것 — 감사가 소스를 훼손한 채 남을 수 있다

**Act 중 두 번 당했다.** 관문이 `대조군 35건 · exit 2`를 냈고, 두 번 다 **소스가 훼손된 채였다.**
하마터면 멀쩡한 코드를 고치러 갈 뻔했다.

| # | 무엇을 했나 | 남은 훼손 |
|:--:|---|---|
| 1 | 배경 감사가 도는 중에 자체검사를 돌렸다 | (훼손 중인 순간을 읽었다) |
| 2 | 감사를 `kill -9` 했다 | `svg: SVG_COMPONENTS` → `svg: []` |
| 3 | 감사가 타임아웃에 죽었다 | `유도 필터`에 `.filter((f) => f !== 'Beta.tsx')` **덧붙은 채** |

### 7.1 ★시그널로는 이 감사를 멈출 수 없다 — `SIGKILL`뿐이 아니다

**초판은 이 절을 *"`SIGINT`·`SIGTERM`은 받아 원복하고 `kill -9`만 건너뛴다"* 로 적었다.
Check 3회차가 그것이 틀렸음을 밝혔다(G-2).** 핸들러는 달려 있지만 **본문이 도는 동안에는 돌지 않는다** —
이 스크립트에 `await`가 **하나도 없고**(전 구간 동기) `selfTest()`가 `spawnSync`로 블로킹한다.
시그널 핸들러는 JS 콜백이라 스택이 이벤트 루프로 풀린 뒤에야 돈다.

**실측**: `timeout 25 node scripts/audit-render-wiring.mjs` 가 **5분 43초** 살아 있었다.

> **이 거짓말이 위험했다.** Ctrl-C가 안 먹는 것처럼 보이면 다음 손은 `kill -9`로 가고,
> 그것은 핸들러를 아예 건너뛰어 **소스를 훼손된 채 남긴다.** 이 사이클에서 세 번 그 길을 갔다.
> 주석과 이 절을 사실에 맞게 고쳤다. **응답성 자체는 안 고쳤다** — 항목 사이에
> `await new Promise(setImmediate)` 한 줄이면 지연이 6분 → 약 23초가 되지만,
> 소스를 훼손하는 스크립트의 제어 흐름을 사이클 막바지에 바꾸는 값이 크다(D-11).
그리고 **증거는 이미 만들어지고 있었다** — 원복 못 한 실행의 백업 파일이 `TMPDIR`에 남는다.
**아무도 읽지 않았을 뿐이다.**

→ 감사 시작에 **고아 백업 감지**를 넣었다. 내용이 현재 소스와 **다른** 고아가 있으면
*"원복하지 못하고 끝난 감사가 N건 있다"* 를 내고 확인 방법을 알려 준다.
**자동 원복은 하지 않는다** — 정당한 편집을 지울 수 있다. **사실만 말하고 사람이 정한다.**

### 7.2 ★`includes`는 덧붙은 훼손을 못 본다

3번을 찾는 데 한참 걸린 이유다. 내가 쓴 확인이 `v.includes(DERIV)` 였는데,
훼손이 `DERIV + " .filter(…)"` 라 **앵커가 그대로 들어 있어 참**이었다.

```text
includes(DERIV)        → true   ← 훼손이 남았는데 초록
그 줄이 DERIV로 끝나나?  → false  ← 이것이 옳은 물음
```

**감사 자신의 규칙 앵커 검사(`src0.includes(from)`)도 같은 약점을 갖는다.**
이전 실행이 남긴 덧붙임 위에 새 훼손을 얹으면 뒤엉킨다. 7.1의 감지가 그 경로를 대부분 덮지만,
**`포함`과 `정확히 그것`은 다른 물음**이라는 것은 백로그로 남긴다(D-4).

### 7.3 ★고아 감지가 처음엔 **해를 끼쳤다**

Check 3회차에 그 장치를 스스로 뜯어보니 결함이 둘이었다.

| # | 결함 | 왜 나쁜가 |
|:--:|---|---|
| 1 | **pid 생존을 안 봤다** | **동시에 도는 다른 감사의 백업**을 고아로 보고, 내용이 같으면 **조용히 지웠다.** 그 백업은 그쪽의 **유일한 안전망**이다 — 지운 뒤 그쪽이 `SIGKILL`을 맞으면 되돌릴 파일이 없다 |
| 2 | `readdirSync(TMPDIR)`이 무방비 | 이 블록은 `uncaughtException` 핸들러 등록(`process.on('uncaughtException', …)`)보다 **먼저** 돈다. 예외가 나면 **종료 코드 계약 밖인 1**로 죽는다 — 계약상 1은 *콘텐츠 위반*이다 |

**1이 이 사이클에서 가장 나쁜 모양이다.** 지금까지는 *"방어 장치가 방어하지 않는다"* 였는데,
이번엔 **위험을 줄이러 온 장치가 위험을 키웠다.**

→ `process.kill(pid, 0)`으로 생존을 보고(`EPERM`은 *살아 있는데 내 것이 아니다*),
`try/catch`로 감싸되 **조용히 넘기지 않는다**(감사는 막지 않는다 — 이것은 편의 장치지 관문이 아니다).

> **새로 넣은 장치는 새로 검사해야 한다.** 이 둘은 대조군도 감사도 안 잡는다 —
> 내가 **읽어서** 찾았다. 그 사실 자체가 백로그다(D-7).

### 7.4 ★코드 주석에 줄번호를 적지 않는다

Check 4회차에 인용한 줄을 전부 열어 봤더니 **거의 다 엉뚱한 코드를 가리키고 있었다** —
Act에서 위쪽에 코드를 넣어 5~10줄씩 밀렸다.

```text
㉚ 주석의 `:1241`  → 실제로는  "이 변수는 ⑫ 대조군이 자식에 넘길 때만 켜진다"
㉚ 주석의 `:1326`  → 실제로는  const scope = scopeViolations({
감사 주석의 `:1121`·`:1127` → 빈 줄
```

**숫자를 고쳐도 다음 사이클에 또 밀린다.** 앵커(코드 조각·심볼 이름)로 바꿨다 —
그것은 코드가 바뀌면 **함께 바뀌거나, 안 바뀌면 눈에 띈다.**

> 이 저장소가 *"수치를 두 곳에 적으면 한 곳만 고치게 된다"* 로 배운 것과 같다.
> **줄번호는 코드의 미러이고, 대조되지 않는 미러다.**

그리고 그 주석은 **내용도 틀렸다** — *"δ 사유가 뜨는 **두** 경로"* 라 했는데 δ 문자열을
만드는 자리는 `scopeViolations()` 안 **하나**뿐이고(`scopeStatic()`의 `pre` 경로는 γ·ε·α₀·σ만 낸다),
그 유일한 소비자가 `exit 2`로 끝난다. **결론은 그대로 옳았지만 근거가 틀렸다.**

### 7.5 ★"손으로 적은 수를 또 손으로 지킨다" — 무한 후퇴인가

`RULES_MIN`을 고치자 곧바로 그 아래 한 겹(`RULE_CLAIMS`·`RULE_GUARDS`)이 필요해졌다.
그럼 그것을 지킬 수가 또 필요한가? **아니다. 멈추는 자리가 있다.**

| 수 | 유도할 원천 | 어떻게 지키나 |
|---|---|---|
| `CASES` 행수 | **있다** — 호출부 인자 | **유도해 대조**한다(`assertCasesMirrorCallSites`). 손으로 안 적는다 |
| `RULES` 수·구성 | **없다** — 어떤 훼손을 걸지는 사람이 정한다 | 손으로 적되 **유도값과 `!==`로 대조**한다 |

> **A-1의 병은 *"손으로 적었다"* 가 아니라 *"아무와도 대조되지 않았다"* 였다.**
> `5 < 4`가 거짓이라 그 수는 아무것도 안 물었다.
> 대조가 **유도값**과 이뤄지면 그 수를 지킬 또 다른 수는 필요 없다 —
> `RULE_CLAIMS`가 틀리면 `RULES`를 **세는 것만으로** 드러난다. **거기서 후퇴가 멈춘다.**

원칙으로 적으면: **유도할 원천이 있으면 유도하고, 없으면 손으로 적되 유도값과 대조한다.**
지키는 수를 또 만들지 않는다.

### 7.6 규약

> **감사가 도는 동안 `verify-diagram-render.mjs`에 대해 아무것도 돌리지 않는다.**
> 감사는 그 파일을 훼손·원복하며 돈다 — 그 사이의 관문 결과는 **소스가 아니라 순간을 잰다.**
> 그리고 **감사는 죽이지 않는다.** 끝까지 돌리거나, 아예 안 돌리거나 둘뿐이다.

**`timeout`도 죽이는 것이다.** 시작 단언만 보려고 `timeout 25`를 걸었더니, `spawnSync`가
블로킹이라 `SIGTERM`이 즉시 처리되지 않고 감사가 계속 돌았다. 그 위에서 무결성을 재고
초록을 얻었는데 — **항목 사이의 깨끗한 순간이었다.** 같은 실수를 세 번 했다.

**끝났는지는 파일이 아니라 프로세스로 묻는다**: `while pgrep -f audit-render-wiring; do sleep 5; done`
