### 2.2 Design (2026-08-11)

**계약 2건 확정 — 이 사이클의 존재 이유**

| # | 계약 | 결정 | 근거 |
|:--:|---|---|---|
| **C-1** | 도해 글자 크기 | **viewBox 절대 단위 확정** — `FontSizeToggle` 미연동 | SVG 내부에서 `em`은 부모의 **CSS px**를, viewBox는 **사용자 좌표계**를 쓴다. 섞으면 도해가 스케일로 작아져도 글자는 그대로여서 375px에서 라벨이 도형을 넘친다. 접근성은 ⓐ 브라우저 확대(벡터라 깨지지 않음) ⓑ 표 병치·`altTable`의 텍스트 대안으로 확보 |
| **C-2** | `altTable` 방침 | **표 병치를 대안 이행으로 명문화** — FR-8을 "표 병치 **또는** `altTable`"로 재정의 | 현재 89모듈이 표를 지우지 않고 병치해 **정보 손실 0**이다. 131개에 `altTable`을 채우고 표를 지우면 자수가 줄어 하한 근접 6모듈이 §5.1 보정에 걸린다. **이미 작동하는 방식을 규칙으로 승격하는 편이 정직하다** |

> C-1·C-2는 **코드 변경을 요구하지 않는다.** 둘 다 "이미 그렇게 하고 있으나 문서가 다르게 적혀 있던" 항목이다. 선행 사이클이 B안을 **묵시적으로** 택했으나 기록하지 않은 것이 Gap의 실체였다.

**`<desc>` 설계에서 한 판단 두 가지**

1. **prop이 아니라 자동 생성** — `desc`를 prop으로 받으면 131개 도해에 일일이 써야 하고 누락이 생긴다. 각 컴포넌트가 자기 데이터에서 한 문장을 만들게 했다. 저작자 입력 0 → **누락이 구조적으로 불가능**하다.
2. **`aria-labelledby`를 버리고 `aria-label` 유지** — `aria-labelledby`는 `<title>`·`<desc>`에 id를 요구해 **6종 전부에 내부 id가 필요**해지는데, 이는 선행 V-3에서 `idPrefix`를 2종(`LayerStack`의 `<pattern>`·`NodeGraph`의 `<marker>`)으로 좁힌 규약과 충돌한다. 스크린리더가 `aria-label`을 우선 읽으므로 접근성 손실 없이 규약을 지켰다.
