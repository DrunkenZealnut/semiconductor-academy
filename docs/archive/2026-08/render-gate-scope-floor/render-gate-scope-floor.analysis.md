- **방법**: 주장별 직접 재현(배선 훼손 5종·탐침 컴포넌트·배럴 조작) + gap-detector 1회(범위 4항목, 코드 추적 7건)

## 0. Do가 "8/8 충족"이라고 적었다. Check가 물은 것은 달랐다

> **자체검사가 통과하면서 본 검사가 깨진 상태를 만들 수 있나?**

**만들 수 있었다.** 이 사이클의 **핵심 판정인 δ**가 그 상태였다.

### C-1 — δ의 **배선**에 대조군이 0건이었다

Do는 `scopeViolations()`를 순수 함수로 뽑아 대조군 ⑭~⑱을 붙였다. 그것이 대조군을 싸게 만들었지만 — **동시에 새 무대조군 지대를 만들었다.** ⑱은 그 함수를 **직접** 부른다. 본 검사가 그 함수에 **무엇을 넘기는지**는 `--self-test`가 한 줄도 실행하지 않는다.

```text
호출부를 이렇게 망가뜨려도                          자체검사
  pagesByKind: new Map()                            ✅ 통과 (종료 0)
  observedSvg: new Set()                            ✅ 통과 (종료 0)
  urls: [...pagesByKind 전부]  (δ가 절대 못 울게)     ✅ 통과 (종료 0)
```

**FR-8 스윕이 이미 신호를 줬는데 읽지 못했다** — δ를 무력화했을 때 깨진 것이 `⑱` **하나뿐**이었다. 다른 판정들은 되돌리면 이웃도 함께 깨졌다(`offTarget` 때문에). **혼자만 깨지는 판정은 "잘 격리됐다"가 아니라 "본 검사와 이어져 있지 않다"는 뜻일 수 있다.**

> **선행 A-1의 정확한 재현이다.** 그 사이클은 *"⑨가 `measureInPage`의 카운터만 보고, 그 뒤 `exit 2`는 `--self-test`가 한 줄도 실행하지 않는다"* 로 배웠다. 이번엔 *"⑱이 순수 함수만 보고, 그 함수를 부르는 자리는 한 줄도 실행하지 않는다"* 였다. **모양이 같고 자리만 옮겼다.**

### C-3 — ★**"두 독립 출처"가 실은 하나였다** (gap-detector)

이 사이클의 설계 전체가 *"파일시스템 유도(기대)와 실제 렌더(관측), 두 독립 출처를 대조한다"* 위에 서 있다. gap-detector가 코드를 따라가 **그 전제가 거짓**임을 짚었다.

```js
const kinds = [...src.matchAll(reAny)];   // reAny는 배럴에서 만든다
if (!kinds.length) continue;              // ← 여기서 나가면 urls에도 안 들어간다
…
if (re.test(src)) urls.add(url);          // 그래서 urls도 배럴의 하류다
```

**배럴이 δ의 기준선이자 `urls`의 상류였다.** 실측으로 확인했다.

```text
배럴 온전                      URL 92
배럴에서 NodeGraph를 뺀다       URL 87      ← 5개가 조용히 사라진다
```

그리고 δ는 그 종의 **키 자체가 없어** `!want → continue`로 침묵한다. α도 다른 페이지에서 관측되니 침묵. **exit 0.**

배럴을 망가뜨리는 것은 손으로 지울 필요도 없다 — `export { NodeGraph, type NodeGraphProps } from …` 처럼 쓰면 `^export \{ (\w+) \} from` 정규식이 조용히 놓친다.

### C-2 — α가 심각도가 다른 둘을 한 문장으로 말했다

SVG 도해 컴포넌트를 새로 만들고 아직 MDX에서 안 쓰면 α가 운다(탐침 파일로 확인). 판정 자체는 참이다 — *"한 번도 검사되지 않았다."* 그런데 메시지가 훨씬 심각한 쪽을 묻는다.

| `pagesByKind` 크기 | 뜻 | 심각도 |
|:--:|---|---|
| 0 | 아직 아무 MDX도 안 쓴다 | 흔하다. 만들고 안 썼다 |
| >0 | **쓰는데 안 그려졌다** | 렌더가 죽었거나 URL 수집이 그 페이지를 놓쳤다 |

### 1.1 C-9가 드러낸 것 — **미러는 종류가 여럿이다**

C-6에서 `SVG6` **목록 미러**를 지우며 *"손으로 적지 않는다"* 를 규약으로 삼았다. 그런데 **같은 함수 두 줄 아래**에 `wantReason: /α LayerStack/` 이라는 **문자열 미러**가 남아 있었다. 목록만 찾고 문자열은 안 찾았다.

**증상이 고약했다.** G-5 조작(유도에서 `LayerStack` 제거)을 하면 α가 다른 종으로 울고 → 사유 불일치 → **자체검사가 먼저 실패** → 계약대로 본 검사를 안 돌린다 → **δ의 "36페이지" 증거가 통째로 사라진다.**

관문은 빨개진다(`exit 2`). 그러나 **진단이 엉뚱하다** — 화면은 *"⑳ 대조군이 실패했다"* 라고 말하고, 진짜 사실인 *"36페이지가 검사 밖이다"* 는 어디에도 안 나온다. §2 B-5가 적은 위험의 실물이다.

## 5. 교훈

1. **순수 함수로 뽑으면 대조군이 싸지지만, 배선이라는 새 무대조군 지대가 생긴다.** 이 사이클은 `scopeViolations()`를 뽑아 대조군 5건을 몇 밀리초에 얻었고 — 그 함수를 **부르는 자리**를 아무도 안 보게 만들었다. 싸진 만큼 어딘가가 비었는지 물어야 한다.
2. **"혼자만 깨지는 대조군"은 좋은 신호가 아닐 수 있다.** FR-8 스윕에서 δ만 격리돼 보였는데, 그 격리가 곧 *"본 검사와 이어져 있지 않다"* 였다. 다른 판정들은 `offTarget` 때문에 이웃과 함께 깨졌고 그것이 오히려 **이어져 있다는 증거**였다.
3. **미러는 종류가 여럿이라 하나를 지워도 남는다.** *"손으로 적지 않는다"* 를 규약으로 세운 **바로 그 함수 안**에 문자열 미러가 남아 있었다(C-9). 목록·문자열·정규식·경로 — 미러를 찾을 때는 **모양을 바꿔 가며** 찾아야 한다.
4. **위험 표에 이름을 적는 것과 그 위험을 피하는 것은 다른 일이다.** Design 위험표가 *"γ의 기준선이 또 하나의 유도라 같이 틀린다"* 를 적었는데, 거기 적은 **대응이 바로 그 함정**이었다(Do §7.1).
5. **실물로 한 번 울려 보는 것이 대조군 열 개보다 앞선다.** G-5를 ⑦보다 앞에 둔 판단이 δ를 만들어 냈다. 순서를 바꿨다면 α·β·γ 대조군이 전부 통과한 채 **36페이지가 조용히 검사 밖인** 사이클로 끝났을 것이다.
6. **"독립 출처"라고 적었다고 독립이 되지는 않는다.** 이 사이클의 설계 전체가 *"파일시스템 유도와 실제 렌더, 두 독립 출처"* 위에 서 있었는데, 코드를 따라가 보니 **배럴이 둘 다의 상류**였다(C-3). 독립성은 **주장이 아니라 데이터 흐름의 성질**이고, 흐름을 따라가야만 확인된다.
7. **브라우저 없이 아는 것은 브라우저 앞에서 말한다.** γ·ε·α₀·σ는 파일시스템과 MDX만 보면 아는데 루프 뒤에 있어 **110초를 헛되이 쓰고** 울었다. 판정의 자리는 정확성뿐 아니라 **사람이 원인을 찾는 비용**도 정한다.
8. **같은 교훈이 자리를 옮겨 다시 온다.** A-1(감지 대 처분) → E-5(같은 것, 렌더 쪽) → C-1(감지 대 배선). 규약을 문서에 적어 놓아도 **새 구조에는 자동으로 옮겨지지 않는다.** 세 번째다.
