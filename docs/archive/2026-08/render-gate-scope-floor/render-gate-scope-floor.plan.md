## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | `verify:render`의 검사 범위는 **파일시스템에서 유도**된다(`src/components/diagram/*.tsx` 중 `<svg` 포함). 유도 규칙이 조용히 틀리면 **범위가 줄어든 채 "전 항목 통과"** 가 나온다. 하한 단언이 없다 — `SVG_COMPONENTS.length === 0`과 `!urls.length` 둘 다 **0일 때만** 운다. |
| **Solution** | **DOM 신원으로 교차 확인한다.** 도해가 `data-diagram`으로 자기 종류를 남기고, 관문이 *"SVG 6종이 각각 최소 1회 검사됐다"* 를 확인한다. 빠지면 `exit 2`. **파일시스템 유도와 실제 렌더, 두 독립 출처를 대조**하는 것이라 유도가 틀려도 잡힌다. |
| **Function · UX Effect** | **독자에게 보이는 변화는 없다.** HTML에 속성 하나가 늘 뿐이다(서버 컴포넌트라 JS 번들 무증가). |
| **Core Value** | **`verify:diagram`이 `WAVES`+D-10으로 얻은 것을 렌더 관문도 갖는다.** 지금은 정적 관문만 *"검사할 것이 사라진 것을 검사했다고 말하지 않는다"* 를 지킨다. |

## 1. 문제

`render-gate-self-test` Check가 **A-2**로 남긴 것:

> 검사 **범위에 하한이 없다** — `SVG_COMPONENTS`에서 컴포넌트가 조용히 빠지면 그 페이지가 통째로 검사 밖인데 `exit 0`. `verify:diagram`은 `WAVES` 등록 + `exit 2`(D-10)로 막았다. 렌더 쪽 대응물이 필요하나 별개 설계다. **가장 큰 구멍.**

범위는 이렇게 유도된다.

```js
const SVG_COMPONENTS = readdirSync('src/components/diagram')
  .filter((f) => f.endsWith('.tsx') && f !== 'DiagramFrame.tsx')
  .filter((f) => readFileSync(...).includes('<svg'))   // ← 여기가 조용히 틀릴 수 있다
```

그 다음 이 목록으로 정규식을 만들어 MDX를 훑어 URL을 모은다. **컴포넌트가 하나 빠지면 그 컴포넌트를 쓰는 페이지가 통째로 사라진다.**

### 1.1 착수 전 실측 — 구멍의 크기

| | |
|---|---|
| 도해 12종 중 SVG로 판정 | **6종** (나머지 6종 `CompareCards`·`FlowSteps`·`Timeline`·`TreeBranch`·`TruthTable`·`ValueBars`는 HTML/CSS라 정당하게 범위 밖) |
| 현재 검사 URL | **92개** |

**컴포넌트 하나가 빠지면 몇 개가 사라지나** (실측):

```text
LayerStack       −36개 (39.1%)
NodeGraph        −33개 (35.9%)
LatticeDiagram   − 6개 ( 6.5%)
ScaleRuler       − 5개 ( 5.4%)
LabeledFigure    − 2개 ( 2.2%)
CurvePlot        − 1개 ( 1.1%)
```

**어느 경우에도 종료 코드는 `0`이다.** 남은 56페이지가 통과하면 "전 항목 통과"가 나온다.

### 1.2 어떻게 빠지나 — 가설이 아니다

| 경로 | 왜 |
|---|---|
| `<svg` 리터럴이 공용 헬퍼로 이동 | 리팩터링으로 `<Svg>` 래퍼를 만들면 원본 파일에 `<svg`가 없어진다 |
| 컴포넌트가 디렉터리 밖으로 | `src/components/diagram/` 밖에 SVG 도해를 만들면 유도 자체가 못 본다 |
| `DiagramFrame.tsx` 하드코딩 제외 | 두 번째 틀 파일이 생기면 그것도 빼야 하는데 이름이 박혀 있다 |
| 파일명·컴포넌트명 불일치 | 유도는 **파일명**을 쓰고 MDX는 **컴포넌트명**을 쓴다. 갈라지면 정규식이 못 맞춘다 |

### 1.3 E-5 — 같은 성격이라 함께 닫는다

> **`unsupported → exit 2` 처분에 대조군이 없다.** ⑬은 `measureInPage`가 `<use>`를 **감지하는지**만 보고, 본 검사에서 `2`가 나오는지는 `--self-test`가 한 줄도 실행하지 않는다.

**A-2도 결국 `exit 2` 처분이다.** 하한 위반을 감지하는 것과 그때 `2`로 끝나는 것은 다른 주장이고, 이 사이클은 그 구분을 **두 번**(A-1·E-5) 겪었다. 처분 대조군 기계를 두 번 만들지 않으려면 함께 한다.

## 2. 왜 "목록 등록"이 아닌가

스크립트가 **이미 반대 근거를 적어 놨다**:

> 목록을 적어 두면 7번째 SVG 컴포넌트가 생겼을 때 이 스크립트가 그 페이지를 조용히 건너뛴다 — CLAUDE.md가 경계하는 **수동 미러를 늘리는 일**이다(G-5).

`WAVES`식 레지스트리는 정적 관문과 모양이 같아 일관되지만, **그 결정을 뒤집는 것**이다. 그리고 뒤집을 만한 이득이 없다 — 레지스트리는 "적힌 것이 다 있나"만 보지 **"적히지 않은 것이 빠졌나"** 는 못 본다.

### 2.1 핵심 착상 — 미러가 나쁜 게 아니라 **대조되지 않는 미러**가 나쁘다

`data-diagram`도 문자열이니 미러 아니냐고 물을 수 있다. 다르다.

```text
출처 A (파일시스템 유도)   LayerStack.tsx 에 <svg 가 있다  →  기대 'LayerStack'
출처 B (실제 렌더)         DOM에 data-diagram="LayerStack"  →  관측 'LayerStack'
                                    ↓
                          둘이 어긋나면 exit 2
```

`LayerStack.tsx`를 `Layers.tsx`로 바꾸고 문자열을 안 고치면 기대는 `Layers`, 관측은 `LayerStack` — **어긋나서 운다.** 반대로 문자열만 고치고 파일을 안 고쳐도 운다. **두 출처가 서로를 검사한다.** 이것이 `schema.ts` ↔ `schema-enum.json`(빌드가 대조한다)이 살아 있는 미러이고, 대조되지 않는 목록이 죽은 미러인 이유다.

## 3. 열린 문제 — Design이 정한다

| # | 문제 |
|:--:|---|
| **A** | **`data-diagram` 값을 무엇으로 넣나.** 각 컴포넌트가 `kind="LayerStack"` 리터럴을 넘기면 명확하지만, `kind={LayerStack.name}`처럼 식별자에서 유도하면 이름 변경이 자동으로 따라온다 — 다만 프로덕션 빌드의 **최소화가 이름을 망가뜨릴 수 있다.** 실측이 필요하다(`npm run build` 후 HTML 확인). |
| **B** | **비SVG 6종에도 붙이나.** 렌더 관문은 SVG만 보지만, 속성을 12종 전부에 붙이면 규약이 단순해지고 나중에 HTML 도해 검사를 만들 때 쓸 수 있다. 안 붙이면 `DiagramFrame`이 종류를 모르는 채로 남는다. |
| **C** | **처분 대조군의 값을 어떻게 감당하나.** ⑫가 이미 자식 하나로 46초를 쓴다. A-2·E-5 처분까지 각각 자식을 붙이면 자체검사가 50초 → **약 140초**가 된다. 자식의 URL 범위를 좁히는 인자(`RENDER_ONLY_URLS` 같은)를 만들면 셋 다 몇 초로 줄고 **백로그 D-2(⑫ 비용)** 도 같이 풀린다 — 다만 **"범위를 줄이는 인자"를 만드는 것은 A-2가 막으려는 바로 그 위험**이라 가드가 필요하다. |
| **D** | **`data-diagram`이 정적 관문(C-1~C-20)의 스캐너를 건드리나.** C-19는 `indexOf`로 태그를 훑는데, 이번 사이클에서 주석 한 줄이 그 스캐너를 깨뜨린 적이 있다. |

## 6. 착수 순서

```text
① 열린 문제 A 실측 — 프로덕션 빌드에서 이름이 살아남나 (G-8)
② DiagramFrame에 data-diagram + 12종 전달
③ 관문: 관측 수집 → 하한 판정 → exit 2 처분
④ G-5 — 실제로 빼 보고 운다 (여기서 안 울면 ③이 헛것이다)
⑤ 열린 문제 C — 자식 범위 인자 + 가드. D-2(⑫ 비용)도 같이 본다
⑥ 대조군 3종(FR-5·6·7) + 되돌려 확인
⑦ 문서 · Check
```

**①이 먼저인 이유**: 최소화가 이름을 망가뜨리면 설계가 통째로 바뀐다. ②를 다 만든 뒤 알면 늦다.
**④가 ⑥보다 먼저인 이유**: 선행 사이클이 *"대조군이 통과하는데 본 검사가 깨진 상태"* 를 여덟 가지 찾았다. **실물로 한 번 울리는 것이 대조군 열 개보다 앞선다.**

## 7. 범위 밖

- **비SVG 6종의 렌더 검사** — HTML/CSS 도해는 좌표 판정 대상이 아니다. 속성을 붙이는지는 열린 문제 B지만 **검사하지는 않는다**
- **`verify:render`를 상시 관문으로** — 본 검사는 서버·자격 증명이 필요하다
- **`<use>` 인스턴스를 실제로 재는 것** — 이번에도 `unsupported`(판정 불가)로 둔다. E-5는 그 **처분**을 증명하는 것이지 판정을 만드는 게 아니다
- **선행 백로그 유지** — A-4(`SLACK` 문턱) · A-5(불투명 well 맨 위) · A-6(알파 합성) · A-8(색 해석 실패 분기) · B ⓑ(k 분포) · B ⓒ(`<tspan>`) · B-1 · B-3 · `lastFile` 절대경로 · G-7 중복 실행 이음매 · `--all --assert-only` 무시 · 미사용 예외 검사 · `--wave w4` `_coverage` 누락 · `⊤` 잘린 글리프
