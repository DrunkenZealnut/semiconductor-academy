## 0. Design 착수 실측 — 열린 문제 셋이 닫혔다

Plan이 *"①이 먼저인 이유: 최소화가 이름을 망가뜨리면 설계가 통째로 바뀐다"* 라고 적었다. 먼저 쟀다.

### 0.1 열린 문제 A — **식별자 유도는 죽는다.** 리터럴을 쓴다

`DiagramFrame`에 두 형태를 함께 넣고 `npm run build`를 돌려 프로덕션 산출물을 봤다.

```text
data-diagram="LayerStack"      46회   ← 리터럴: 살아남는다
data-diagram-auto="J"          46회   ← LayerStack.name: 최소화가 한 글자로 뭉갠다
출현 파일 44개
```

**`LayerStack.name`이 `"J"`가 된다.** Next.js가 서버 번들도 최소화하므로 함수 이름은 계약이 될 수 없다.
→ **D-1. `data-diagram`은 리터럴 문자열이다.**

이름 변경이 자동으로 따라오지 않는 것은 **손해가 아니다.** §1이 보이듯 어긋나면 관문이 운다 — 이 저장소에서 *조용한 것*이 나쁘지 *시끄러운 것*은 나쁘지 않다.

### 0.2 열린 문제 C — **자식을 임시 cwd에서 돌린다.** 새 인자를 만들지 않는다

Plan은 `RENDER_ONLY_URLS` 같은 **범위 축소 인자**를 후보로 뒀는데, 그것은 *"A-2가 막으려는 바로 그 위험"* 이다. 정적 관문이 이미 다른 답을 갖고 있었다.

```js
// scripts/verify-diagram-placement.mjs — selfTestExitCode()
const root = mkdtempSync(join(TMPDIR, 'dgm-exit-'));
symlinkSync(resolve(...parts), join(root, ...parts));   // node_modules·docs·src/components·src/styles
spawn(..., { cwd: root });
```

`collectUrls()`는 **cwd 기준으로 `src/content`를 훑는다.** 자식을 콘텐츠가 한두 개뿐인 임시 루트에서 돌리면 URL이 저절로 1~2개가 된다.

**새 인자가 없다** → 범위를 줄이는 스위치가 코드에 생기지 않는다. **A-2가 막으려는 것을 만들지 않고 A-2를 검사한다.**
→ **D-2. 처분 대조군은 임시 cwd + 심링크로 자식을 싸게 돌린다.** 백로그 D-2(⑫가 46초)도 같은 수단으로 줄인다.

### 0.3 열린 문제 D — C-19는 `<figure`를 안 훑는다

C-19의 `indexOf` 스캐너는 `<pattern`·`<svg`만 겨눈다. `data-diagram`은 `<figure>`에 붙으므로 닿지 않는다. G-2가 확인한다.

### 0.4 열린 문제 B — **12종 전부에 붙인다**

`DiagramFrame`이 종류를 모르는 채로 남으면 규약이 *"SVG 종만 넘긴다"* 가 되어 새 컴포넌트를 만들 때 판단이 필요하다. 전부 넘기면 규칙이 하나다 — **도해는 자기 이름을 말한다.** 검사는 SVG 6종만 하지만 그건 관문 쪽 사정이다.
→ **D-3. `kind`는 12종 전부가 넘긴다. 선택 prop이 아니라 필수다** — 빠뜨리면 `typecheck`가 잡는다.

### 0.5 하한 판정의 기대 집합 (실측)

| 컴포넌트 | 보유 MDX |
|---|---:|
| `LayerStack` | 44 |
| `NodeGraph` | 39 |
| `LatticeDiagram` | 8 |
| `CurvePlot` | 5 |
| `ScaleRuler` | 5 |
| `LabeledFigure` | **2** |

**가장 얇은 것이 `LabeledFigure` 2개다.** 하한을 *"각 종이 최소 1회"* 로 두면 여유가 1이다 — 이 컴포넌트를 쓰는 MDX 둘이 동시에 사라지는 일은 콘텐츠 삭제이지 유도 실패가 아니므로, 그때 우는 것이 **맞다.**

## 1. 설계의 중심 — 두 출처가 서로를 검사한다

```text
  기대 (파일시스템 유도)                    관측 (실제 렌더)
  src/components/diagram/*.tsx              브라우저가 그린 <figure data-diagram="…">
  중 `<svg` 를 포함하는 것                   을 검사 중에 수집
        │                                          │
        └──────────────► 대조 ◄────────────────────┘
                          │
              기대 − 관측 ≠ ∅  →  exit 2
```

| 무엇이 틀어지면 | 무슨 일이 나나 |
|---|---|
| `LayerStack.tsx`에서 `<svg`가 사라진다(헬퍼로 이동) | 기대에서 빠진다. **관측에는 남는다** → 어긋나서 운다\* |
| `LayerStack.tsx` → `Layers.tsx` 이름 변경 | 기대는 `Layers`, 관측은 `LayerStack` → 운다 |
| `kind="LayerStack"`만 고치고 파일은 그대로 | 기대는 `LayerStack`, 관측은 새 이름 → 운다 |
| 컴포넌트를 디렉터리 밖으로 옮긴다 | 기대에서 빠지고 URL도 사라진다. 관측에도 안 나온다 → **§1.1** |

\* 기대에서 빠지면 그 컴포넌트를 쓰는 MDX가 URL 목록에서 빠지므로 관측에도 안 나온다 — **그래서 §1.1이 필요하다.**

### 1.1 ★대조는 **양방향**이어야 한다

> **Do가 여기에 δ를 더했다(§7.2).** 아래 세 방향으로도 부족했다 — α·β·γ는 *"종류가 한 번이라도 그려졌나"* 만 보는데, 정작 중요한 것은 *"검사됐어야 할 페이지가 검사됐나"* 다. **γ의 기준선도 틀렸다(§7.1)** — 배럴로 바뀌었다.

순진하게 `기대 − 관측`만 보면 **가장 중요한 경우를 놓친다.** 유도에서 빠진 컴포넌트는 URL 수집에서도 빠져 관측에 안 나오고, 그러면 기대에도 관측에도 없어 **차집합이 공집합**이다. 조용히 통과한다.

이것이 이 사이클의 함정이다. **선행 사이클의 A-3(문턱을 한쪽 끝에서만 봤다)과 같은 병이다.**

**대조를 세 방향으로 한다.**

| # | 비교 | 잡는 것 |
|:--:|---|---|
| **α** | 기대 − 관측 ≠ ∅ | 등록·유도는 됐는데 **한 번도 안 그려졌다**(MDX에서 다 빠졌다 · 렌더가 죽었다) |
| **β** | 관측 − 기대 ≠ ∅ | 그려졌는데 **유도가 몰랐다** — `<svg` 필터가 놓친 컴포넌트 |
| **γ** | 기대 집합이 **MDX가 실제로 쓰는 도해 종류**와 어긋난다 | 유도·관측 **둘 다** 빠진 경우. `data-diagram`은 12종 전부가 내므로, MDX 스캔으로 얻은 종류 집합과 관측 집합을 견준다 |

γ가 §1 표의 마지막 행(디렉터리 밖으로 이동)을 잡는다. **`kind`를 12종 전부에 붙인 이유(D-3)가 여기서 값을 한다.**

> **다만 여기 적은 γ의 기준선("MDX가 쓰는 종류")은 공허했다** — 그 집합이 유도와 같은 목록에서 만들어져 함께 틀린다. 배럴 `index.ts`로 교체했다(§7.1).

## 2. 처분 — `1`이 아니라 `2`다

| 코드 | 이 사이클에서 |
|:--:|---|
| `1` | 콘텐츠 위반 — 글자 축소 · 대비 미달 · 글리프 구멍 · 마커 |
| `2` | **범위 상실** — 하한 위반 · `unsupported`(E-5) · `figures === 0` · 자체검사 실패 |

**하한 위반은 "도해가 나쁘다"가 아니라 "검사가 덜 됐다"** 이므로 `2`다. `--all` 부모가 `2`를 중단 신호로 보는 계약(usage §2.1.1f)과도 맞는다.

## 3. 무엇을 만드나

### 3.1 제품 쪽 — 한 줄

```tsx
// DiagramFrame.tsx
export function DiagramFrame({ kind, caption, note, altTable, scrollable, children }:
  DiagramCommon & { kind: DiagramKind; scrollable?: boolean; children: ReactNode }) {
  return <figure className="not-prose my-6" data-diagram={kind}> … </figure>;
}
```

`DiagramKind`는 `types.ts`의 유니온이다. 12종이 각자 리터럴을 넘기고, **`typecheck`가 오타와 누락을 잡는다.** 서버 컴포넌트라 JS 번들은 늘지 않고 HTML에 속성 하나가 붙는다(실측: 44파일).

### 3.2 관문 쪽

```js
// measureInPage — 관측 수집. figures를 세는 자리 옆이다.
out.kinds = [...new Set([...document.querySelectorAll('figure[data-diagram]')]
  .map((f) => f.getAttribute('data-diagram')))];

// 본 검사 뒤 — α·β·γ 대조 → exit 2   ← 실제로는 α·β·γ·δ이고 순수 함수로 뽑았다(§7.7)
```

γ의 기준선(MDX가 쓰는 도해 종류)은 `collectUrls()`가 이미 MDX를 훑으므로 **같은 순회에서** 모은다 — 두 번 훑지 않는다.

### 3.3 대조군 — 5건 추가 (15 → 20)

> **실제로는 6건이 늘어 21건이다**(δ가 생기고 음성이 붙었다). 최종 구성은 §7.7.

| # | 대조군 | 종류 |
|:--:|---|---|
| ⑭ | **α** — 기대에 있는데 관측에 없다 | 감지 |
| ⑮ | **β** — 관측에 있는데 기대에 없다 | 감지 |
| ⑯ | **γ** — MDX가 쓰는데 둘 다 모른다 | 감지 |
| ⑰ | **A-2 처분** — 하한 위반이면 자식이 `exit 2`와 사유를 낸다 | **처분** |
| ⑱ | **E-5 처분** — `unsupported`면 자식이 `exit 2`와 사유를 낸다 | **처분** |

⑰·⑱은 D-2(임시 cwd)를 쓴다. ⑫도 같은 수단으로 옮겨 **셋이 기계를 공유**한다.

## 4. 착수 순서

```text
① types.ts에 DiagramKind + DiagramFrame에 kind (필수)
② 12종이 리터럴을 넘긴다 — typecheck가 누락을 잡는다
③ measureInPage에 관측 수집 + collectUrls에 γ 기준선
④ α·β·γ 대조 → exit 2
⑤ ★G-5 — LayerStack을 유도에서 빼고 본 검사를 돌려 실제로 우는지
⑥ D-2(임시 cwd) 기계 + ⑫를 그 위로 이사 → 비용 실측
⑦ 대조군 ⑭~㉑ + 되돌려 확인(FR-8)   ← δ가 늘어 여섯이 됐다
⑧ 문서 · Check
```

**⑤가 ⑦보다 앞이다.** Plan이 적은 대로 — *"실물로 한 번 울리는 것이 대조군 열 개보다 앞선다."*
**⑥이 ⑦보다 앞인 이유**: 기계가 없으면 ⑰·⑱을 만들 수 없고, ⑫를 먼저 옮겨 보면 기계가 옳은지 **이미 통과하던 대조군으로** 확인된다.

## 7. Do 실측

### 7.1 ★설계가 실측으로 두 번 고쳐졌다

| | Design이 정한 것 | Do가 바꾼 것 |
|---|---|---|
| **γ** | *"MDX가 쓰는 종류"* 와 대조 | **공허했다.** 그 집합은 `ALL_COMPONENTS`에서 만든 정규식으로 채워지므로 `!ALL_COMPONENTS.includes(c)`가 **절대 참이 안 된다.** 유도와 같은 출처라 **함께 틀린다.** 배럴 `index.ts`로 교체 — 이름과 경로를 따로 적어(`export { LayerStack } from './LayerStack'`) 파일이 밖으로 나가도 이름이 남는다 |
| **δ** | 없었다 | **G-5가 만들어 냈다**(§7.2) |

§1.1이 *"α만 만들고 끝내면 헛것"* 이라고 경고했는데, **그 §1.1이 만든 γ가 다시 같은 병에 걸려 있었다.** 위험 표에 이름을 적어 두는 것과 그 위험을 피하는 것은 다른 일이다.

### 7.2 ★G-5 — α·β·γ가 조용했다. δ는 여기서 나왔다

Design이 *"실물로 한 번 울리는 것이 대조군 열 개보다 앞선다"* 라며 ⑤를 ⑦보다 앞에 뒀다. 그 판단이 이 사이클을 구했다.

```text
1차 (α·β·γ만)   LayerStack을 유도에서 뺀다
                92페이지 → 56페이지
                ✅ 전 항목 통과        ← 36페이지가 조용히 검사 밖인데 통과했다
```

**왜 α가 안 울었나** — 남은 56페이지 중 **8개에 `LayerStack`이 함께** 있어 관측에는 나왔다(착수 전 실측으로 미리 계산했다). α·β·γ는 *"종류가 한 번이라도 그려졌나"* 만 본다.

**δ를 넣었다** — *"이 종을 쓰는 페이지가 전부 검사 목록에 있나."*

```text
2차 (δ 포함)    기준선            exit 0 · 범위: 유도 6종 / 관측 11종(SVG 6종) / 배럴 12종 / 페이지 92
                LayerStack 제거    exit 2 · δ LayerStack — 페이지 36개가 검사 목록에 없다
```

**36개는 착수 전 실측치와 정확히 같다.**

### 7.3 관문이 실물로 잡아낸 것 둘

| # | 발견 | 성격 |
|:--:|---|---|
| **F-1** | `FlowSteps`가 `lucide-react` 아이콘(`ChevronRight` 등)으로 `<svg viewBox>`를 그린다 — 파일에 `<svg` 리터럴이 없어 유도가 **비SVG로 분류** | Plan §1.2가 적은 *"`<svg` 리터럴이 공용 헬퍼로 이동"* 경로의 실물. 유도를 못 믿는다는 증거다 |
| **F-2** | `chapters.json`에 `number` 필드가 **0개**인데 매핑이 `String(c.number).padStart(2,'0')`을 썼다 → `slugByNum`이 **항상 빈 Map**. 책 17장이 URL 매핑을 못 받았다 | **A-2의 실물.** 경고 한 줄은 났지만 `exit 0`이었다. 지금은 챕터가 비SVG 종만 써서 범위 손실 0이지만 **`LayerStack` 하나만 들어와도 조용히 빠진다.** `id` 기반으로 고쳤다 |

**F-1이 δ의 기준을 좁혔다.** 처음엔 *"SVG를 그리는 종"* 으로 δ를 걸었더니 `FlowSteps`의 62페이지를 거짓으로 지목했다. 이 관문이 판정하는 것은 *"SVG"* 가 아니라 **"글자 있는 SVG"** 다(`figures`와 같은 기준). *"SVG를 그린다"* 와 *"이 관문이 판정할 것을 그린다"* 는 다른 문장이다.

### 7.4 열린 문제 C의 결과 — 값이 **줄었다**

```text
자체검사   49.58초  →  5.43초      (대조군 15 → 21건인데 9배 빨라졌다)
```

임시 cwd에서 자식을 돌리니 URL이 1개가 되어 자식 하나가 46초 → 1초대다. **자식을 셋으로 늘리고도 이전 하나보다 빠르다.** 선행 백로그 **D-2**(⑫가 자체검사 비용의 92%)가 함께 닫혔다. **범위 축소 인자를 만들지 않고 얻었다** — 그런 인자는 이 사이클이 막으려는 위험 그 자체다.

### 7.5 게이트

| # | 결과 |
