## 0. Design 단계에서 잰 것

### 0.1 열린 문제 A — 토큰 색은 그대로 넣으면 된다

Plan §3 A는 *"대조군이 리터럴만 쓰면 oklch 경로를 증명하지 못한다"* 였다. 실측으로 풀렸다.

```text
theme.css            --color-slate-800: oklch(27.9% 0.041 260.031)
getComputedStyle     fill = oklch(0.279 0.041 260.031)
canvas 파싱          {R:29, G:41, B:61, A:255}
```

**Tailwind 클래스가 만드는 계산값과 인라인 `fill="oklch(…)"` 가 같은 형태다.** 즉 대조군이 `oklch(…)`를 직접 쓰면 **동일한 파싱 경로**를 지난다.

값은 **`theme.css`에서 읽는다** — 스크립트에 옮겨 적지 않는다(`verify:diagram`의 `readPalette()`가 세운 규약).

### 0.2 열린 문제 B — `figures === 0`은 겨눌 수 있다

`setContent`로는 항상 도해가 있다고 봤는데 아니다. **글자 없는 도해**를 주면 `texts.length === 0`에서 `return`하므로 `figures`가 0으로 남는다.

```text
글자 없는 도해 → figures = 0
```

선행 사이클이 넣은 *"아무 도해도 못 봤는데 통과하는 경로"* 가드를 그대로 겨눌 수 있다.

### 0.3 열린 문제 D — 106건 결함이 축소판으로 재현된다

마스크 구멍(`fill="black"`)이 글자를 포함하는 **가장 작은 사각형**이 되게 짠 도해 하나로 충분하다.

| | 대비 지적 |
|---|---|
| 현재 (`NOT_PAINTED` 필터 있음) | **0건** |
| 되돌림 (필터 제거) | **1건 — 비율 1.44** |

**실제 사건의 1.44가 그대로 나온다.** 대조군 하나가 그 회귀를 고정한다.

### 0.4 ★fixture를 만들다 **같은 부류의 잔여 결함**을 찾았다

위 fixture가 글리프 구멍을 1건 냈다. 좌표를 재 보니 구멍은 글자를 여유 8/43/7/8로 **덮고 있었다.** 지적된 `sample`을 보니 **`"+"`** — `<pattern>` 안의 글리프 텍스트였다.

```js
const texts = [...svg.querySelectorAll('text')].filter((t) => t.textContent.trim());
```

**`texts`에 `NOT_PAINTED` 필터가 없다.** 지난 사이클이 `rects`에서 그려지지 않는 도형을 걸러 106건을 고쳤는데, **`texts`는 그대로 뒀다.** 같은 부류다.

> **실제 앱에서 안 터지는 것은 우연이다.** 패턴 글리프는 타일 좌표 `(4, 12)`에 있고 층 rect는 `bodyX=16, y=16`에서 시작한다 — 글리프 중심이 어느 rect에도 안 들어가 `topmost = null`로 규칙을 건너뛴다. **좌표가 조금만 달랐으면 터졌다.**

이것이 이 사이클의 존재 이유를 그대로 보여준다 — **자체검사가 없어서 반쪽만 고친 것을 아무도 몰랐다.**

## 1. 결정

### D-1 · 하네스는 `page.setContent()` (Plan D-1 확정)

§0.1~0.3이 셋 다 `setContent`로 겨눌 수 있음을 보였다. 서버·자격증명 0.

### D-2 · 색은 **`theme.css`에서 읽어** 대조군에 넣는다

리터럴(`#fefefe`)은 파싱 경로가 같아도 **실제 토큰이 아니다.** `readPalette()` 규약을 따라 값을 읽어 쓴다 — 팔레트가 바뀌면 대조군도 따라간다.

### D-3 · 판정 **6종 전부**에 양성 · 대표 음성 1건 (Plan §3 C 확정)

하네스가 0.3초라 아낄 이유가 없다. 6종: 가로 넘침 · 글자 축소 · 대비 · 글리프 구멍(2조건) · 마커 미해결 · 마커 중복. 여기에 `figures === 0`(§0.2)과 회귀 대조군(§0.3)을 더한다.

### D-4 · ★**`texts`의 `NOT_PAINTED` 누락을 이 사이클에서 고친다**

§0.4는 **Plan에 없던 발견**이다. 넣는 이유 셋:

1. **하네스를 만들다 하네스가 찾았다.** 이 사이클의 목적이 그것이다.
2. **반쪽만 고친 상태를 방치하면 다음 사람이 "고쳐졌다"고 읽는다** — 지난 사이클 커밋이 *"배경 후보를 그려지는 도형으로 한정했다"* 라고만 적었다.
3. **비용이 한 줄이고, 대조군이 같이 생긴다**(§0.4의 fixture가 그대로 양성이 된다).

> **범위를 넓히는 결정을 명시한다.** 선행 사이클들에서 배운 대로 — 결정 없이 고치면 감점이고, Plan이 위임하지 않은 것은 Design이 이유를 적고 결정한다.

### D-5 · `--self-test`는 **본 검사를 건너뛴다**는 것을 출력에 적는다

선행 `--assert-only`와 같은 위험(관문 대용으로 쓰임). 같은 방어를 쓴다.

## 2. 대조군 설계

| # | 대조군 | 기대 |
|:--:|---|---|
| ① | **음성** — 정상 도해 | 6종 전부 0건. *하네스가 옳게 도는지가 먼저다* |
| ② | 가로 넘침 | `pageOverflow` |
| ③ | 글자 축소 (실효 9px 미만) | `small` |
| ④ | 대비 미달 (토큰 색으로) | `lowContrast` |
| ⑤ | 글리프 구멍 — 마스크 없음 | `glyphHole` |
| ⑥ | 글리프 구멍 — 구멍이 안 덮음 | `glyphHole` |
| ⑦ | 마커 미해결 | `markers.missing` |
| ⑧ | 마커 중복 | `markers.dup` |
| ⑨ | **`figures === 0`** — 글자 없는 도해 | `figures` 0 |
| ⑩ | **회귀** — 마스크 구멍이 최소 포함 사각형 | 대비 **0건**. `NOT_PAINTED` 필터를 지우면 1.44로 깨진다 |
| ⑪ | **회귀** — `<pattern>` 안 글리프가 라벨로 판정되지 않는다 (D-4) | 지적 0건. `texts` 필터를 지우면 깨진다 |

**①을 먼저 만든다.** 선행 사이클들이 반복해서 겪었다 — 하네스가 틀리면 양성이 "통과"해도 의미가 없다.

## 4. 구현 순서 (Plan §6 정정)

```text
① 하네스 + 대조군 ① 음성
② 대조군 ②~⑧ (판정 6종 양성)

④ D-4 texts 필터 + 대조군 ⑪         ← 고치기 전에 ⑪이 먼저 실패하는 것을 본다
```

④에서 **대조군을 먼저 쓰고 고친다.** 선행 사이클에서 그 순서가 유효했다(구멍 가드를 넣기 전에 대조군이 먼저 실패했다).

**7/7 충족.**

### 7.1 G-4 — 되돌리면 무엇이 깨지나

```text
rects의 NOT_PAINTED 제거 (106건 사건)   → ❌ ⑩ 회귀
texts의 NOT_PAINTED 제거 (이번 발견)     → ❌ ⑪ 회귀
대비 판정 무력화 (minContrast 0)        → ❌ ④ 대비
글자 크기 판정 무력화 (하한 0)           → ❌ ③ 글자 축소
마커 미해결 판정 무력화                  → ❌ ⑦ 마커 미해결
글리프 구멍 판정 무력화                  → ❌ ⑥ 글리프 구멍
```

각각 **해당 대조군만** 깨진다.

### 7.2 ④의 순서가 유효했다

Design §4가 정한 대로 **`texts` 필터를 넣기 전에 ⑪을 먼저 돌렸다.**

```text
①~⑩ ✅ 통과
⑪   ❌ 실패   glyphHole: ["+"]
```

`sample`이 `"+"` — `<pattern>` 안의 글리프였다. **대조군이 실제 결함을 잡는 것을 보고 나서** 고쳤다. 이 순서가 아니었으면 *"대조군을 만들었더니 통과하더라"* 로 끝나 **공허한지 알 수 없었다.**

### 7.3 구현 중 걸린 것

`NOT_PAINTED` 선언이 `texts`보다 **아래**에 있어 TDZ 오류가 났다. 배경 후보와 라벨 **양쪽**이 쓰는 값이 되었으므로 위로 옮겼다 — 그 자체가 §0.4가 말한 "두 곳에서 걸러야 한다"의 구조적 표현이다.
