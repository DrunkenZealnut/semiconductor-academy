> Plan: `docs/01-plan/features/diagram-label-legibility.plan.md`
> 위험군: 패턴 위 글자 **53개 · 27모듈**(층 44 · wells 9)

## 0. Design 단계에서 잰 것

### 0.1 B안(라벨 뒤 판)은 죽었다 — 높이 분포

| 층 높이 | 개수 |
|---|:--:|
| ~30 | **12** |
| 31~45 | 18 |
| 46~60 | 9 |
| 61~ | 5 |

가장 얇은 다섯:

```
h= 16  013-photodiode      "p형 수광면 — 보통 1μm 이하"
h= 16  022-bjt             "베이스 (p형) — 흐름을 조절"
h= 18  hs-semicon-basics/bjt "베이스 — p형"
h= 20  066-doping          "표면 — 열확산은 여기서 스며든다"
h= 22  057-wafer-quality   "무결함층(DZ) — 소자가 실제로 만들어지는 곳"
```

라벨 글자는 `DIM.font` 13px이고 판에 패딩을 주면 **17~19px**이다. **h=16 층에서는 판이 층보다 크다.** 12개가 h≤30이라 예외 사례가 아니다.

### 0.2 A안(패턴에 구멍)을 만들어 눈으로 봤다

`<mask>`로 패턴 rect에서 라벨 bbox만 뚫었다. `022-bjt`(h=16 포함) 전후:

| | 결과 |
|---|---|
| **전** | 세 층 라벨 모두 `−`/`+`가 글자를 관통 — "에미터"에 `_`가 붙어 읽기 어렵다 |
| **후** | 세 라벨 모두 **완전히 읽힌다.** 층 색이 남고, 라벨 밖 글리프는 그대로 보인다 |

**h=16 최박 층도 통과했다** — B안이 죽는 그 자리에서 A안은 산다. 층 색(분홍)이 살아 있고 라벨이 또렷하다.

### 0.3 마스크 경계를 타일 격자에 맞춰야 한다

첫 시제품은 라벨 bbox에 패딩 4를 준 사각형으로 뚫었는데 **라벨 좌우에 `·` 잔여물**이 남았다. 패턴 타일은 16 단위이고 글리프가 타일 안 `x=4, y=12`에 있어, 마스크 경계가 타일 중간을 지나면 **글리프가 반만 잘린다.**

구멍의 네 변을 **16의 배수로 바깥쪽 스냅**하니 잔여물이 사라졌다 — 글리프는 통째로 지워지거나 통째로 남는다.

### 0.4 `⊤` 모양 글리프는 이 사이클이 만든 것이 아니다

`022-bjt` 베이스 층(h=16) 오른쪽 글리프가 세로로 잘려 `⊤`로 보인다. **마스크를 끄고 찍은 사진에도 똑같이 있다** — 층 rect 높이가 타일 글리프를 자르는 기존 현상이고, `patternUnits="userSpaceOnUse"`라 타일 격자가 층 경계에 정렬되지 않기 때문이다. **이 사이클 밖**이다(§6).

### 0.5 wells는 시제품이 건드리지 않았다

`017-nmos` 시제품 결과: 층 라벨 `p형 실리콘 기판`은 깨끗해졌으나 **wells 라벨 `n⁺ 소스`·`n⁺ 드레인`은 `−`가 그대로 관통한다.** 층 패턴 rect에만 마스크를 걸었기 때문이다. wells도 같은 장치가 필요하다(9건).

## 1. 결정

### D-1 · 장치는 **A안(패턴에 마스크 구멍)**

B안(뒤판)은 §0.1로 죽었다 — h=16에서 판이 층보다 크다. C안(타일 위상 조절)은 라벨 y가 층마다 달라 타일 하나로 못 맞춘다. D안(라벨을 층 밖으로)은 단면도의 의미를 바꾼다.

**A안이 유일하게 셋을 동시에 만족한다** — 라벨이 읽히고, 층 색이 남고, 글리프가 라벨 밖에서 계속 보인다(FR-2).

### D-2 · 구멍은 **패턴 타일 격자(16)에 바깥쪽 스냅**

§0.3의 실측이 근거다. 스냅하지 않으면 경계에서 글리프가 반만 남아 **라벨 옆에 점 같은 잔여물**이 생긴다.

```
x0 = floor((labelX − 4) / 16) × 16      x1 = ceil((labelX + labelW + 4) / 16) × 16
y0 = floor((labelTop − 2) / 16) × 16    y1 = ceil((labelBottom + 3) / 16) × 16
```

`labelX`·`labelW`는 **D-13이 이미 계산해 둔 값**을 그대로 쓴다(`approxWidth`). 새 미러를 만들지 않는다.

### D-3 · **wells에도 같은 장치**를 적용한다 (9건)

§0.5. wells 패턴 rect에도 마스크를 건다. wells 라벨은 `textAnchor="middle"`이라 bbox 계산이 층 라벨과 다르다 — 중심 기준으로 좌우 절반씩 잡는다.

### D-4 · 기계 규칙은 **둘로 나뉜다** (FR-4의 정정)

Plan FR-4는 *"D-13의 wells 배치 규칙도 같은 기계 규칙에 담는다"* 고 적었다. **하나로 담을 수 없다** — 두 결함의 성질이 다르다.

| | R-3 (글리프) | D-13 (wells) |
|---|---|---|
| 그리기 순서 | 글리프가 라벨보다 **먼저** | wells가 라벨보다 **나중** |
| 증상 | 같은 색으로 **섞인다** | 라벨을 **덮는다** |
| 판정 | 마스크 구멍이 라벨 bbox를 덮는가 | 라벨 bbox에 나중 요소가 겹치는가 |

**하네스는 공유하고 규칙은 둘로 둔다.**

- **정적(C-20)** — "패턴 rect에는 반드시 마스크가 걸린다 · 마스크는 격자 스냅 헬퍼를 거친다". C-18과 같은 방식(문자열 존재/부재)이라 싸고 오탐이 낮다. **다만 마스크가 실제로 라벨을 덮는지는 안 본다.**
- **브라우저(`verify:render` 확장)** — `text.getBBox()`가 마스크 구멍 안에 들어가는가(R-3), 라벨 bbox에 나중 요소가 겹치는가(D-13). 좌표로 결정되는 것은 좌표로 본다.

선행 사이클들이 세운 분업 그대로다 — **정적은 계약, 브라우저는 좌표.**

## 7. Do에서 드러난 것

### 7.1 `verify:render`가 그려지지 않는 도형을 배경으로 읽었다

마스크를 넣자 **대비 미달 106건**(53영역 × 2뷰포트 — 이 변경의 정확한 발자국)이 났다. 원인은 검사기다.

```js
const rects = [...svg.querySelectorAll('rect, circle, ellipse')];
```

`<defs>`·`<mask>` 안의 사각형까지 고른다. 마스크 구멍(`fill="black"`)이 **가장 작은 포함 사각형**으로 뽑혀 배경이 검정이 됐고, 멀쩡한 라벨이 대비 1.44로 잡혔다.

**마스크를 `<defs>`로 옮기는 것으로는 안 고쳐졌다** — `querySelectorAll`은 defs도 훑는다. 첫 가설이 틀렸고, 코드를 읽고서야 원인을 찾았다.

**고침**: 배경 후보를 **그려지는 도형**으로 한정한다(`defs`·`mask`·`pattern`·`clipPath`·`symbol`·`marker` 안은 제외). 106건 → 0건.

> **이 결함은 원래 있었다.** `<pattern>` 안에는 `<rect>`가 없고 `<text>`만 있어 드러나지 않았을 뿐이다. 이 사이클이 `<mask>`를 도입해 처음 밟았다.

### 7.2 주석에 쓴 태그 이름이 C-19를 깨뜨렸다

`glyphHole`의 문서 주석에 그 태그 이름을 리터럴로 적었더니, C-19의 `checkPatternTextClassIn`이 `indexOf`로 훑어 **주석을 여는 태그로 오인**하고 그 뒤 band 축 라벨의 `TEXT_MUTED`까지 삼켰다 — 거짓 경보.

**문자열로 훑는 검사가 있는 파일에서는 주석도 코드처럼 읽힌다.**

### 7.3 자식 프로세스 하네스가 상대 경로를 쓰고 있었다

선행 사이클의 종료 코드 대조군이 `[process.argv[1], …]`로 자식을 띄우는데, **자식은 cwd를 바꿔 돈다.** `node scripts/…`로 실행하면 argv[1]이 상대 경로라 자식이 모듈을 못 찾는다. 이번에 처음 밟았고 `resolve()`로 고쳤다. **선행 사이클의 잠복 결함이다.**

### 7.4 C-20의 첫 판정이 약했다

`/glyphHole\(/`는 **함수 정의**에도 걸린다 — 호출을 전부 없애고 정의만 남겨도 통과했다(G-4 되돌림에서 드러났다). 호출만 세도록 `glyphHole\(\{`로 조이고 **패턴 채움 수와 비교**한다.

> 선행 사이클에서 배운 것이 그대로 반복됐다 — *"되돌렸는데 통과했다"* 가 이번에는 **실험이 아니라 검사가 약한 것**이었다. 둘 다 의심해야 한다.
